# Design

## Context

См. proposal.md. Config::from_env_in вручную выбирает exe/models или cwd/models,
но worker CLI и doctor уже используют model_paths::Context. QueueItem TUI не
содержит execution identity, а Data::Queue каждый раз вызывает console.record.
Journal уже умеет selected groups и Left/Right; console пока прокручивается
стрелками, выбирается Tab и копирует весь текст.

## Goals / Non-Goals

Один resolver для конфигурации процесса и обоих ASR transport. Строгий учёт
событий отказа независимо от частоты poll. Единые контекстные клавиши логов.
Бюджет очереди, формат аудио, модели и аппаратный захват не меняются.

## Decisions

- Передавать model_paths::Context в composition boundary Config; рабочий путь
  выбирать тем же resolver, который использует doctor. Тесты задают частные
  home/exe/cwd/overrides, без изменения пользовательского окружения.
- Добавить optional execution_id в queue DTO: один отказ одного исполнения
  записывается один раз; новая попытка с тем же текстом остаётся новым событием.
  Legacy DTO без ID совместимы и сравниваются по доступным полям состояния.
- Console j/k перемещают выбранное событие, h/l идемпотентно сворачивают/раскрывают,
  y копирует выбранное; полный текст остаётся отдельной командой Ctrl+Y.
  Journal использует существующую selection/expansion и копирует выбранную группу.
- Формы и фильтры сохраняют ввод; используются существующие shortcut profiles,
  без обещания физических key codes в терминалах, которые их не передают.

## Risks / Trade-offs

- Явный неверный путь остаётся ошибкой: не подменять его другой моделью.
- Полный model/device запуск Mac не доступен здесь: отдельная приёмка владельца.
- Дубли journal и queue могут представлять одно событие разных источников;
  меняется только ложный повтор неизменённого queue snapshot.
