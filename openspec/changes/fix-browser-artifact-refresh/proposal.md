# Последовательное обновление открытых документов

## Why

Продолжение запрошенной владельцем проверки медленной обработки и очистки UI/TUI.
В DocumentPane каждый refresh начинает новый GET, а номер запроса делает ответы
предыдущих запросов устаревшими. При ответах медленнее трёхсекундного refresh это
может удерживать документ в загрузке. Код также не отменяет чтение закрытой вкладки.
Сначала закрепляем воспроизведение, не называем этот дефект причиной медленного ASR/LLM.

## What Changes

- Вынести чтение артефакта в отдельный hook с одним активным GET на открытый ресурс.
- Объединять refresh во время чтения в один повтор после завершения, показывать
  пригодный ответ текущей сессии и сохранять текст при обычном обновлении.
- Отменять HTTP-чтение при смене сессии/версии/вкладки и отбрасывать поздние ответы.
- Проверить медленные ответы, финальное обновление после обработки, переключения,
  ошибки/восстановление и визуал браузерными тестами.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `archive-playback`: ARCH-008 уточняет жизненный цикл чтения документов клиентом
  при медленном API. ARCH-001 и прежние пользовательские действия сохраняются.

## Impact

UI DocumentPane/useArtifact и необязательный AbortSignal для пяти существующих GET
методов api.ts. URL, ответы API, модельная обработка и сохранённые документы не меняются.
Нет новых зависимостей. Работающий демон и пользовательский архив не затрагиваются.
