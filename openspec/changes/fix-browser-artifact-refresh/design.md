# Design

## Context

См. [proposal](proposal.md) и [ARCH-008](specs/archive-playback/spec.md).
DocumentPane запускает tick каждые 3 секунды и один финальный при live → false.
Встроенный useArtifact начинает GET на каждый tick и увеличивает seq, обесценивая
предыдущий запрос; cleanup/cancellation отсутствуют. Пять чтений используют этот hook:
transcript, versions, summary, processed и speakers. API call уже объединяет
пользовательский AbortSignal со штатным таймаутом.

## Goals / Non-Goals

Исправить последовательность GET и вынести жизненный цикл чтения из большого
DocumentPane. Сохранить ключи сессии/версии, трёхсекундный ритм и финальный tick,
отображение ошибок и все пользовательские действия. Не менять общий shell poll,
подтверждения start/stop, mutations, плеер, ASR/LLM или протокол сервера.

## Decisions

- useArtifact.ts хранит один активный запрос и один флаг накопленного refresh.
  Повтор не отменяет нужное чтение: после ответа выполняется один новый GET.
  Обычный debounce мог бы откладывать чтение бесконечно; последовательная очередь
  каждого tick копила бы уже ненужные запросы.
- Жизненный цикл по key отделён от refresh. При новом key старый AbortController
  отменяется, поздние resolve/reject защищены alive. Snapshot помечен key, чтобы
  предыдущий текст не появлялся даже до эффекта нового ресурса.
- Вызов load получает AbortSignal. Он необязателен в существующих API GET, поэтому
  прежние callers совместимы. Серверная обработка из-за client abort не объявляется
  остановленной; прекращается только ожидание клиента.
- Начало чтения откладывается в microtask с проверкой живого lifecycle, чтобы
  проверочный mount/unmount React не выполнял оставшееся чтение закрытого контекста.

## Risks / Trade-offs

- Потеря последнего обновления → тест live → false при удерживаемом запросе.
- Старый ответ или ошибка из закрытой вкладки → проверка AbortSignal и переключения
  сессии/вкладки браузерными тестами, без подмены production hook.
- Изменение вёрстки → все прежние screenshots должны пройти без обновления baseline.
- Таймаут сохраняется 15 секунд; это не ускорение сервера. Проверки используют
  искусственную задержку HTTP, а не пользовательские записи и модели.
