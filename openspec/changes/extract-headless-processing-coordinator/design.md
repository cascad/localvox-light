# Design

## Context

См. proposal/Why. Autocook зависит от core/process/chrono/tracing и не запускает
capture; его file layout и тесты можно сохранить. Root main вызывает только spawn.
Прямые worker-замеры уже выявили долгие ответы, но не измеряют очередь/линии.

## Goals / Non-Goals

Общий библиотечный вход существующего пакета и безопасный инженерный queue runner.
Не менять политику, форматы очереди, действия UI/TUI, модельные лимиты или запуск
устройств. Не считать создание стенда полным выполнением BL-003.

## Decisions

- lib.rs экспортирует существующий autocook; main использует библиотеку. Исходный
  файл/пути остаются, реализации не копируются в стенд. Coordinator tests выполняются
  как lib tests, launcher tests остаются bin tests; CI явно проверяет оба.
- Необязательный Observer — bounded sync channel + счётчик потерь. Claim/accepted/
  failed metadata отправляются try_send только после успешного изменения jobs.json,
  пока снимок результата ещё защищён queue mutex. Sender никогда не ждёт consumer.
  Для обычного spawn observer=None; прежние переходы/часы/лимиты сохраняются.
- Событие содержит ID/phase/execution/clocks/attempts/state, без last_error и текста
  документов. Время копируется из принятого Job, неизвестное остаётся None.
  Переполнение наблюдателя не ломает обработку, но делает измерение неполным.
- Новый bench binary запускает тот же coordinator без main/capture/API. Он принимает
  только workspace с маркером профилировщика и без активной записи, проверяет worker
  sibling identity, пишет metadata-only отчёт, прекращает coordinator по terminal
  jobs/ошибке/таймауту/сигналу. Окружение и данные создаёт внешний изолированный стенд.
- Загрузка библиотеки не запускает сервисы. Установка/обычный launcher не выбирают
  измерительный binary. Производственный API/Wire/version не меняются.

## Risks / Trade-offs

- Пропустить быстрый Prepare при polling → события у принятого перехода; lost
  counter явный. Никаких длительностей по времени опроса вместо job clocks.
- Случайный запуск на архиве владельца → обязательный marker и отсутствие recording;
  existing profiler создаёт только новые каталоги, стенд не чистит чужие данные.
- Ложный test coverage после переноса → сохранить имена/сценарии, выполнить lib и
  bin/launcher checks, записать новые counts отдельно от исторических результатов.
- Протокол/worker mismatch → отказ до исполнения, bounded завершение; receipt
  проверяет прежняя реализация. Ошибка observer не становится успешной обработкой.

## Migration Plan

Изменение исходников/сборка, без миграции архива и без перезапуска установленного
демона. Новые Rust API и bench entry нужны только инженерным потребителям.
