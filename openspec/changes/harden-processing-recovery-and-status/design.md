# Design

## Context

См. proposal.md и screenshots владельца. Очередь уже сохраняет attempts, phase и
last_error, но maintenance автоматически возрождает Failed через 1/2/4 часа.
Incremental offer при Stop может promote Failed с обнулением attempts. Сам yt-dlp
имеет вложенные retries. Summary без файла теряет причину при выдаче API blocks.
Палитра берёт 16 строк без счётчика/продолжения.

## Goals / Non-Goals

Конечный бюджет, ручное восстановление и объяснимое отсутствие результата. Не
перерабатывать готовую запись из-за старого лога, не стирать её аудио/историю,
не угадывать качество ASR по числу строк. Mac аппаратный повтор — отдельный gate.

## Decisions

- Общий лимит три запуска фазы; Failed терминален до explicit retry/recook.
  Убрать автоматическое revival, оставить чтение legacy revivals в jobs.json.
  Claim/recovery не позволяют четвёртый запуск после прерываний. Stop обновляет
  finalization intent, но не снимает Failed. Явная полная переварка получает новый бюджет и снимает старый incremental intent.
- Координатор владеет retry; yt-dlp получает конечный socket timeout и нулевые
  внутренние retry, иначе бюджеты перемножаются. Инструмент запускает общий process
  supervisor; собственные временные файлы принадлежат RAII объекту и удаляются
  при неуспехе/после декодирования. Title необязателен и ограничен отдельно.
- Ранний Transcribe может начинаться без Prepare. До запуска фазы сохраняется
  единый run ID; существующая публикация начала этапа перед worker/model resolver
  и его отказ относятся к одному запуску, поэтому имеют измеримую длительность. Старый журнал остаётся историей; готовность идёт от receipts.
- Summary API добавляет status/reason для отсутствующего файла через проверяемое
  состояние артефакта/фазы. Оба клиента используют одинаковые факты. Ноль слов и
  отсутствие содержательного ответа модели имеют разные причины. Готовый с
  пропусками pipeline не утверждает, что все файлы созданы. Старые Nothing receipts
  не инвалидируются автоматически; пользователь может явно переварить запись целиком.
- Palette viewport зависит от доступной высоты; selection всегда виден, offset
  ограничен концом. Счётчик диапазона/total и обе границы продолжения явны. Навигация
  Page/Home/End общая для отображения и ввода; h/l сохраняют согласованный scope.

## Risks / Trade-offs

Потеря работы при retry → production HTTP тесты сохранения предыдущих файлов.
Перезапуск/Stop снимают предел → durable queue + coordinator fixture/reload tests.
Фальшивый success → API/оба клиента проверяют skipped и reason, browser/PTY регресс.
Удаление временного чужого файла → только собственный TempDir, проверенный output path.

## Migration Plan

Legacy queue/summary читаются без миграции файлов. Failed больше не получает
автоматического дедлайна. Завершённые артефакты остаются; исправление путей модели
или параметра само по себе не запускает переработку Failed/Done. Инструкции полной ручной
переварки и причины skip обновляются в US-007/008/009/022.

## Follow-up: порядок команд записи

Полный browser прогон выявил гонку существующего сценария US-002: Start и Stop
могли одновременно находиться в HTTP, и задержанный Start включал запись после
Stop. Это исправление требуемой остановки (REC-001/003), без нового режима записи.
RecordBar последовательно отправляет изменяющие команды, ожидая только завершения
предыдущего POST. Ожидание подтверждения движка остаётся отдельным: Stop доступен
сразу и вытесняет прежнюю проверку Start. Отказ предыдущего POST не блокирует Stop.
Регресс управляет задержкой ответа и наблюдает реальные fetch-вызовы и порядок
применения команд, не использует паузы на удачу.
