# Design

## Context

См. [proposal](proposal.md). Ниже — code-reviewed состояние на `0d2c47b`, не новые
runtime свидетельства. Планируемое поведение задают delta specs; реализация not-run.

- [Discovery](../../../crates/localvox-light-core/src/jobs/discovery.rs) и
  [queue](../../../crates/localvox-light-core/src/jobs.rs) исключают активную запись.
  Снять проверку активности глобально нельзя: обычный cook публикует полную версию.
- [Recorder](../../../crates/localvox-light-core/src/chunks.rs) пишет `.part`, затем
  WAV/meta; FLAC работает отдельно. Ошибка patch/sync сейчас логируется, но rename
  ещё возможен. Нет строгого terminal manifest или согласованного read/conversion
  lease; RV-005 нельзя игнорировать при конкурентном чтении.
- [Cook/Windower](../../../crates/localvox-light-core/src/cook.rs) уже непрерывно
  подаёт файлы одного источника в общий VAD-разрезатель. Frame=320, max=15 s,
  min=8 s, silence=500 ms; при потолке выбирается лучшая доступная пауза, без неё
  возможен принудительный разрез. `finish` вызывается после последнего файла.
  Модель грузится на cook; все строки публикуются в конце. Результат сортируется
  по start/source, поэтому поздняя дорожка может сдвинуть глобальные номера строк.
- [Text](../../../crates/localvox-light-llm/src/pipeline.rs): пакеты ограничены
  строками/символами, ответы привязаны к их номерам. Глоссарный prompt отбирает термины
  по всему документу: даже поздний термин способен изменить запрос раннего пакета.
- [API](../../../crates/localvox-light-api/src/archive.rs) читает best/readable.
  [UI](../../../ui/src/DocumentPane.tsx) уже опрашивает активный документ, но отдельной
  частичной версии нет. [Media](../../../crates/localvox-light-api/src/archive/media.rs)
  строит WAV по снимку meta: растущий URL нельзя считать неизменным файлом для Range.
- Текущий `.env.defaults`: archive chunk=300 s. Это транспортная ротация, не граница
  фразы. [Live Vosk](../../specs/live-transcription/spec.md) — другой RAM/voice-hook
  контур, не источник нового архивного результата.

## Goals / Non-Goals

**Goals:** повторно использовать выполненную работу без потери/дублирования
подтверждённых аудиодиапазонов; показывать согласованный префикс; при неопределённости
оставлять недоделанное. Для непрерывного PCM streaming и offline должны получать
одинаковые ASR окна независимо от транспортной нарезки.

**Non-Goals:** смена ASR/LLM, fuzzy сшивка текстов, новая семантическая гарантия
очистителей (RV-020), streaming URL/скачивание, ранняя summary, глобальный постоянный
ASR сервер, пересмотр старых таймкодов/часов capture, правка пользователем растущего
текста, новые голосовые команды. Полный экспорт/индекс по-прежнему после финализации.

## Decisions

### 1. Закрытые диапазоны и явный terminal record

Recorder остаётся единственным писателем первичного capture состояния. Для новых
записей он публикует versioned `capture/` manifest: recording generation, объявленные
источники, revision, закрытые диапазоны `(source, sequence, start_sample, sample_count)`
в существующей аудиошкале источника, статусы empty/paused/ended/unknown. Время хранения
не выводится из mtime; sample boundaries целочисленные, UI seconds только производные.

WAV сначала успешно patch/sync/close/rename, затем небольшой atomic seal record.
Ошибка не продвигает manifest; тяжёлая проверка PCM/hash выполняется в worker вне
capture loop. Worker проверяет заголовок/длину и содержимое под read lease. Факт
появления WAV сам по себе не является seal. Пустые открытые файлы, которые recorder
удаляет при pause/stop, тоже должны быть учтены: дырка в номерах имён не автоматически
означает потерянное аудио и не автоматически разрешает её пропустить.

Stop публикует terminal record только после хвостов всех источников: expected final
ranges и normal/interrupted reason. Отказ терминального commit виден отдельно;
его можно повторить, не запускать новую запись и не выдумывать EOF. Pause не EOF.
После crash terminal разрешён только после получения instance ownership и штатного
восстановления архивных `.part`; ошибка восстановления оставляет источник blocked.
Volatile PCM, ещё не сохранённый до отказа устройства/питания, не объявляется спасённым.

Альтернативы: читать растущий `.part` или считать отсутствие свежего файла концом
потока. Отклонены: header не завершён, tail ещё меняется, остановка/сбой неразличимы.

### 2. Чтение и конвертация используют один chunk lease

Канонический ключ lease — generation/source/sequence, независимо от WAV/FLAC.
Читатели держат shared lease на всё чтение/декодирование; конвертер — exclusive на
смену представления/удаление. Capture не ждёт ASR или конвертера при записи нового
файла. Порядок блокировок: session execution lease → chunk leases в порядке ключей;
конвертер не получает execution lease и не меняет processing/versions.

В рамках этого этапа закрывается нужный для функции объём STORE-002/RV-005:
bounded converter под общим process supervisor, проверка декодируемости, точного
sample count и PCM digest перед удалением WAV. При отказе остаётся WAV. Ни exit=0,
ни существующий FLAC не достаточны. Текстовые кеши привязаны к PCM, не только к
container bytes: безопасная WAV→FLAC замена не должна обнулять всю работу.

Альтернатива — запретить FLAC целиком или без lease повторять open при исчезновении
файла. Первый меняет пользовательский выбор, второй не доказывает тождество входа.

### 3. Один общий planner окон, без finish на каждом файле

Выделить из cook повторно используемый streaming window planner, сохранив фактические
правила VAD/quietest cut. Вход — непрерывные проверенные диапазоны одного источника;
выход — immutable window descriptors и покрытие тихих диапазонов. `finish` разрешён
только при подтверждённом EOF; неполный frame/tail остаётся в сохранённом аудио.

Лёгкий session planner принадлежит capture engine и работает отдельным управляемым
потоком вне capture callback и модуля autocook. Он читает только новые sealed
диапазоны, держит VAD/tail в ограниченной RAM и публикует входные descriptors в
`capture/plan/`. Очередь содержит coalesced disk horizons, не PCM. Здесь нет ASR
или LLM и не занята их вычислительная линия. Декодирование FLAC — только bounded
порциями через supervised decoder; запись аудио не ждёт planner. При его отказе
capture продолжается, ранняя работа блокируется с диагностикой.

Состояние C VAD не сериализуем. После restart/recovery или при fallback после
отказа planner можно один раз заново пройти проверенный PCM от начала источника,
сопоставить descriptors и использовать совпавший ASR cache. В штатном режиме нет
повторного VAD/decode всего префикса при каждом новом файле. Эта альтернатива
отклонена: суммарное чтение росло бы квадратично по числу обновлений. Нельзя заменять
replay предположительным восстановлением приватного состояния native VAD.

Тяжёлый worker получает finite horizon готовых descriptors, перепроверяет входы
и распознаёт нужные диапазоны; запуск/модель один раз на horizon, не на каждое 15 s
окно. Новые descriptors относятся к следующему заданию. Нет постоянного ASR worker,
который занял линию и часами ждёт файл, или нового сервера с моделями. Файлы читаются
ограниченными PCM порциями; старый read-whole-file путь не переносится как скрытый
расход RAM. Цена загрузки модели/планирования и latency измеряются на native серии.

Стабильный ID окна: generation/source/start/end; checksum PCM + fingerprint recipe,
конкретных model/vocab и planner revision участвуют в валидности. Даже успешное
пустое распознавание/отфильтрованное no-real-word имеет coverage outcome; timeout
или exception никогда не превращаются в empty. Новые алгоритмические отличия,
если понадобятся, требуют recipe bump и сравнения с прежним offline путём.

Это не обещание распознать каждое слово: существующий hard cut без пауз ограничен
моделью и сохраняет свой quality risk. Новых искусственных разрезов на 300 s файлах
не появляется; эвристической дедупликации слов на стыках нет.

### 4. Доказанный префикс и атомарный checkpoint

Планировщик публикует проверяемые descriptors отдельно от аудиосеалов, не переписывая
их manifest. Оба namespace принадлежат одному capture generation; descriptor
ссылается только на проверенные sealed диапазоны. Capture execution lease живёт
до остановки и recorder, и planner; отсутствие recording marker не доказывает,
что старый поток уже не пишет. Stop подтверждает сохранность аудио независимо от
времени завершения планирования. Delete/смена языка/прочие конфликтующие мутации
не обходят этот lease; shutdown должен bounded остановить planner/декодер.

Отдельный `incremental/` ASR cache, без записи ранних результатов в best/processed.json.
Immutable window records включают входные fingerprints, outcome, исходный ASR текст
и контрольную сумму. Порядок: temp result → sync/atomic publish → проверка → atomic
checkpoint, который ссылается только на существующие проверенные records. Общий
[atomic writer](../../../crates/localvox-light-core/src/artifacts.rs) переиспользуется.
Дубликат вычисления после crash допустим; дубликат логического результата — нет.

Checkpoint не источник правды сам по себе: повторно проверяются referenced records,
recipe/model/source generation и PCM. Повреждённый suffix откатывается до последней
доказанной границы; исходник не удаляется. Тишина учитывается в покрытии, иначе
сессия без слов никогда не закончится. Старый кеш другого входа не перезаписывается
до принятия нового поколения; это не разрешение обрабатывать весь старый архив.

ASR может идти по источникам независимо. Для общего текста нужен минимальный
подтверждённый frontier объявленных источников, с учётом окончания/явного отключения,
а не максимум готового. Опоздавшая дорожка не вставляет строки в уже закрытый пакет.
Новая/неопределённая топология, отсутствие надёжной границы или неизвестный интервал
блокируют публикацию общего префикса/LLM, но не вычисления и кеширование по источнику.
До разрешения показывается последний согласованный снимок с причиной ожидания.
Не придумываем синхронизацию источников по похожим словам и не меняем временную
модель старых архивов в рамках этой фичи. Проверки pre-roll/pause/unequal sources
обязательны; если существующих capture сведений недостаточно, используем этот
fail-closed путь до EOF, не новую эвристику часов.

### 5. Финализация использует кеш и прежние конечные артефакты

После terminal snapshot финальное задание получает тот же processing execution
lease и проверяет завершённый plan, при его отсутствии/отказе один раз восстанавливает
его общим planner до настоящего EOF. Совпадающие записи окон принимаются,
невалидные/недостающие окна вычисляются, последний tail flush выполняется один раз.
Проверяется полное ожидаемое покрытие каждого источника, включая explicit gaps и
empty outcomes; неизвестный/потерянный диапазон блокирует полное подтверждение.
Recovery worker пишет восстановленные descriptors только в свой output namespace,
не в capture/plan работающего producer; валидность проверяется по общему input.

Глобальная diarization/roster, если запрошены, завершаются после EOF. До неё UI
использует честные подписи источников; готовность speaker labels не изображается.
Это может требовать финального прохода по аудио: мгновенный Stop не обещан.
Межсессионное узнавание не добавляется и запрет не пересматривается.

Далее обычные VersionStore/source-parent/processing receipts с проверкой результата.
Это не новая общая транзакция нескольких legacy файлов. API переключается с draft
лишь на проверенный полный артефакт; промежуточный candidate не считается готовым.
Crash в любой точке публикации оставляет читаемый префикс, recovery завершает commit
либо повторяет недостающее под тем же lease. Summary и индекс получают только
подтверждённый final source. В полном экспорте по best нет скрытого partial fallback.

### 6. Граница первого выпуска: ранний STT, обычная правка после Stop

Решение владельца 2026-11-10: довести готовые аудиокуски до параллельного STT и
чтения/копирования/прослушивания в UI/TUI, затем остановиться на кандидате для
просмотра и сбора багов. Ранняя LLM-правка (PIPE-017, прежние 5.1/5.2) отложена:
она не реализована и не считается выполненной в этом change. Номер сохраняется
для будущего отдельного согласования; новых моделей и общего рефакторинга здесь нет.
Во время записи Текст — исходный STT. Summary ждёт Stop и подтверждённого полного
источника; существующие явно запрошенные refine/cleanup после Stop идут прежним путём.

### 7. Короткие задания в существующих линиях и понятные controls

Новый job intent `incremental` отличается от обычного cook и имеет finite input
horizon/generation; marker guard обычного cook сохраняется. Повторные обнаружения
coalesce в один pending intent, checkpoint progress не становится тысячами jobs.
Один execution owner сессии, прежний supervisor/cancel registry; worker protocol
повышается и проверяется до claim. Новая работа использует общие STT/локальную LLM
линии, без увеличения pools. Готовые обычные задания не вытесняются бесконечным
префиксом: после quantum ресурс возвращается очереди, старое ожидающее обслуживается
прежде следующего раннего quantum. Глобальный queue mutex не держится во время I/O.

Capture не ждёт завершения этих процессов, запись первична; никакой очереди всего
PCM в RAM для ASR. На отставании вычисления просто догоняют сохранённое позже.
Reader/worker не меняет живую meta, marker и primary manifest. Входной planner
принадлежит capture owner и не пишет версии/текст. Writer domains явные:
capture/seals и capture/plan → capture lease; incremental output/versions/receipts →
processing execution lease. Обычная API mutation получает control → capture →
processing leases до записи; compute получает processing lease, затем chunk read
leases. Это сохраняет конкурентное чтение первичного аудио без второго владельца
текстовых файлов. Capture planner читает chunk leases и не получает processing
lease; конвертер держит только chunk lease. Отказ захвата mutation lease возвращает
понятный конфликт, не ждёт окончания многочасовой записи.
Cancel processing не меняет primary capture input: для него нужны control и
согласованная остановка processing owner, но не capture lease. Иначе отмена была бы
недоступна во время записи. Delete активной записи по-прежнему отклоняется;
после Stop сначала подтверждается завершение оставшегося capture planner/decoder,
затем получается полный набор leases и удаляются файлы.

Предложенная новая настройка `LOCALVOX_LIGHT_INCREMENTAL_TRANSCRIBE=on` в presets
и каталоге, подпись «Распознавать во время записи». Общий autocook=off запрещает её
запуск. Новый bool читается при очередном планировании, поэтому может быть Live;
операция с уже снятым snapshot завершается, новая не начинается. Model/endpoint
по-прежнему имеют честный существующий срок применения, не обещаются Live.

Stop capture закрывает input и разрешает финализацию; не является cancel compute.
Cancel processing останавливает вычисления, оставляет capture и подтверждённый draft,
сохраняет durable tombstone до явного Retry, включая последующий Stop/рестарт.
Выключение раннего bool только отлагает работу до Stop, не является такой отменой.
Смена языка/best/recook/имён при занятой или записываемой сессии не мутирует вход
между проверкой и commit; вместо этого понятный конфликт по INV-SESSION-001.

### 8. Один snapshot API для UI/TUI, стабильный плеер

API возвращает source kind `partial|final`, generation/revision, строковые stable
IDs, captured/available_audio/STT/text frontiers и единый документ. Частичная
ревизия публикуется после referenced records; клиент не смешивает ответы разных
поколений. Полное чтение после EOF остаётся совместимо с текущими endpoint-ами,
новые поля additive; оба клиента используют общий выбор draft/final, не свои
догадки по наличию файлов. До первого префикса — штатное «ожидание фрагмента».

Вкладки Реплики/Текст читают готовое, без очистителей Текст — единый исходный текст.
Существующие full-copy хоткеи копируют ровно текущий подтверждённый snapshot,
без журнала/пометки partial. Полный архивный export/SRT ждёт final best.
Обновление сохраняет scroll/selection и TUI anchor по stable ID, не по индексу;
при исчезновении invalidated поколения нет молчаливого выбора чужой строки.
Завершение строки/приход новой порции не переводит фокус и не включает follow-scroll.

Аудио для активной записи адресуется revision-bound snapshot URL с фиксированными
чанками/длиной/Range/peaks. Файлы защищены теми же reader leases, недоступный
пересекающийся диапазон не подменяется нулями. Следующая ревизия не меняет `src`
playing mpv/browser player: новое аудио выбирается следующим действием пользователя,
старый snapshot остаётся доступен до обычного явного удаления записи. Если старый
файл утрачен, возвращается ошибка, не иной файл под тем же snapshot ID. Это обычный
конечный WAV снимок, без MSE/самодельного infinite streaming.

Журнал показывает время операции отдельно от recording duration, готовность до
конкретной границы и состояния «ждём следующий закрытый фрагмент», «ждём источник»,
«ждём ресурс», «финализация», «summary после Stop». Общего процента будущей записи
нет. Ошибка сохраняет последний валидный view; console grouping/unread indicator
сохраняют существующую эстетику. Не рисуем 0 s/100% там, где граница неизвестна.

## Risks / Trade-offs

- 300 s ротация → первая часть появляется с такой задержкой плюс вычисления;
  default chunk size не меняем в этой работе. Частота не обещана при отставании.
- Жизненный цикл нового лёгкого planner и цена decode/model startup → обязательные
  ownership/shutdown tests и native CPU/I/O/latency/cache-hit замеры до включения
  default. Штатный VAD/decode planner идёт только по новым PCM, полный replay —
  при recovery; дополнительные hash/verification чтения измеряются отдельно.
  Общий постоянный ASR worker остаётся отдельным решением BL-008.
- Неопределённая вторая дорожка/топология → общий preview/text может ждать до Stop;
  уже выполненный per-source STT сохранён, никакой синтетической тишины/перенумерации.
- Поздний термин меняет prompt → часть ранних LLM запросов придётся повторить;
  STT reuse не зависит от этого. Качество/полезность раннего текста не приравнивается
  к полному смысловому контролю модели.
- Disk full / power loss / захват не дал PCM → не обещаем спасение несохранённого;
  не подтверждаем неизвестное, сохраняем валидный prefix и диагностику.
- Snapshot/cache увеличивает число производных файлов → ограниченные записи на
  окно/пакет, без отдельной полной PCM копии и без автоматического удаления primary.
  Удаление session удаляет производные по существующей ownership процедуре.

## Migration Plan

Новые manifests только у новых capture sessions. Старые архивы/URL/CLI без них
обрабатываются прежним полным путём; статус чтения не доподписывает старые данные.
Согласованный комплект daemon/worker/UI/TUI, protocol preflight до запуска;
rollback — выключить incremental bool, продолжить обычный full cook по аудио.
Новый кеш старому worker не нужен и не должен приниматься им за готовую версию.

Доставлять проверенными этапами из tasks, не включать незаконченный путь пользователю.
До включения default — alternating native comparison с полным STT на одном
сохранённом публичном PCM: окна/coverage совпадают, подтверждённые окна не вызывают
ASR повторно после Stop. Предлагаемый инженерный reference-бюджет — не более 20%
overhead суммарной активной работы относительно full cook (startup/planning/verify
включены); исходные/выходные bytes, CPU/I/O, пиковая RAM и finalization latency
публикуются отдельно. Это gate на контролируемом стенде, не SLA для всего железа.
Превышение бюджета требует обсуждения lifecycle, а не удаления проверок/скрытия цены.
До замера фиксируются три offline/incremental пары, input/weights/params и расписание
публикаций. Отдельно проверяются steady порции и burst/backlog; сжатая по времени
подача публичного PCM не называется аппаратным двухчасовым capture test. Idle ожидание
новых данных отделено от суммарной активной работы, переиспользование окон измеряется
счётчиками фактических ASR вызовов. Границы речевых окон — независимый PCM/hash oracle;
совпадение текста проверяется отдельно и расхождения не замалчиваются.
User-guide обновлять вместе с доступным поведением, а не выдавать этот план за фичу.
Автономные проверки — temporary producer/API/owned workers, синтетические границы
и сохранённый публичный PCM. Рабочий daemon/личный архив не затрагиваются.
Owner microphone/loopback длительный сеанс и Mac — отдельные not-run до приёмки.
