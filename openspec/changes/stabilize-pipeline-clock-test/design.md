# Design

## Context

См. proposal.md. `workspace()` устанавливает clock на 07:00:25, но не останавливает
его. В timing тесте `since=07:00:20`; через секунду ожидаемые 5 с исчезают.
Продакшен-счётчик правильно продолжает расти.

## Goals / Non-Goals

**Goals:** точное управляемое тестовое время после загрузки страницы и независимость
от задержки Playwright/runner; сохранение скриншотов и проверок переходов/потери связи.

**Non-Goals:** остановка часов всех тестов, retries, увеличение timeout,
регулярное выражение с произвольным elapsed, обновление PNG и production кода.

## Decisions

- Разрешить fixture получить начальное время; только timing сценарий начинает
  на час раньше и после загрузки вызывает штатный `clock.pauseAt(07:00:25)`.
  Это рекомендованная модель clock API установленной версии Playwright.
  `setFixedTime` не подходит: тест должен продвигать Date.now через runFor.
- Проверить исходный и исправленный сценарий с одинаковой временной задержкой
  Node перед открытием «Ход». Задержка служит только локальному reproduction probe
  и не остаётся в suite. Все исходные assertions и baseline сохраняются.
- После outage продвигать виртуальное время до истечения capped 30 s polling
  backoff из usePolling. Прежние 3.1 s зависели от автоматического хода часов.
  Реальные expect/test timeout остаются прежними, проверка recovery сохраняется.

## Risks / Trade-offs

- Остановка до navigation может задержать загрузку → pauseAt после готовности UI.
- Изменение глобального clock поведения затронуло бы остальные проверки → default
  fixture прежний, новое начальное время задано только timing сценарием.
- Shared UI/TUI интеграция на GitHub не выполнялась → оставить её fix задачи открытыми.

## Voice grouping follow-up

На 99bd709 другой сценарий с точными 5/7 с всё ещё использовал default running
clock. Для него повторно использовать start-one-hour-earlier → readiness →
pauseAt(07:00:25), затем существующие runFor. Default workspace и production
прежние. Временную Node задержку использовать только для red→green reproduction,
не оставлять sleep/retry и не ослаблять точные значения в принятой suite.
