# Proposal

## Why

У завершённой summary предпоследней записи TUI показывает «время неизвестно», хотя `/progress` содержит начало 22:21:43.529 и конец 22:28:02.719 (379.190 с). Сводная строка журнала состоит из StageEvent, а UI/TUI берут границы только из operation_start/end. На странице хвоста начало этапа также может отсутствовать. Соседняя операция длиной 0.935 с ошибочно выглядит как 00:00 из-за целочисленного формата.

## What Changes

- Использовать существующие подтверждённые часы этапа из Progress для его строки журнала UI/TUI, включая неполный хвост.
- Сопоставлять запуск, этап и границу конкретной попытки; не переносить времена с другого запуска/повтора и не считать первый видимый heartbeat началом.
- Сохранить отдельные времена вложенных операций; положительные длительности менее секунды показывать как `<1 с`.
- Проверить исходный случай, текущий этап, повторы, отсутствующие/невалидные границы, историю и UI/TUI; обновить справочник.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `processing-pipeline`: уточнение PIPE-011 для длительностей этапов в журнале и неполной истории.

## Impact

Только проекции и форматирование UI/TUI, их проверки и документация. HTTP/хранилища/модели не меняются; дополнительных опросов и повторной обработки пользовательской записи нет. Подготовить проверенные сборки, не останавливая работающие пользовательские процессы. Незавершённый paste WIP остаётся отдельным change.
