# Design

## Context

См. proposal.md и RV-020. `near` допускает 1–2 буквенных изменения, поэтому
допустимое существующее слово может стать другой словоформой. Проверка строки
не является синтаксическим/семантическим анализатором всей встречи.

## Goals / Non-Goals

Закрыть воспроизведённые русские замены с сохранением полезных опечаток, пауз,
типографики и однозначного согласования. Не менять модели/settings/prompts,
не добавлять Python/сервис/LLM-judge и не обещать полную правильность любой ASR-правки.

## Decisions

- Использовать точный словарный разбор закреплённого `rs-morphy4 = 0.1.3`,
  опубликованный OpenCorpora словарь из crate. Тексты/словарь извне во время
  обработки не загружаются. DictionaryAnalyzer без prediction/frequency ranking,
  единая lazy OnceLock, ошибки отклоняют сомнительную замену. Не брать первый
  вероятный разбор за доказательство; учитывать неоднозначность всех разборов.
- Для близкой русской замены: неизвестное исходное слово → известное допустимо
  в прежнем edit budget; два известных слова требуют отдельного строгого основания;
  неизвестное → неизвестное сохраняет источник. Отсутствие слова в словаре само
  по себе не доказывает опечатку: это остаётся пределом, не общей смысловой гарантией.
- Узкое основание для valid→valid: непосредственно соседнее неизменённое подлежащее
  в начале предложения, все его разборы однозначно именительные; тот же глагол,
  прошедшее время, прежние прочие грамматические признаки. Исходная форма не
  согласуется ни с одним разбором подлежащего, новая согласуется со всеми. Разборы
  подлежащего/глагола с альтернативной ролью, пунктуация между ними, смена леммы,
  времени/вида/наклонения не подтверждают поправку. Это ограниченное правило, не
  полный parser; оно сохраняет прежнее полезное исправление согласования.
- Прежний двухсловный ASR repair также проходит словарное основание для каждого
  заменённого русского слова и ограничение длины; он не обходит новый admission.
  Пробелы/регистр/пунктуация/однозначные паузы сохраняют прежние пути. Нерусские
  буквенные замены остаются под прежними guards, не объявляются проверенными словарём.
- Словарные данные остаются неизменёнными в зависимости; добавить attribution и
  лицензионные тексты, включить их в release archives. Не переносить 20 MB данных
  в Git. Pin/lock и black-box тесты фиксируют используемые предположения.
- Проверять старый source/candidate через новый guard, отдельно от native calls.
  Короткие corpus и четыре длинных сохранённых результата не изменяются. Настоящий
  worker с fake provider проверяет интеграцию refine/cleanup и receipts. Локальная
  Ollama/демон не вызываются. Холодную загрузку/стоимость словаря и размер бинарника
  измерять отдельно от генерации модели, Mac/аудио остаются not-run.

## Risks / Trade-offs

Неполный словарь/новые термины → консервативные отказы, глоссарий остаётся каноном.
Верные формы могут быть неподтверждённым ASR → часть полезных правок отклоняется;
измерить сохранение 24 коротких useful и контекстно проверенных длинных правок.
Новое неизвестное слово может быть именем → прежний grounding/цитаты/числа остаются,
общая семантическая приёмка не заявлена. Дополнительные данные/RSS → lazy загрузка,
без динамического накопления сессионных текстов, release CPU/память измеряются.

## Migration Plan

Форматы/история не мигрируют. Новый worker использует проверку при новых вызовах;
в этом этапе собираются тестовые worker/checker, работающая установка не переключается.
