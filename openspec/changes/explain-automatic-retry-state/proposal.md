# Proposal

## Why

После ошибки workflow сообщает об ожидаемом автоматическом повторе, не проверяя доступность координатора. Список очереди скрывает фазу и срок backoff; старое Failed без failed_at противоречиво выглядит как требующее ручного повтора в «Ход», хотя scheduler может вернуть его автоматически. Это мешает выполнить PIPE-011 и уточнённый PIPE-016.

## What Changes

- Общий расчёт статуса автоматического повтора для progress и queue: подтверждённое ожидание, недоступный/неподтверждённый координатор, исчерпанный бюджет; неизвестное время не заменяется выдуманной датой.
- Queue API дополнительно сообщает фазу и план повтора. UI/TUI показывают фазу, число попыток, причину и «не раньше», сохраняя порядок и прежние действия.
- Проверить интервалы 1/2/4 часа, границы restart/retry, старые данные, недоступность и восстановление. Политику планировщика и число попыток не менять.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `processing-pipeline`: уточнить PIPE-011 для статуса повторов в общей очереди и при недоступном координаторе, сохраняя прежние обязательства.

## Impact

Core workflow, Archive queue, клиентские DTO, UI queue и TUI projection. Поля API добавляются совместимо; jobs.json, POST retry/recook, лимиты и автоматические интервалы неизменны. Модели, пользовательский архив, аппаратная приёмка и BL-002/004 вне этого среза.
