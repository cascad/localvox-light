Chain также завершился с проверенными refined/processed receipts: refine изменил
237 строк, после него cleanup сохранил 258 дополнительных edits; 1 строка без ответа,
18 поправок отвергнуты. Один repeat с temperature 0.2 не гарантирует одинаковый
набор поправок в разных запусках. Совместное время **9 мин 17 с** подтверждает цену
двух полных генераций; исходный час на материале владельца этим не воспроизведён.

Summary включает один повтор после проверки. Из 154.926 s generation заняла
56.427 s, операции grounding — 74.762 s (48.3% wall); первая 69.211 s,
остальные девять 0.536–0.807 s. GLiNER действительно загружен. Общая операция
пока не разделяет lexical/source NER/answer NER/matching; эти 69 s нельзя честно
приписать одному компоненту. SourceEntities уже повторно использует исходные
сущности внутри документа. Более узкий
[profile-summary-grounding-cost](../../profile-summary-grounding-cost/proposal.md)
остаётся proposal-only, его задача не закрыта этим общим замером.

Wall включает процесс, чтение/запись и проверки. Вне HTTP — остаток wall после
последовательных proxy requests, не отдельный профиль каждого validator. Вложенные
операции журнала не складываются с wall. Load/prompt/generation — counters самого
Ollama; их сумма может отличаться от HTTP wall. Resource counters worker не включают
внешний Ollama/его GPU/RAM, поэтому малый worker RSS не является памятью всей LLM.

## Подтверждённые выводы текущих случаев

- Генерация занимает 95.2% wall refine и 92.6% cleanup. Полный текст генерируется
  заново: 31–32 тысячи output tokens. Проверки исходных строк не объясняют основное время.
- Cleanup создаёт гораздо больше запросов и почти вдвое больше prompt tokens,
  но в этом последовательном прогоне быстрее refine. Увеличение пакета само по себе
  не доказано главным способом ускорения; условия residency различаются.
- Chain генерирует 64045 output tokens и тратит 525.591 s на generation (94.3% wall).
  Два прохода фактически занимают почти сумму отдельных случаев; это наблюдение
  одного reference, не универсальная формула для другого текста/оборудования.
- Автоматический режим STT + optional summary уже исключает оба прохода по решению
  владельца. Этот замер не включает их обратно и не ослабляет сохранение оригинала.
- Summary имеет другой профиль: почти половина wall приходится на grounding.
  Оптимизация правки текста и разбор первой проверки summary — разные задачи.

Следующий обоснованный эксперимент для ручной правки: измерить выдачу **только
изменённых строк** на том же материале, сохранив привязку/проверки/исходные строки.
Это пока эксперимент, не новая доступная функция и не принятое качество prompts.
Нужно сравнить output tokens, wall, пропуски/отклонения и содержание поправок.
Одно ускорение без проверки качества не разрешает смену production prompt.
Часовой инцидент владельца требует его материала/исторических условий или логов:
на этом reference одна правка заняла 4–5 минут, оба прохода вместе — около 9 минут.
Эти числа не задают SLA для всех записей и моделей.
