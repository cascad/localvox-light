# Proposal

## Why

Владелец выбрал vox как единый запуск демона и TUI и отдельно согласовал полный
выход. Обычный выход сохраняет daemon; для завершения всего приложения нужна
понятная отдельная команда, без убийства процессов по имени.

## What Changes

- «Завершить LocalVox» как отдельное действие TUI, доступное через палитру.
- Перед полной остановкой — подтверждение; активная запись явно упоминается.
- Запрос к подключённому daemon использует обычную авторизацию API и существующий
  graceful shutdown: закрытие записи, сохранение/восстановление очереди, owned workers.
- Клиент сообщает ход завершения и закрывается после подтверждённой остановки;
  ошибки не выдает за успех. Обычные qq/F10/Ctrl+Q остаются выходом только из TUI.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `runtime-settings`: RUN-006 явный полный выход через TUI и управляемую остановку демона.

## Impact

Lifecycle/API control, client effect и TUI confirmation/status, relevant tests,
US-062/docs/evidence. Не посылать signals произвольным PID, не искать процессы по
именам, не останавливать работающий daemon владельца ради разработки. Аппаратную
проверку аудио оставлять отдельно от tests на временном API/capture fixtures.

Отдельный этап после vox; реализация и фактические проверки отслеживаются в tasks
и evidence этого change. Приёмка настоящей записи на Mac остаётся у владельца.
