# Проверка удаления · 2026-11-23

## Что установлено

Владелец уточнил: на Mac зависает открытие удаления **небольшой записи в архиве**,
до подтверждения. Это не свидетельство зависания файлового удаления заметки.
Точную причину зависания его терминала агент не воспроизвёл; Mac приёмка остаётся
**not-run**. Привязка зависания к длине текста не доказана.

Подтверждённый дефект TUI: DeleteSession всегда выбирал current — документ справа,
хотя в списке мог быть выделен другой. Также отсутствовала клавиша d. Исправлен
контекст списка/деталей, включая фильтр. Цель и компактный заголовок фиксируются
при открытии подтверждения; до s нет запроса удаления. Esc отменяет без I/O.
Буква d в редакторе и строке поиска остаётся текстом.

При успешном ответе проверяется deleted, равный исходной identity. Список/курсор
обновляются, а epoch нижняя граница для Sessions/Queue/Jobs отсекает чтения,
начатые до acknowledgement. Поэтому поздний poll не возвращает запись или её
ошибку. Открытый сосед и плеер сохраняются. Ошибка/неверный ответ сохраняет
данные и подтверждение для повтора. Правила ARCH-005 на сервере не менялись.

Для Notes те же d/Delete/s/Esc, captured slot/raw/source, ограничение item после
удаления и смены слота. Удаляется заметка, слот сохраняется; пустой/недоступный
контекст объясняется. NOTE-003 и production файловая интеграция не менялись.
US-023/030 и подсказки обновлены.
