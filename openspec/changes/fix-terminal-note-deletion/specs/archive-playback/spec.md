# Spec Delta

## ADDED Requirements

### Requirement: ARCH-021 Контекстное удаление выбранной записи в TUI

В «Архиве» d/Delete и команда «Удалить запись» SHALL открывать подтверждение для
выбранной видимой строки при фокусе списка, для открытой записи — при фокусе деталей.
Открытие подтверждения SHALL не удалять данные, не переключать документ/плеер и
оставлять рабочими s для подтверждения и Esc для отмены. Заголовок SHALL быть
компактным, цель операции SHALL оставаться исходной при смене выбора и обновлениях.
Текстовый ввод SHALL сохранять d как символ. После подтверждённого удаления выбор
SHALL оставаться допустимым, старое чтение списка SHALL не возвращать удалённое.
Отказ API SHALL сохранять данные и показывать причину. Правила ARCH-005 сохраняются.

Код: [commands](../../../../../crates/localvox-light-terminal/src/app/commands.rs),
[input](../../../../../crates/localvox-light-terminal/src/app/input.rs),
[responses](../../../../../crates/localvox-light-terminal/src/app/responses.rs).

#### Scenario: Выбранная и открытая запись различаются
- **WHEN** открыт A, но в отфильтрованном списке выбран B и вызвано удаление
- **THEN** подтверждение относится к B, Esc не меняет данные, s отправляет ровно
  один запрос для B; A остаётся открыт и продолжает воспроизведение.

#### Scenario: Запоздалое чтение
- **WHEN** удаление B подтверждено, а затем приходит старый список с B
- **THEN** B не возвращается в интерфейс и выбор остаётся на доступной записи.

#### Scenario: Отзывчивое подтверждение
- **WHEN** пользователь открыл удаление через d или палитру
- **THEN** окно подтверждения появляется и отвечает на Esc/s без обращения к API
  до подтверждения, а задержанный или ошибочный запрос не блокирует выход/управление.
