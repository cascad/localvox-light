# Design

## Context

Используем неизменённые profiler/worker и 72-case evaluator предыдущего этапа.
Проектный reference — Qwen 3.5 9B. Установленные Granite 4.1 не требуют скачиваний.
Mac в текущей среде недоступен; его фактическая скорость остаётся hardware not-run.

## Goals / Non-Goals

Сузить выбор по качеству/полезности и относительным native counters на одной машине.
Не выдавать RTX tokens/s за Mac benchmark, не заменять полную правку моделью только
пунктуации и не смешивать качество cleanup с качеством summary.

## Decisions

- Один frozen 72-case corpus, три repeats; дополнительный заранее фиксированный
  holdout с оборванными/соседними репликами, ответы и literal данные не переносить
  между строками. Guards не меняются. Источник/receipts проверяет прежний evaluator.
- Все установленные три кандидата проходят оба набора. Кандидат для длинного прогона:
  ноль violation/review и ≥22/24 полезных правок во всех repeats первого набора,
  ноль нарушения привязки строк во втором. Иные формулировки можно разобрать явно,
  но это не основание молча ослабить gate. Если никто не проходит, длинный прогон
  пропускается с отрицательным результатом, без выбора победителя по одной скорости.
- Native calls последовательно, на копиях в D: target; источники и `.env` не менять.
  Учитывать отдельные cold/load counters, сохранить model digests и точные options.
- Сравнение движков — по первичным документациям и требованиям интеграции. MLX
  применим к Apple Silicon, CPU/Metal llama.cpp — иной вариант исполнения. Model
  weights/quant/context и прогон на Mac нужны для честного сравнения; смена движка
  не доказывает улучшения смысла. Новый backend этим этапом не внедряется.
- Последующее поручение владельца: SAGE 95M скачана в F: с pinned revision и
  проверенным SHA-256; отдельное окружение Python на F:, CPU 2 threads, без CUDA.
  Один процесс/одна загрузка, greedy per-line inference, три repeats обоих corpora.
  Это raw model test без production guards/receipts. Область SAGE — орфография и
  пунктуация: отдельно оценить 8 format/asr-repair случаев, паузы/повторы не выдавать
  за её заявленную capability. Остальные инварианты/неожиданные замены не скрывать.

## Risks / Trade-offs

- Короткий набор может пройти модель, ошибающаяся в длинной речи → holdout и затем
  публичный runtime; отсутствие ошибок не объявляется общей гарантией.
- Слишком строгий exact oracle → статус review и явный разбор; не редактировать
  corpus по полученным ответам и не приравнивать пунктуацию к смысловой потере.
- Иная система памяти на Mac → размеры model file только ориентир, не peak RAM;
  аппаратное измерение оставить открытым, использовать старый Qwen как известную базу.

## Migration Plan

Нет rollout. Сохранить измерения и shortlist; для другого runtime или новой
пользовательской операции потребуется отдельная реализация/проверка.
