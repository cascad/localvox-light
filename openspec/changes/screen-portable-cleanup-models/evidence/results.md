## SAGE 95M вне Ollama

По прямому поручению скачаны 8 файлов в `F:\project_models\sage-fredt5-95m`:
revision `ed51b4a46603931380951a3d8456685c9215864f`, SHA-256 model.safetensors
`e005b48ae460cbf5f82f0f3da8b13d5df7c2c98eb1e02ed8a7d525d3de7a9bfe`.
Хеш совпал с upstream LFS. Веса 382561704 bytes; конфиги/токенизатор также на F:.
Изолированное окружение и caches на F:, глобальный Python не изменялся.

Python 3.12.3, torch 2.9.1+cpu, transformers 4.57.1, CPU 2 threads/inter-op 1,
greedy decoding. Один процесс/одна загрузка, отдельный вызов на каждую строку;
сеть выключена, CUDA не используется. Все 288 выходов завершились EOS без усечения.
Это **raw model test без production guards**, а не worker/receipt acceptance.
[Полные собственные результаты и hashes](sage-cpu-results.json),
[команды и runner](../../../../docs/sage-quality.md).

- Основные 72 фразы: 6.635 / 6.139 / 6.386 s. Отдельные 24 строки: 2.762 / 2.773 / 2.823 s.
- Импорт библиотек ~5.112 s, загрузка модели ~0.266 s в этих условиях. Parameter
  storage ~382.5 MB, **не peak RSS всего Python**. Файловый кеш/диск влияют на cold start.
- Из 8 format/asr-repair ожиданий выполнены 7/8 во всех повторах. Удаление пауз и
  повторов не является заявленной задачей этой модели, это не полный паритет cleanup.
- Strict oracle: основной набор expected 48, missed 9, review 10, violation 5;
  boundary expected 20, review 3, violation 1. Повторы одинаковые, это устойчивость
  greedy output, а не независимая статистическая оценка надёжности.

**Важно разобрать типы несовпадений:** четыре из пяти основных literal violations
— замена типа кавычек при сохранённых цитируемых словах. Они не названы смысловой
потерей. Три boundary review — добавленные многоточия к обрывам, не перенос реплик.

Смысловой дефект во всех повторах: «Сначала сохрани запись, потом удали временный
файл» → «Сначала сохранил запись, потом удалил временный файл». Повеление стало
утверждением о прошлом действии. В boundary прямое цитирование «эээ» также переписано
в другую форму с дефисами. Полезная орфография не оправдывает эти изменения.
ONNX-оптимизация/встраивание сейчас не выполняются: сначала нужно защитить содержание.

## Варианты вне текущего runtime

Проверены первичные источники, 2026-11-02. Ни один чужой benchmark не подменяет наш.

| Кандидат | Что проверено / ограничение |
|---|---|
| [SAGE 95M](https://huggingface.co/ai-forever/sage-fredt5-distilled-95m) | Русская орфография/пунктуация, T5. CPU-прогон выполнен выше; summary не строит, смысловой дефект остаётся. |
| [RUPunct small](https://huggingface.co/RUPunct/RUPunct_small), [INT8 export автора конвертации](https://huggingface.co/ekhodzitsky/rupunct-small-onnx) | Token classification знаков/регистра, ONNX ~29 MB по карточке export. Runtime не запускался. Может стать узким оформителем, не заменяет ASR word repair/cleanup/summary. GigaAM e2e в проекте уже выдаёт пунктуацию. |
| [Granite 4.2 3B](https://huggingface.co/ibm-granite/granite-4.2-3b) | Свежий компактный вариант, но русский не входит в заявленные Tested Languages. Не установлен/не проверен, не рекомендован только за свежесть. |
| [Ministral 3 3B](https://ollama.com/library/ministral-3) | Ещё компактный кандидат общего назначения, веса ~3 GB по каталогу. Не установлен/не проверен; сам по себе не решает сохранение цитат и границ. |
| [MLX LM](https://github.com/ml-explore/mlx-lm) | Runtime для Apple Silicon, quantized models. Это не новая модель и не исправление качества; Mac runtime/конкретный checkpoint здесь not-run. |
| [llama.cpp](https://github.com/ggml-org/llama.cpp) | CPU/Metal и локальный API — другая обвязка исполнения. Переход без прямого аппаратного сравнения не обоснован. |

Для T5 потенциальный путь без Python в продукте — экспорт encoder/decoder и loop
генерации в Rust/ONNX Runtime. [Optimum поддерживает экспорт encoder-decoder](https://huggingface.co/docs/optimum-onnx/onnx/usage_guides/export_a_model),
но экспорт/совпадение именно этих весов и скорость на Mac ещё не проверены. Менять
runtime до исправления смысловых ошибок не является способом улучшить качество.
