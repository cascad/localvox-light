## ADDED Requirements

### Requirement: INV-SESSION-001 Exclusive session mutation

Любая операция, изменяющая или удаляющая данные сессии, SHALL получить согласованное владение до первого изменения: recook, delete, best, lang, source/speaker rename. Для отмены и удаления занятой записи система SHALL сначала запросить управляемую остановку и подтвердить освобождение записи. Удаление SHALL выполняться только после получения владения; неудачная остановка SHALL оставлять файлы на месте и сообщать причину. Остальные конфликтующие мутации SHALL возвращать понятный отказ до записи файлов, без скрытого отложенного применения. Отмена SHALL сохранять подтверждённые результаты и не объявлять недоделанные этапы успешными. Предложение расширяет PIPE-012 согласно [DEC-007](../../../review-code-inventory/proposal.md#dec-007), не объявляет нынешние API защищёнными.

#### Scenario: Delete during worker execution

- **WHEN** worker удерживает сессию и запрошено delete
- **THEN** запрошена остановка; каталог остаётся на месте до подтверждённого освобождения записи и получения владения, затем выполняется удаление.

#### Scenario: Stop fails before deletion

- **WHEN** worker не подтвердил остановку или запись по-прежнему занята
- **THEN** удаление не выполняется, видна причина незавершённой операции; отсутствие heartbeat и истечение ожидания не разрешают удалить файлы.

#### Scenario: Cancel after a completed phase

- **WHEN** пользователь отменяет текущую обработку после сохранения валидной расшифровки
- **THEN** обработка останавливается, расшифровка остаётся доступна; незавершённая сводка не помечается готовой и отменённая работа не возобновляется немедленно как автоматический retry.

#### Scenario: Change language during worker execution

- **WHEN** worker удерживает сессию и запрошена смена языка
- **THEN** meta не изменяется до получения владения; отказ сохраняет прежний язык и производные.

#### Scenario: Change best or names during worker execution

- **WHEN** запись занята и запрошены best либо переименование источника/говорящего
- **THEN** операция возвращает понятный конфликт без изменения файлов и без скрытого применения после завершения worker.

#### Scenario: Manual CLI competes with API

- **WHEN** обычный CLI держит блокировку сессии
- **THEN** API использует ту же границу владения; если подтвердить управляемую остановку владельца нельзя, отмена/удаление сообщают об этом и не обходят его владение, остальные мутации возвращают конфликт.
