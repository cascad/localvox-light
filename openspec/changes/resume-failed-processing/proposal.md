# Proposal

## Why

Кнопка «Повторить» остановленного задания в UI вызывает recook без scope, то есть полную переработку. Ошибка summary приводит к повторному STT и инвалидированию годных производных; ingest на Prepare без аудио через этот путь повторить нельзя. Это мешает сохранять выполненную работу по PIPE-010/012 и DEC-003.

## What Changes

- Отдельная команда возобновляет существующее Failed-задание с его незавершённой фазы, сохраняя вид задания, настройки и артефакты. Даёт новый ограниченный бюджет попыток, снимает force и начинает новую границу ручного запуска.
- Запрещает возобновление Running/Pending/Done, активной записи и занятой worker сессии. Ошибка очереди не подтверждается успехом.
- Кнопка очереди и именованная команда TUI используют возобновление; явные «Повторить сводку/текст/всё» сохраняют свои операции recook.
- Проверки исходного отказа, сохранности файлов, гонок/повторов HTTP, переходов, UI/TUI и совместимости.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `processing-pipeline`: уточнить PIPE-010 — возобновление упавшего этапа отдельно от принудительной переработки по PIPE-012.

## Impact

Core JobQueue, Archive/HTTP, Rust/TypeScript clients, UI queue и TUI actions. Новый POST /api/sessions/{name}/retry, успешные старые API и формат jobs.json совместимы. Автоматический ремонт Done, controlled cancel/delete, модели и аппаратная приёмка остаются за пределами этого среза.
