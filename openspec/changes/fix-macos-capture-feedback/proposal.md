# Proposal

## Why

После успешных поведенческих тестов владелец сообщил: микрофон на Mac пишет,
системный звук не появляется даже при явно включённом loopback. Подтверждены
отсутствие macOS usage descriptions у daemon binary и потеря capture errors
для HTTP-клиентов (daemon вызывает engine без UiMsg channel). Причина тишины
на конкретном Mac без native диагностики пока не установлена.

## What Changes

- Добавить daemon metadata для штатного macOS запроса доступа к аудио.
- Показывать фактическое состояние микрофона и системного звука в UI/TUI,
  сохранять ошибки в существующей консоли без спама при повторах.
- Различать открытый поток и подтверждённый входящий сигнал; тишину не называть
  отказом разрешения, которого система нам не подтвердила.
- Исключить незаметный захват входа вместо выхода на duplex macOS устройстве.
- Проверить переходы состояния, HTTP, UI/TUI и metadata; аппаратный Mac повтор
  оставить отдельной обязательной проверкой, не подменять mock-тестами.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `recording`: REC-004 — состояния отдельных источников, доступ и ошибки захвата
  доступны пользователю независимо от UiMsg channel демона.

## Impact

Core audio/engine, daemon build metadata, additive /api/record fields,
Rust client, TUI/header/console, GUI recording bar, пользовательский справочник.
Модели, обработка архивов и конфигурация выбранных устройств не меняются.
