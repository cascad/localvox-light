# Подтверждать приём ссылки сохранённым заданием

Статус: **implemented / tested in source tree**; установленный release не обновлён.
Результаты: [evidence](../../evidence/implementation-review-2026-09-27.md).
Основание: [BL-001](../../backlog.md#bl-001). Это отдельное предложение, baseline пока описывает код.

## Why

На момент обнаружения from_url игнорировал bool enqueue_ingest, а save_meta_public не возвращал ошибку. Сохранение каталога и очереди не является одной транзакцией.

## What Changes

Подтверждать приём ссылки сохранённым заданием. Поведение при отказе и повторе описано в delta spec.

## Capabilities

### New Capabilities

Нет новых возможностей продукта.

### Modified Capabilities

- `processing-pipeline`: уточнение поведения для описанных сценариев.

## Impact

Core/API и связанные сценарии; исходное аудио не мигрируется. Работа с установленной
сборкой и архивом пользователя этим документом не выполняется.

## Исходные сведения BL-001

**Ошибка сохранения при приёме ссылки должна доходить до пользователя.**
Тип: дефект; состояние: `open`; контракт: PIPE-001, SC-PIPE-02.
Обнаружено 2026-09-27 при сверке кода: [ingest::from_url](../../../crates/localvox-light-core/src/ingest.rs)
игнорирует bool из `enqueue_ingest`; `save_meta_public` не возвращает ошибку.
Это вывод из исходников, отказ реального диска не воспроизводился.
Готово, когда отказ сохранения meta/очереди даёт ошибку API/CLI, исходные данные не
теряются, а успешный ответ имеет читаемое задание на диске. Нужна проверка отказа записи.
