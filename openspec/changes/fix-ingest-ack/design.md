# Проект решения

## Context

Сегодня from_url игнорирует bool enqueue_ingest, а save_meta_public не возвращает ошибку. Сохранение каталога и очереди не является одной транзакцией.

## Goals / Non-Goals

Цель: подтверждать приём ссылки сохранённым заданием. Не включать глобальную перестройку хранилища и бессрочное
расширение гарантий на все процессы приложения.

## Decisions

Сделать сохранение источника/постановку Result-операцией с проверкой обоих результатов. Явно определить безопасный повтор при созданном каталоге без job; не обещать общей файловой транзакции без механизма.

Реализация 2026-09-27: checked atomic write метаданных, затем enqueue под queue mutex.
При отказе очереди источник сохраняется; ошибка сообщает имя сессии. Повтор создаёт
новую сессию без удаления прежней. Atomic create_dir резервирует уникальный каталог
при одновременном приёме ссылок. Enqueue при отказе сохранения откатывает свою
мутацию в памяти; общей транзакции meta/jobs нет. Проверка — в
[журнале сверки](../../evidence/implementation-review-2026-09-27.md).

## Risks / Trade-offs

Не принимать описание механизма за доказательство crash-safety. Работа затрагивает
повтор/отказ и должна иметь проверку на временном архиве; нужен ревью выбранного поведения.

## Verification

Воспроизвести отказ записи meta и jobs на временном хранилище; проверить успешный ответ повторным чтением после открытия очереди.
