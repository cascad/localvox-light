# Смешанный журнал: сохранение этапов и стоимость опроса · 2026-10-31

Продолжение после контрольного коммита `867825b`. Затронуты принятые
PIPE-002/004/008/011 и delta PIPE-016. Ранее выполненные проверки остаются
историческими; этот прогон проверяет пропущенное взаимодействие двух форматов.

## Воспроизведение дефекта

StageEvent, RunMark и новые операции используют один progress.jsonl. Старый
RunMark допускал неизвестные поля: любая journal-запись с run читалась как граница
запуска и очищала накопленные события этапов. После вывода диагностики/operation_end
терялись начало и завершение; interrupted_stage мог не заметить прерванный worker.
Проверенный артефакт оставался доступным, но уже без времени из стёртого представления.

Регрессия `journal_operations_do_not_erase_stage_events_or_hide_an_interruption`
до исправления упала: `None` вместо `Some(Transcribe)` после обычной строки журнала.
Это подтверждённая причина потери представления этапов, а не доказанная причина
часовой генерации текста в пользовательской записи.

## Исправление

- [progress](../../../../crates/localvox-light-core/src/progress.rs): только самостоятельный RunMark сбрасывает запуск; journal-записи отделены от StageEvent. История читается потоково; run и события возвращаются одним чтением. Сломанная JSON/UTF-8 строка не скрывает соседние записи.
- [workflow](../../../../crates/localvox-light-core/src/workflow.rs): удалено второе полное чтение/разбор истории; уже проверенный STT переиспользуется внутри одного ответа.
- [artifacts](../../../../crates/localvox-light-core/src/artifacts.rs): версия читается и строго разбирается один раз; прежний канонический SHA-256 строится из тех же строк, которые проверяются. Между запросами файл проверяется заново, постоянного кеша по mtime нет.
- [HTTP-регрессия](../../../../crates/localvox-light-api/src/http/tests/workspace.rs): перемешанные события, завершённый STT, активная summary, привязанная операция и завершение проверены настоящими запросами типизированного клиента. Границы STT сохраняются на каждом переходе.
- [Восстановление очереди](../../../../crates/localvox-light-core/src/jobs.rs): прежний startup-тест дополнен диагностикой и operation_end; reclaim помечает прерванный этап Failed, сохраняя счётчик.

## Измерение

Один временный синтетический архив: 7200 строк с таймкодами на 7200 секунд,
валидные STT/cleanup/summary receipts. В истории 1 либо 12 запусков, по 400 записей
диагностики с текстом 2048 символов, события начала/завершения и operation_end.
Аудио/модели/сеть не используются. Сначала один прогрев, затем 5 измерений;
в таблице медианы, min/max сохранены в [before](mixed-history-before.json) и
[after](mixed-history-after.json).

Windows, dev-сборка без ONNX. CPU сообщает имя AMD Ryzen 9 9900X3D; окружению
доступно 6 логических CPU. Это локальный замер с прогретым файловым кешем,
не SLA release-сборки, не benchmark BL-003 и не оценка качества распознавания.

| История | Размер, байт | Чтение before → after, мс | Полная схема before → after, мс | Сохранено событий before → after |
|---|---:|---:|---:|---:|
| 1 запуск | 854253 | 2.267 → 2.367 | 236.057 → 119.316 | 0 → 2 |
| 12 запусков | 10251036 | 28.201 → 29.434 | 295.281 → 146.636 | 0 → 2 |

Полный опрос схемы занял примерно вдвое меньше времени. Само корректное потоковое
чтение немного медленнее ошибочного старого фильтра; выигрыш получен удалением
повторной работы в workflow/проверке транскрипта. Полный файл истории больше не
выделяется одним буфером; RSS отдельно не измерялся.

Воспроизведение из корня репозитория:

```powershell
$env:LOCALVOX_PROFILE_OUTPUT = Join-Path (Get-Location) 'target/mixed-history-profile.json'
cargo test --locked -j 2 -p localvox-light-core --lib progress::tests::profile_mixed_history_polling -- --ignored --exact --nocapture --test-threads=1
```

Baseline получен до исправления, с тем же тестом и входными данными; повтор текущей
команды измеряет текущую реализацию. В обычном тестовом прогоне profiler ignored,
порог времени не зашит в unit-тест.

В первом общем прогоне launcher-test не уложился в искусственные 3 секунды;
отдельный повтор прошёл за 2.68 s. Затем общий process-прогон дал 8 отказов,
последовательный повтор — 3 (ожидание первого вывода, бюджет вложенного запуска,
assert менее 4 s для успешного noisy worker). Это исходные отказы проверок,
они не выдаются за успешные прогоны. Связь с конкуренцией/задержками запуска —
вывод по поведению повторов, не системная трассировка и не доказанный дефект модели.

Уточнены только тестовые условия: успешный launcher использует штатный START_TIMEOUT
15 s, fixture живёт ограниченно дольше; observer ожидается в пределах 8 s budget
worker, noisy-проверка использует 15 s с учётом termination/reap; вложенный запуск
имеет 20 s budget. Проверки Cancelled, гибели дерева, первой порции до завершения,
переполнения канала, границ вывода и самого timeout сохранены. Добавлена диагностика
termination/elapsed/stderr; CI ограничивает libtest двумя потоками (внутренняя
конкуренция проверяется самими сценариями). Итоговый общий прогон 111 passed —
после этих изменений. Рабочие лимиты запуска/обработчиков приложения не изменялись.
