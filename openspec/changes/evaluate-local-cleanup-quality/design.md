# Design

## Context

См. proposal. Имеются неизменённый release worker, text-only profiler, native
результаты длинного публичного cleanup Gemma/Qwen и узкий sparse corpus.
Новый набор проверяет обычный cleanup через его реальные guards и processed.json.

## Goals / Non-Goals

Оценить сохранность заданного содержания, полезность однозначных правок и разброс
повторов. Исправление guards, качество первичного ASR/summary и автоматическое
принятие новой модели не входят в это измерение.

## Decisions

- Собственные synthetic фразы с заранее заданными допустимыми вариантами и
  обязательными фрагментами. Не использовать другую LLM как единственного судью.
  Правила просты и проверяемы: не спутать допустимый порядок слов с потерей смысла.
- Различать `expected`, `missed`, `violation`, `review`: совпадение с допустимым
  вариантом; сохранённый исходник вместо требуемой правки; нарушенный инвариант;
  иная переформулировка. Последняя требует разбора и не объявляется ошибкой или
  успехом автоматически. No-op на позитивных примерах не засчитывается полезностью.
- Gemma E4B и Qwen 3.5 4B, по три независимых worker repeats одного набора при
  штатном sampling. Порядок фиксируется, exclusive GPU ownership не предполагается.
- Проверяющий инструмент читает только явно заданный profiler output; проверяет
  complete/success, source/версию/границы edits/receipts, запрет sparse для этого
  режима оценки. Изменённый источник и некорректный артефакт — отказ измерения.
- На публичном результате автоматические lexical/number/quote/modality флаги
  означают запрос на просмотр, не доказанную ошибку. Просмотреть в контексте
  стратифицированную выборку изменений обоих моделей, сохранить индексы и основания.
  Не коммитить полный транскрипт; собственные synthetic source/actual допустимы.
- Пределы: текстовая сверка не заменяет аудио; фразы исходного STT уже могут быть
  неверными. Оценка агентом обозначается agent-review, приёмка владельцем not-run.

## Risks / Trade-offs

- Набор невелик и искусственный → фиксировать категории/знаменатели и не выдавать
  процент за общую вероятность ошибок или качество всех встреч.
- Жёсткий oracle не принимает полезную переформулировку → отдельный review и
  объяснение; не подгонять ожидаемые варианты после получения ответов модели.
- Опасная поправка отклонена worker → оценивать сохранённый результат, не приписывать
  модели самостоятельную безопасность. Сырые native предложения здесь не сохраняются.

## Migration Plan

Изолированное измерение на D:, без миграции настроек/архива. Результаты не меняют
производственный режим. RV-018 остаётся открытым до отдельного исправления/регрессий.
