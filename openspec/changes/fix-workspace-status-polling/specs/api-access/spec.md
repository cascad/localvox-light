## ADDED Requirements

### Requirement: API-006 Независимый опрос состояния UI

UI SHALL опрашивать архив, очередь заданий и состояние записи независимо, без
накопления параллельных фоновых чтений одного ресурса. Медленное чтение одного
ресурса SHALL не задерживать публикацию других состояний. Явное обновление после
пользовательского действия SHALL отменять предыдущее чтение и не принимать его
поздний ответ. При ошибке SHALL сохраняться последние доступные данные; отмена
чтения SHALL не повторять изменяющий запрос и не объявляться остановкой сервера.
Начало записи SHALL по-прежнему подтверждаться состоянием движка по REC-001.

Код: [App](../../../../../ui/src/App.tsx),
[polling](../../../../../ui/src/usePolling.ts), [GET API](../../../../../ui/src/api.ts).

#### Scenario: Медленный фоновый запрос
- **WHEN** чтение sessions, jobs либо record не закончено к следующему интервалу
- **THEN** для него не запускается ещё одно фоновое чтение, остальные ресурсы продолжают обновляться.

#### Scenario: Импорт во время опроса архива
- **WHEN** принят импорт, а старое чтение архива ещё ожидается
- **THEN** явное обновление получает новый архив, поздний старый ответ не убирает принятую запись из UI.

#### Scenario: Подтверждение записи
- **WHEN** запись подтверждена движком и UI обновляет состояние после start/stop
- **THEN** старый фоновый GET не меняет подтверждённое состояние после нового снимка; start/stop не повторяются автоматически.

#### Scenario: Ошибка и восстановление
- **WHEN** очередной фоновый GET завершился ошибкой, затем следующий удался
- **THEN** доступные данные сохраняются, после успешного чтения отображается свежий снимок.
