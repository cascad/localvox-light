# Design

## Context

См. proposal. BL-005 уже воспроизводит HTTP 503 и закрытый endpoint настоящим
worker/API. SEARCH-002 требует ошибку semantic; сейчас per-session skip вместе
с early return пустого search скрывает полный отказ векторизации.

## Goals / Non-Goals

Вернуть причину, когда не удалось получить ни одного доступного вектора.
Сохранить частичные/прежние данные и обычный пустой ответ для пустого архива.
Не менять embeddings, model thresholds, API JSON, retry policy или архив владельца.

## Decisions

Сохранить первую ошибку embed при сканировании сессий, продолжить обработку
остальных. После прежней атомарной записи/очистки производного индекса вернуть
ошибку, если docs пуст и причина есть. При доступных docs оставить прежнюю
деградацию. Немедленный return на первой сессии потерял бы успешные следующие
сессии; успешный пустой индекс снова скрыл бы отказ.

Native BL-005 является регрессией: red assertion semantic.is_err → green;
добавить пустой архив без запроса, восстановление и сохранность кеша при отказе.
Отдельный mock-алгоритм индексации вместо этого теста не создаётся.

## Risks / Trade-offs

- Клиент, принимавший отказ за «ничего нет», теперь увидит ошибку → это исправление
  SEARCH-002, hybrid продолжает работать по lexical.
- Частичный индекс не гарантирует полноту поиска → сохраняется прежнее поведение,
  синтетические векторы не доказывают качество retrieval.
- Native worker может оказаться старым → собрать sibling перед прогоном.

## Migration Plan

Формат не меняется. Обновление исходников/комплекта, без перезапуска работающего
демона или миграции пользовательских данных в ходе проверки.
