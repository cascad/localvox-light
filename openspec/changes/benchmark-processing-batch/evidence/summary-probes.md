# Прямые измерения summary · 2026-11-01

BL-003/008, PIPE-007/008/011: измерены отдельные STT/summary worker-фазы с настоящими
локальными Qwen и GLiNER. Задачи полного координатора/очереди и итогового бюджета
2.2/2.3 остаются открытыми. Это не аппаратная приёмка и не проверка качества текста.

## Условия

Текущий release worker SHA-256 не менялся:
`9ad460f6922ff9e86c69a129fbd844885840519fa5637626b880c0ad1e0699d2`.

весов из сети не выполнялось. Доступна RTX 5080, nvidia-smi сообщил 16303 MiB VRAM.
Фоновая нагрузка не контролировалась.

[Контекст Ollama](summary-model-context-2026-11-01.json) фиксирует digest Qwen,
первый пустой список resident models и последующее размещение модели на GPU.

Это snapshot размещения, не непрерывный замер пика внешнего процесса/GPU.
Нет утверждения о холодном cache ОС: profiler предварительно читает fingerprints.

Исходники и outputs — отдельные target-каталоги на D:, TEMP/TMP worker там же.
Пользовательский архив и LocalVox daemon не менялись. Настройки/кеш существующего
Ollama не сбрасывались: модель остаётся под обычной политикой его keep-alive.

## Двухчасовой синтетический диагностический вход

PCM того же публичного WAV повторён 12 раз без изменения samples: 7225.554 s,
231217772 байта WAV. Файл создан потоковой записью 160000 frames за раз через
Python wave в новом `target/summary-source-20261101/lf-dense-repeated-12.wav`.
Порядок: 12 полных копий исходного PCM, параметры WAV сохранены, заголовок пересчитан.
Это воспроизводимый нагрузочный пример с повторяющимся содержимым, не типичная встреча.

[Данные](summary-repeated-two-hours-2026-11-01.json):

- STT **80.8818 s**, наблюдаемый worker peak **529.1 MiB**.
- Summary **306.5879 s**, worker peak **1457.5 MiB**, NER загружен.
- 7 map-частей, один повтор после проверки и reduce: **9 HTTP-запросов**.
- HTTP wall **216.6602 s**; внутри него Ollama сообщил load **2.1984 s**,
  prompt **10.3495 s**, generation **203.3470 s**. Остаток worker **89.9277 s**.
- Две генерации выдали по **8192 токена** при `num_predict=8192` и заняли
  **88.1324 + 86.6764 = 174.8088 s**, около **57% всего времени summary**.
  Оба запроса относятся к части 4/7 — исходному ответу и повтору. Причина
  завершения в этой версии collector не сохранялась; ретроспективно length не
  подставляется. Полные тела ответов в отчёт не записывались.
- По операциям журнала проверки имён/чисел заняли **87.4699 s**, загрузка NER —
  **1.0430 s**. Это границы операций, не независимое измерение только NER-кернелов.
  Вложенные durations не суммируются со временем worker.
- Все фазы завершились успешно в исходном лимите **360 s на фазу**, STT и summary
  имеют ready receipts. Summary оставлена **с сомнениями содержания**, человеческого
  подтверждения нет. Batch 387.5362 s, preflight 3.3047 s, total 390.8439 s.

Во время выполнения действительно прочитан промежуточный checkpoint: global и
case complete=false, принятый STT с 80.8818 s уже сохранён, summary ещё running.
Данные первого этапа не ждут окончания второй фазы.

Результат выявляет два кандидата следующего эксперимента: стоимость очень длинного
ответа/повтора и проверок большого текста. Он не устанавливает причину прежней
часовой обработки конкретной встречи. Нельзя просто уменьшить token cap и объявить
ускорение: требуется сравнить полноту/завершённость summary на разных материалах.
Такой эксперимент ещё не выполнен, production лимиты/промпты не менялись.
