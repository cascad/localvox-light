# Плеер при фоновых обновлениях · 2026-11-01

Продолжение проверки UI и очистки проекта по поручению владельца. Пользовательский
архив, .env, работающий демон и устройства не изменялись. TEMP/TMP тестовых процессов
направлены в `D:\rust_repo\localvox-light\target\test-temp`, без глобальных настроек.

## Воспроизведение отказа

Новый browser-тест `archive metadata refresh preserves the paused audio position
without reloading` выполнен на старом Player: после изменения duration 120 → 180
и штатного обновления sessions получен FAIL, `currentTime: 0, reloads: 1` вместо
`currentTime: 20, reloads: 0`, paused осталось true. Локальный лог:
`target/player-refresh-red.log`. Это реальный HTMLAudioElement и декодирование
синтетического PCM через перехваченный HTTP Range, не измерение скорости STT.

## Реализация ARCH-009 и сохранение ARCH-002

- [Player](../../../../ui/src/Player.tsx) определяет источник именем, наличием аудио
  и токеном. Обновление положительного total меняет шкалу без `load()` и сброса
  позиции/stopAt. Source cleanup останавливает старый audio, удаляет src и освобождает
  медиа при смене записи, исчезновении аудио, уходе из архива и unmount.
- При новом источнике сбрасываются локальная и опубликованная родителю позиция,
  playing, note и выделение. Ref callback исключает перезагрузку из-за новой ссылки
  onPos. Старый nonce не обнуляется и не переигрывается.
- Peaks используют существующий [useArtifact](../../../../ui/src/useArtifact.ts):
  ключ записи/доступности, total как refresh; чтения последовательны и coalesced,
  поздний ответ ограждён ключом, ненужный fetch отменяется. Последняя успешная форма
  остаётся и при ошибке обновления. В [api](../../../../ui/src/api.ts) добавлен
  необязательный signal, прежний timeout 120 секунд сохранён.

В [browser e2e](../../../../ui/tests/e2e/workspace.spec.ts) выполнены семь новых
сценариев: пауза/20 секунд без reload; playing и until после обновления; смена
сессии; уход/возврат; исчезновение/появление аудио; coalescing и отмена старой
волны; сохранение волны при 503 и последующее восстановление. Три lifecycle
сценария начинаются с реального звучащего фрагмента; после смены источник на
паузе с нуля, старое выделение снято. Для удаления DOM также проверен захваченный
старый элемент: paused=true, src=null.

Slow-wave тест удерживает GET при длительностях 180/210/240: один активный запрос,
старая форма остаётся. После release выполняется ровно одно последующее чтение.
При следующем pending GET выбор другой записи вызывает abort signal; поздний
release не меняет новую форму. В error-тесте начало второго последовательного
чтения подтверждает обработку первого 503 до проверки сохранённой формы.

Целевой прогон: **7 passed**. Существующий native browser audio сценарий повторно
прошёл вместе с новым paused-тестом: **2 passed**. Проверены обычные pause/seek,
границы клавиатурного seek и повтор одной реплики; второй запуск не является
дополнительными уникальными тестами.

## Границы

Отмена fetch наблюдается на стороне клиента, она не доказывает остановку серверной
работы. Синтетический WAV не подтверждает seek реального длинного FLAC, физический
звук или подгрузку новых байтов растущей записи. Модели и микрофон не запускались;
аппаратная приёмка общего журнала (10.2) остаётся not-run. Main specs не
синхронизируются, changes не архивируются. Коммиты выполняет пользователь.
