# Design

## Context

В `Player` эффекты аудио и peaks зависят от `[name, total]`. Периодическое чтение sessions меняет total даже при неизменном URL: `load()` сбрасывает currentTime и stopAt. Peaks очищаются перед каждым запросом, отмены и ограничения параллелизма нет. ARCH-002 требует один плеер и корректную границу реплики; новая delta уточняет непрерывность при фоновых обновлениях.

## Goals / Non-Goals

Сохранить текущий визуал и управление, отделить идентичность аудио от метаданных, ограничить фоновую нагрузку waveform и доказать жизненный цикл браузерными тестами. Не менять TUI, серверный формат, скорость воспроизведения и механизм получения новых байтов растущего WAV. Не запускать модели или пользовательский архив.

## Decisions

- Источник определяется именем, наличием аудио (положительная длительность) и текущим токеном. Изменение самого положительного total не меняет источник и не вызывает `load()`.
- Эффект источника сбрасывает локальную и опубликованную родителю позицию только при смене источника. Cleanup останавливает и освобождает захваченный audio-элемент также при удалении его из DOM. Обработчик позиции хранится в ref: новая callback-ссылка не является новым медиаисточником.
- Peaks используют существующий `useArtifact`: ключ записи/доступности, total как сигнал обновления. Он уже обеспечивает последовательность, coalescing, fencing и abort. API peaks получает необязательный AbortSignal, сохраняя таймаут 120 секунд. Последняя успешная волна сохраняется и при ошибке.
- Nonce перехода не сбрасывается вместе с источником: старый запрос нельзя переигрывать при возвращении в архив. Новый явный запрос исполняется прежним способом.

Зависимость только от имени не учитывала бы исчезновение/появление аудио и смену токена. Отдельный новый механизм чтения peaks дублировал бы уже проверенные отмену и coalescing в useArtifact; поэтому используется общий hook.

## Risks / Trade-offs

- HTMLAudioElement живёт по собственным медиа-событиям. Проверки используют реальный decoder и синтетический PCM с HTTP Range, широкие временные границы вместо ожидания точных секунд при воспроизведении.
- Отмена fetch не доказывает остановку обработки на сервере. Длительность шкалы может обновиться без перечитывания уже загруженных WAV-байтов; потоковое наращивание медиа не обещается.
- Ошибка первоначальной waveform даёт прежний плоский placeholder, ошибка обновления сохраняет последнюю успешную волну. Нового UI ошибки в этом срезе нет.

## Validation

Сначала воспроизвести сброс паузы/позиции тестом на старом коде. Проверить playing/fragment, смену записи, уход/возврат и исчезновение/появление аудио, последовательные/отменённые peaks и восстановление после ошибки. Затем unit/build/lint, полный browser e2e без изменения PNG, общий временный API/UI/TUI, строгие OpenSpec/check-openspec/diff. TEMP/TMP только текущих тестовых процессов направить в target на D:.

## Migration Plan

Форматы данных не меняются. Достаточно собрать UI обычной командой; откат исходников и пересборка возвращают прежний клиент без миграции архива.
