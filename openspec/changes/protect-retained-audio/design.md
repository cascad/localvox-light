# Безопасная очистка аудио

## Context

См. [proposal](proposal.md), DEC-001/RV-004. `sweep_audio_retention` вызывается
при запуске engine; прежний recursive mtime-проход не проверяет очередь или STT.

## Goals / Non-Goals

Очистка — явно включаемая политика экономии места после подтверждённого STT.
Она не должна конкурировать с записью, recook или удалять последний исходник
неудачной обработки. Ручное удаление и проверка конвертации FLAC — отдельные пути.

## Decisions

- CLI default days=0; пример настройки также 0. Явное положительное значение
  сохраняется, но подчиняется новым условиям. Файлы пользовательских настроек не переписывать.
- Обходить непосредственные `sessions/<name>/audio`, не произвольное дерево.
  Для каждой сессии брать queue mutex, проверять очередь и неблокирующий execution lock.
  Этот порядок соответствует координатору; удерживать владение до окончания удаления.
- Пропускать запись с live marker, .part, Pending/Running, недоступной очередью
  или без валидного transcript receipt. Legacy без самого подтверждения не очищать;
  legacy receipt без хеша допускает только текущую структурную проверку.
- Возраст файла и расширения WAV/FLAC сохраняются. Проверка STT один раз на сессию,
  не для каждого чанка. Ошибка удаления сохраняет оставшиеся данные и диагностируется.

## Risks / Trade-offs

- Старые записи без receipt занимают место дольше → это сохранение источника,
  а не основание считать отсутствие подтверждения успехом.
- Проверка файла под mutex добавляет короткую задержку при старте → не запускать
  модель, сеть или декодирование в этом проходе; проверяется текст/манифест.

## Verification

Временные файлы с заданным mtime: default/off, свежие, старые после STT,
отсутствующий/повреждённый STT, Pending, Running/lock, part, повреждённая очередь.
Проверить, что текст/summary/meta не удаляются.
