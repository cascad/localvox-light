# Design

## Context

См. proposal. Журнал ограничен курсорными страницами; начало/родитель может отсутствовать.
`run` отделяет историю, `operation`/`parent` связывают процесс с вложенными операциями.
Последняя StageStatus доказывает результат, operation_end доказывает только окончание работы.

## Goals / Non-Goals

Одна понятная семантика дерева в двух клиентах; чистая проекция ограниченного кеша,
устойчивые ID, точные первичные события и прежние ограничения памяти/чтения.
Модели, scheduler, форматы результатов и аппаратные устройства не меняются.

## Decisions

- Необязательные структурированные scope/role в событиях: recording/final/import
  и worker. Контекст ставит координатор при запуске и сохраняет для дочернего процесса;
  при повреждённых/недоступных метаданных ставится unknown. Старые события не мигрируют
  и не классифицируются по названиям.
- Проекция строит контекст → этап → операции с ограниченной глубиной. Отсутствующие
  родители и циклы не теряют события. Каждая попытка остаётся отдельной операцией;
  служебная обёртка worker и её команда входят в подробности этапа.
- Транспортные фазы prepare/text не становятся дополнительными этапами: их обёртки
  находятся в «Логи запуска» контекста, реальные download/extract остаются этапами.
  Старый структурированный command.program позволяет узнать обёртку, но не контекст.
- Контексты/этапы имеют стабильные ID. Развёрнутость, выбранный ID и scroll anchor
  не зависят от номера строки. Фильтр сохраняет предков и не переписывает свёрнутость.
- Общие часы остаются отдельными от таймеров веток. В stage union добавляются
  известные интервалы структурированных фоновых worker операций из ограниченного
  чтения; при неполной истории не выдаётся точный баланс ожидания.
- «Измерено» в заголовке ветки — union известных worker-интервалов загруженного окна,
  рядом отдельно указан диапазон событий. Полный баланс приходит от workflow;
  остаток называется «вне измеренных этапов», а не автоматически ожиданием.
- Основной экран использует понятные названия/состояния, технические команды и run ID
  доступны через подробности и копирование. Пустые необязательные очистители компактны.

## Risks / Trade-offs

- Старые записи не содержат scope → честный заголовок «Проход», без выдуманных стадий записи.
- Ограниченная страница скрыла родителя → видимая ветка с пометкой неполного контекста;
  последующая страница связывает её по ID.
- Различные Rust/TS клиенты → одинаковые сценарии fixtures и проверки дерева/часов;
  snapshot и browser/native PTY дополняют проверки поведения.

## Migration Plan

Поля JSON необязательны, старые читатели их игнорируют. Никаких изменений личного
архива; проверка на временных fixtures. Новый локальный комплект после проверок,
Mac/Linux аппаратные сценарии остаются not-run.
