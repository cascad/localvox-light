# Группировка длинной записи · 2026-11-10

## Наблюдение и граница вывода

Read-only просмотр текущего задания: 18 240 / 18 240 секунд входа достигнуты через
7 мин 18 с после запуска worker; затем общий `transcribe` продолжался больше часа.
В очереди сохранился предыдущий timeout 7200 с. Это не профиль стека процесса и не
доказательство точного времени одного GigaAM. Исходный код подтвердил кубический
пересчёт cosine по исходным векторам на каждом слиянии. Работающий процесс и архив
ради проверки не останавливались/не переобрабатывались.

## Изменение

- Condensed cosine matrix, f64 accumulation и kodama 0.3.0 Average/NNC вместо
  O(n³·d). Нормы вычисляются один раз, исходная пара — один раз; дальше O(n²).
- Порог и cap сохранены; итоговые метки следуют первому фрагменту. Равные расстояния
  могут давать другой детерминированный порядок; bitwise parity старых f32 не обещается.
- Checked arithmetic, лимит матрицы 256 MiB, fallible allocation, проверка finite и
  размерностей. Ошибка возвращается вызывающему коду; текст остаётся без недостоверных голосов.
- Отдельные последовательные операции прохода дорожки, группировки и объединения
  дорожек. Ошибка операции имеет `failed` и не теряется по лимиту verbose-логов.
  `parent` связывает подоперацию с текущим worker; UI/TUI проверяют run, attempt и
  текущую фазу, не оживляя старую операцию после повтора. Внешний конкурирующий
  heartbeat полного cook убран.

различных голосов. [Машинные результаты](cluster-profile.json).

алгоритма, **не** обещание времени полного STT/diarization и не оценка качества модели.

  420 passed, 7 ignored. В параллельном общем запуске старый тест pre-roll имел

  тестовыми потоками прошёл. Этот тест/производственный pre-roll не менялись.
- 480 сравнений с исходным алгоритмом на 24 входах × 4 порогах × 5 caps; тесты
  2048 фрагментов, границ порога, ties, нулевых/невалидных векторов, overflow и бюджета.

  полного счётчика PCM от готовности этапа и сохранение исходных строк без назначения

  Production build прошёл.

- Настоящий HTTP + общий UI/TUI сценарий: `cargo test --locked -p localvox-light-api --lib --jobs 2 -- --ignored --exact http::tests::cross_clients::shared_workspace --nocapture` — 1 passed.

## Native smoke нового worker

[Результат и fingerprints](native-smoke.json): первые 180 s уже имеющегося публичного
benchmark PCM, отдельная временная сессия на D, настоящий GigaAM int8 и обе ONNX-модели
диаризации. Cook — 7.6 s, 18 непустых строк, 15 с голосовой меткой, `transcribe=done`.
Отдельные start/end и измеренная длительность прохода дорожки, группировки и объединения
присутствуют в журнале; LLM не запускалась. Время операции в JSON включает journal I/O и
завершение heartbeat и поэтому отличается от внутренних tracing timings.

Release worker скомпилирован и связан, кандидат `target/review/diarization/localvox-process.exe`
прошёл CLI `--help` и native smoke. Установка Cargo в обычный `target/release/localvox-process.exe`
не удалась из-за блокировки исполняемого файла текущим пользовательским worker. Это
ошибка установки, а не успешная полная команда `cargo build`; работающий процесс не заменён.

Приложение с новым embedded UI также скомпилировано/связано, но установка в исполняемый
`localvox-light.exe` заблокирована Windows. Отдельный кандидат прошёл `--help`.
`cargo build --locked --release -p localvox-light-terminal --bin localvox-tui --jobs 2`
прошёл полностью, TUI установлен в target/release и прошёл `--version`.
[Fingerprints трёх кандидатов](release-candidates.json). Установка daemon/worker
ждёт ответа владельца о прерывании текущей попытки.

Строгая валидация change и main specs прошла (15/0); `check-openspec.py` —
88 требований / 188 сценариев / 88 строк покрытия. Main specs не sync/archive.
