# Установка после остановки владельцем · 2026-11-10

Это продолжение [исходных проверок](implementation.md), а не переписывание результатов до установки.

Владелец сообщил «тормознул старый». Перед копированием проверено отсутствие daemon,
worker и TUI. Три кандидата сверены с [fingerprints](release-candidates.json), установлены
в `target/release`, контрольные суммы установленных файлов совпали. Предыдущие файлы
сохранены в `target/review/diarization/previous` (ignored, диск D).

Демон запущен скрытым процессом с `--daemon --audio-dir <прежний рабочий каталог>`
из корня репозитория. Авторизованный health вернул `ok`; запись звука выключена.
Ни конфигурация устройств, ни секретные значения `.env` не менялись.

У старой Failed-задачи оставались `refine=true`, `cleanup=true`, `follow_settings=false`.
В сессии не было ни одной версии расшифровки, processed или summary. По ранее принятому
пользователем сценарию «распознавание + optional summary» выполнен штатный
`POST /api/sessions/<session>/recook?scope=all`: удалено 0 производных файлов,
аудио не удалялось. Новая задача — `summary=true`, `cleanup=false`, `refine=false`,
`follow_settings=true`, отдельная попытка Transcribe. Путь нового worker и его
установленный fingerprint проверены до запуска.

## Найденный отдельный gap наблюдаемости

RV-021 / PIPE-011: при recook уже имеющегося YouTube-аудио этап Transcribe реально
работает, но API добавляет прошлые `download` и `extract` в `execution.next`, отображая
их blocked. Воспроизведено настоящим HTTP без искусственных progress events.
Выполнение распознавания этим не остановлено. Исправление этой проекции — отдельный
срез; завершение текущей оптимизации не объявляет этот gap закрытым.
