# Отключить узнавание участников между записями

План готов; новые имена/recook реализованы и проверены, историческая миграция
пользовательского архива ещё открыта. [Evidence](../../evidence/implementation-review-2026-09-27.md).
Основание: [BL-019](../../backlog.md#bl-019).

## Why

В видео Фила Ранжина пользователь увидел чужое имя «Арсен Маркарян». Владелец потребовал отказаться от автоматического узнавания людей между разговорами.

## What Changes

- **BREAKING**: убрать перенос имён по общим голосовым профилям, включая старые профили и повторную обработку.
- Сохранить диаризацию и ручные имена в пределах одной записи; ручное именование не обучает общий профиль.
- Предусмотреть явное исправление старых неверных подписей и производных без массового удаления корректных ручных имён.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `speakers`: SPK-002/003: локальные имена вместо автоматической межсессионной идентификации.

## Impact

Core diarize/cook, Archive::name_speaker, профили/roster, версии и сводки; совместимость API профилей и миграция старых подписей требуют разбора.

## Исходные сведения BL-019

Перенесено из прежнего бэклога. Пункты ниже сохраняют исходные намерения и критерии;
это ещё не согласованный `tasks.md`.

**Отключить автоматическое узнавание участников между разными разговорами и видео.**
Тип: изменение поведения / ошибочная атрибуция; состояние: `open`; приоритет: высокий.
Направление задано владельцем 2026-09-27; реализация и проверка ещё не выполнены.
Связь: F11, SPK-002/003, [RV-015](../../review.md).

Пример пользователя: в видео «Почему я бросил IT. Проблемы IT, о которых молчат
на митапах – Фил Ранжин», пометка «добавлено 11:29», участник подписан
**«Арсен Маркарян»**, хотя, по сообщению пользователя, говорит другой человек.
Это зарегистрированный пример ошибочной подписи; конкретные артефакты записи
при добавлении задачи не исследовались, источник именно этой подписи ещё надо подтвердить.

Сверено по коду: [speakers_for_lines](../../../crates/localvox-light-core/src/cook.rs)
загружает общие профили `<work_dir>/speakers.json` и передаёт их в
[diarize::names](../../../crates/localvox-light-core/src/diarize/mod.rs), где вызывается
[Profiles::recognise](../../../crates/localvox-light-core/src/diarize/profiles.rs).
[Archive::name_speaker](../../../crates/localvox-light-api/src/archive.rs) при ручном
именовании сохраняет общий профиль через enroll. Это существующее поведение,
которое требуется изменить, а не желаемая гарантия SPK-003.

Требуемое поведение:

- Диаризация и сопоставление реплик остаются в границах одной записи. Участники
  разных сессий не связываются автоматически, даже при высоком сходстве голоса
  или наличии старого именованного профиля. Это отключение функции, не подбор порога.
- Без имени, явно заданного для этой записи, используются локальные обозначения
  участников. Ручное именование действует только в выбранной сессии и не создаёт
  либо обновляет профиль для узнавания человека в других разговорах.
- Новая и повторная обработка не применяют общие голосовые профили. Имена из них
  не должны попадать через speaker-подписи в транскрипт, UI, сводку или экспорт.
  Это не запрет упоминать имена, реально произнесённые в содержании разговора.
- Уже сохранённые неверные подписи требуют отдельного исправления вместе с
  производными. Отключение будущего узнавания само по себе старые результаты не чинит.
  Нельзя массово стирать корректные ручные имена или заменять все совпадения имени
  в архиве: текущий roster не хранит происхождение подписи (ручное/автоматическое).

Задачи:

- Подтвердить происхождение неверного имени в указанном видео и проверить все
  пути автоматического применения/сохранения межсессионных профилей.
- Убрать межсессионное узнавание и побочный enroll при локальном именовании;
  сохранить разделение говорящих и ручные имена внутри одной записи.
- Определить и реализовать явное исправление уже ошибочных подписей и связанных
  сводок/версий без потери текста и корректных ручных имён; отдельно проверить пример пользователя.
- Проверить независимые сессии с одинаковыми/похожими голосовыми векторами,
  заранее существующим именованным профилем, ручным именованием и повторной обработкой.
  Имя из сессии A не переносится в B; именование B не меняет A или общий профиль.
  Записать результаты и обновить SPK-002/003 по фактически изменённому коду.

Готово, когда перенос имён между сессиями исключён в проверенных путях обработки,
локальная диаризация и именование работают, а зарегистрированный пример исправлен
проверяемым способом. Сейчас изменена только документация, архив и код не исправлялись.
