# Локальные имена говорящих

## Context

См. [proposal](proposal.md). В `cook::speakers_for_lines` читаются общие profiles,
`names` применяет recognise, `Archive::name_speaker` вызывает enroll.
В выбранной записи `20260927_112917_youtube` сохранена подпись «Арсен Маркарян»;
исторический roster не позволяет отличить автоматическое имя от ручного.

## Goals / Non-Goals

Исключить применение/обучение общих профилей при новой обработке и именовании.
Сохранить диаризацию, локальное ручное имя и возможность явного исправления записи.
Не определять личность по названию видео, не заменять произнесённые имена в тексте,
не очищать весь архив по совпадению строки имени.

## Decisions

- `names` получает только участников и язык, без объекта общих profiles. Для
  импортированного источника участник не считается владельцем микрофона («Я»).
- Roster хранит признак ручного имени; отсутствие поля означает неизвестное
  историческое происхождение, не ручное подтверждение. Ручное именование не enroll.
- При recook читать прежний roster только этой сессии. Переносить подтверждённое
  ручное имя при взаимно однозначном локальном совпадении векторов (cosine >=0.90,
  ровно один кандидат в обе стороны). При неоднозначности оставить локальные номера.
  Изменение размерности модели исключает сопоставление. Общие profiles не участвуют.
- Старые profiles остаются доступны для просмотра/удаления через прежний API как
  legacy-данные. Их присутствие не возвращает узнавание. Существующие корректные
  подписи не переписываются при запуске приложения.
- Для явно выбранной неверной подписи использовать локальное переименование и
  перегенерацию сводки; исходный текст сохраняется. Конкуренция мутаций — BL-002.

## Risks / Trade-offs

- Локальное сопоставление тоже вероятностно → строгая однозначность, отказ при
  смене размерности; тесты совпадения и двусмысленности, без обещания идеальной идентификации.
- У legacy нет provenance → не переносить автоматически непроверенные старые имена
  при новом STT; сохранять прежние версии и не применять массовую миграцию.
- Работающий release ещё содержит старую логику → проверки на копии записи;
  исходный пользовательский архив не считать исправленным до отдельного подтверждённого шага.

## Verification

Уточнение реализации: переименование сохраняет локальный label, затем удаляет
устаревшую сводку и ставит Summary без Prepare/STT/refine. Ошибка очереди после
локального сохранения возвращается как частичный отказ с явным текстом; нельзя
показывать старую сводку как учитывающую новое имя. Это не multi-file transaction.
Все JSONL предварительно читаются строго перед relabel; битая версия останавливает
операцию до изменения любого transcript. Файлы публикуются atomic_write по одному.

Общий именованный профиль не меняет labels новой записи; имя в A не влияет на B;
переименование короткой реплики не требует enrollment; ручной origin сохраняется;
recook переносит только однозначное локальное имя. Проверить копию пользовательского
примера и изменения только speaker-полей, не произнесённых слов.
