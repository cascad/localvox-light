# Proposal

## Why

Владелец принял b3766b6 как рабочую точку и поручил законченный модульный рефакторинг.
Выбор модели, inference runtime, источник ввода и клиентский интерфейс должны
изменяться через явные границы с сохранением поведения и надёжности.

## What Changes

- Зафиксировать владельцев пользовательских сценариев и действующие порты/адаптеры.
- Собрать предпочтения TUI, отделить ввод/ответы/представление; разделить React views
  и API операции по фичам с сохранением HTTP/CLI и визуальных результатов.
- Изолировать сборку ASR backend и LLM transport от сценариев обработки; использовать
  реальные существующие реализации и model identity, без фиктивных future providers.
- Разделить управление очередью, исполнение worker и приёмку; свести общие операции
  импорта/настроек в пределах существующих гарантий и совместимости.
- Убрать подтверждённые дублирования; сохранить чтение старых артефактов/очереди,
  cancellation/deadlines/ownership, алгоритмы/параметры моделей и все US-сценарии.
- Проверенные этапы коммитить отдельно; завершить общими регрессиями и сборкой.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет: внутренний рефакторинг, `skip_specs: true`. Действующие ARCH/PIPE/CFG/STORE
контракты сохраняются. Намеренные изменения поведения оформляются отдельно.
BL-006 и аппаратные/default gates не закрываются одним переносом кода.

## Impact

TUI, React document views, archive API, coordinator/worker, ASR construction,
LLM transports и внутренние настройки. UI/HTTP/CLI actions, disk formats, model
recipes, default раннего режима и пользовательские данные сохраняются.
