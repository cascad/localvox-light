# Design

## Context

См. proposal и native evidence RV-018/RV-019. Оба этапа используют общий overlap
guard; отдельные names/numbers guards не защищают обычные смысловые слова.
Глоссарий детерминирован и применяется до обращения к модели.

## Goals / Non-Goals

Закрыть воспроизведённые потери слов/цитат, смену повеления прошедшим временем и
смешивание строк, сохранив измеряемые полезные правки. Не обещать универсальную
семантическую верификацию, не подключать SAGE/новую модель/summary и не менять архив.

## Decisions

- Отдельный pure correction guard, общий для cleanup/refine. До принятия правки
  проверять цитаты/технические литералы/числа/значимые оговорки и ограниченное
  соответствие слов в порядке источника. Необоснованные вставки/удаления отклонять.
- Ограниченные близкие орфографические замены, разделение/соединение разорванных
  слов и локальные ASR-повреждения разрешаются, но не произвольная переформулировка.
  Явные опасные переходы наклонения/времени блокируются отдельно: edit distance
  сам по себе не отличает «сохрани» от «сохранил».
- Удаляемые паузы/заикания ограничены. «Короче» сравнительное и «как быструю»
  не являются подстроками-заполнителями; цитируемые паузы — данные, не мусор.
  Оговорки и смыслообразующая пунктуация рядом с ними сохраняются.
- Ограничить объём работы валидатора; большие/неоднозначные поправки сохраняют
  источник. Нужен быстрый путь для неизменённых слов/пунктуации, без LLM/NER вызовов.
  Обычный лог сохраняет сводные omitted/rejected, подробные причины/время строки
  доступны на debug без повторного вывода всего исходника и ответа на каждую строку.
- Проверять модель относительно текста после глоссария, который ей действительно
  подавали. Отдельные grounding guards сохраняются. Duplicate IDs не выбираются
  по правилу last-wins: неоднозначная строка остаётся исходной.
- Регрессии сначала должны воспроизвести дефект. Далее pure tests, настоящий
  worker + fake provider для refine/cleanup и native повтор прежнего corpus/границ.
  Отдельно проверить ранее сохранённые опасные предложения, не выдавать replay за
  свежие вызовы модели. Измерить отказ от полезных правок и стоимость guard.

## Risks / Trade-offs

- Консервативная защита отклонит часть хороших реконструкций → измерить usefulness,
  сохранить source fallback и примеры, не ослаблять требования ради красивого счёта.
- Смысл может меняться без простого нарушения токенов/знаков → не объявлять guard
  доказательством всего смысла; открытые пределы и аудиоприёмку отмечать явно.
- Лексикализация/глоссарий меняют слова законно → сравнивать фактический вход модели,
  закрепить glossary regression и неизменность первичной версии.

## Migration Plan

Исправляется admission обычных этапов, без изменения recipe/defaults или массового
перепроцессинга. Старые результаты автоматически не переписываются. Проверенный
исходник остаётся доступным, новый запуск получает усиленную защиту.
