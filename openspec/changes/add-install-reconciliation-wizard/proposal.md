# Proposal

## Why

Владелец попросил повторяемый doctor/reconciliation для установки: выбирать
Ollama, модели или существующие пути и не выполнять готовую работу повторно.
Формат подтверждён: мастер в терминале. Сейчас doctor знает runtime paths,
а загрузчики проверяют только свой models/ и не настраивают Ollama.

## What Changes

- Общая read-only диагностика, пригодная для человека и scripts; существующий
  doctor сохраняется и получает структурированный вывод.
- Терминальный мастер: обнаружение → выбор → план → подтверждение → только
  недостающие действия → повторная проверка. Отмена до подтверждения ничего не меняет.
- ASR: использовать обнаруженную модель/указать готовую папку либо скачать
  выбранный компонент в выбранный каталог; optional модели выбираются отдельно.
- LLM: существующая Ollama и её модели, скачивание отсутствующей, импорт GGUF
  с явным именем либо свой сервер. Ollama остаётся необязательной для STT.
- Установка Ollama через официальный установщик с понятным возвратом в мастер;
  существующая установка/сервер не переустанавливаются и не перенастраиваются.
- Установщики получают check/wizard/reconcile; повторный reconcile не скачивает
  и не распаковывает исправный bundle, не pull-ит уже установленный tag.

## Capabilities

### New Capabilities

Нет новой capability: используется installation-models.

### Modified Capabilities

- `installation-models`: SETUP-005 read-only report и SETUP-006 повторяемый мастер;
  существующие SETUP-001/002/003 и соседняя delta SETUP-004 не ослабляются.

## Impact

doctor/CLI, отдельные setup planner/prompt/probe/execution modules, установщики и
загрузчики моделей, package helper list, CI fixtures, README/user-guide.
На машине разработчика не устанавливать/перезапускать Ollama и не скачивать
модели ради проверки. Windows/Mac first-run installer acceptance — отдельно not-run.
Наблюдение: здесь Ollama уже работает, qwen3.5:9b и bge-m3 присутствуют.
