# Design

## Context

См. proposal.md. Theme уже задаёт bg/ink/dim/command/argument/value и статусы,
но часть технических заголовков наследует border style либо ink, а поля/настройки
используют несогласованные dim/ink стили.

## Goals / Non-Goals

**Goals:** одна роль caption и общие стили heading/label на существующем renderer;
ясная разница chrome/data с сохранением ровной геометрии.

**Non-Goals:** смена структуры экранов, переписывание app/domain state, новый парсер
пользовательского текста, настройка каждого цвета, изменение UI браузера/плеера.

## Decisions

- Добавить Theme.label с приглушённым синим акцентом для RGB dark/light, Cyan для
  16-color и Reset для no-color. Heading использует Bold, обычная подпись в
  no-color — Dim; значения остаются ink/value, пояснения dim.
- Назначать роль там, где renderer знает тип подписи: panel titles, nav/tabs,
  labels формы, заголовки разделов настройки/журнала и metadata header. Не угадывать
  тип строки по двоеточию/регулярному выражению и не окрашивать пользовательские
  строки как команды. Название самой записи в заголовке документа остаётся данными.
- Сохранить существующие состояния ошибок/selection/focus, аргументы и timestamps.
  Style snapshots должны менять только styles, без новых строк/колонок.

## Risks / Trade-offs

- Недостаточный контраст → вычисляемые RGB contrast tests для bg/selection,
  style assertions dark/light/16/mono и просмотр всех изменённых baselines.
- Унаследованный border/selection стиль перекроет подпись → проверки готового Buffer,
  включая выбранную настройку/редактор и заголовки с активным/неактивным фокусом.
- No-color не различает оттенки → Reset fg/bg и типографика/маркеры, прежняя геометрия.

## Migration Plan

Только пересборка TUI; daemon/worker и архив не меняются. Обновить обычный бинарник,
если свободен; работающий клиент не завершать, при блокировке дать отдельную сборку.
Ручной просмотр настоящего терминала остаётся отдельной приёмкой.
