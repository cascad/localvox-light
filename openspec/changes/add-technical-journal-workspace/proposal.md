# Proposal

## Why

Нужны два представления одного приложения в эстетике живого технического журнала: графический UI и новый терминальный клиент с теми же пользовательскими сценариями. Нынешний TUI управляет capture-engine внутри собственного процесса и показывает live-транскрипт/диагностику; он не является терминальным аналогом React-приложения и служит только справочным материалом.

## What Changes

- Создать новый `localvox-tui` как отдельный клиент HTTP API демона: архив, документы, участники, очередь, заметки, «Спросить», поиск/чат, запись, плеер и настройки. Полная карта действий — в `parity.md`.
- Оформить UI и новый TUI одним визуальным языком: дерево операций с ветками, цветные команды/аргументы, приглушённые подробности, раскрытие `+ N lines`, компактные состояния и фактическое время. Документы остаются читаемыми документами внутри рабочего пространства.
- Добавить ограниченный API журнала с курсором, идентификаторами запусков/операций и безопасными структурированными событиями; состояние результата по-прежнему определяется очередью и проверенными артефактами.
- **BREAKING**: заменить пользовательский режим `localvox-light --tui` новым клиентом; интерактивный запуск больше не создаёт отдельный capture-engine. Закрытие TUI оставляет демон и запись работающими. Миграция включается после проверки паритета, а не при первом каркасе.
- Заложить проверки одновременно с реализацией: переходы состояния, API-контракты, снимки терминального экрана и его стилей, браузерные visual/e2e, отдельный сквозной прогон с настоящим временным HTTP-сервером.

## Capabilities

### New Capabilities

- `technical-journal`: общая семантика журнала, события, сворачивание, безопасное отображение, состояния связи и визуальные проверки UI/TUI.
- `terminal-workspace`: самостоятельный терминальный аналог графического приложения, навигация/формы, функциональный паритет и управление воспроизведением.

### Modified Capabilities

- `runtime-settings`: отдельный жизненный цикл нового TUI, миграция старого запуска и состав поставки (`RUN-004`, `RUN-002`).

## Impact

Точки интеграции: `ui/src/{App,Progress,Queue,RecordBar,DocumentPane,Settings,Notes,Ask,Player}.tsx`, `ui/src/api.ts`, `ui/src/styles.css`; `core/progress.rs`, `core/workflow.rs`; `api/{http,archive}.rs`; запуск в `localvox-light/src/main.rs`, CLI, workspace, сборочные/установочные скрипты и CI. Новый терминальный код размещается отдельно от старого `localvox-light-tui`; его реализация не переносится.

Существующие PIPE/REC/VER/ARCH/NOTE/ASK/CFG/API-контракты и DEC-001–008 сохраняются. Численное ускорение обработки, постоянный STT-worker и массовая чистка кода не входят в этот change: измерения ведутся через BL-003/008, ручной импорт — BL-006. RV-001/008/009/010 и BL-002/004/021 остаются отдельными известными пробелами; новый клиент не должен закреплять их как допустимое поведение или скрывать их.

Статус: **implementation in progress**, по поручению владельца начать реализацию. Delta остаётся в change; выполнение отслеживается в tasks/evidence. Наличие документов не означает готовность приложения.
