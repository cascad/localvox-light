# Runtime and settings Spec Delta

## MODIFIED Requirements

### Requirement: RUN-002 Комплект бинарников и UI

Демон SHALL искать localvox-process рядом со своим exe и проверять worker-протокол перед захватом очереди. Frontend берётся rust-embed из ui/dist: release содержит сборочный снимок, debug может читать каталог. Сборка только пакета демона не является сборкой workspace/worker. Windows scripts/run.ps1 собирает демон и worker одним вызовом Cargo в выбранном профиле (release по умолчанию, dev по запросу), при Desktop добавляет окно, при Tui добавляет новый localvox-tui; Desktop и Tui выбирают разные клиентские режимы, одновременный выбор отклоняется. BuildOnly не запускает приложение. Пути бинарников берутся из сообщений Cargo, cwd — корень репозитория. Release-комплект SHALL включать новый терминальный клиент; компонент воспроизведения и способ его установки SHALL быть явно проверяемы.

Код: [Config::from_env, protocol preflight](../../../../../crates/localvox-light/src/autocook.rs), [WebApp](../../../../../crates/localvox-light-api/src/http.rs), [workspace](../../../../../Cargo.toml), [запуск из исходников](../../../../../scripts/run.ps1). [Планируемые проверки](../../evidence/coverage.md).

После прежней миграции: [проверка сборки и протокола 2026-09-27](../../../../evidence/worker-startup.md). Это историческое свидетельство, не проверка нового TUI.

#### Scenario: Несовместимый worker

- **WHEN** протокол соседнего обработчика отличается
- **THEN** координатор не начинает выполнять задания им; лог содержит путь worker, ожидаемый/полученный протокол, результат запуска и команду исправления. После обновления комплекта требуется перезапуск демона; preflight автоматически не повторяется.

#### Scenario: Ошибка сборки перед запуском

- **WHEN** Cargo завершился с ошибкой при вызове scripts/run.ps1
- **THEN** скрипт завершается ошибкой, старые бинарники не запускаются.

#### Scenario: Пересборка фронта release

- **WHEN** изменён ui/dist без пересборки демона
- **THEN** уже собранный release бинарник не заменяет встроенный frontend.

#### Scenario: Сборка терминального режима

- **WHEN** scripts/run.ps1 вызван с Tui и BuildOnly
- **THEN** собирается согласованный комплект с новым localvox-tui, ни демон, ни клиент не запускаются.

## ADDED Requirements

### Requirement: RUN-004 Новый терминальный запуск

После завершения миграции `localvox-tui`, `localvox-light --tui` и прежний интерактивный выбор TUI SHALL открывать новый терминальный клиент одного демона. При недоступном локальном демоне launcher SHALL проверять доступность API LocalVox, запускать соседний демон не более одной попытки и ожидать готовность ограниченное время; подключение к явно указанному удалённому адресу SHALL не запускать локальный демон. На занятом посторонним приложением порту SHALL показываться объяснимый отказ. `--daemon` и `--no-tui` SHALL сохранять явно выбранный серверный/журнальный режим. Закрытие TUI SHALL не посылать stop/shutdown демону.

Точки миграции: [main](../../../../../crates/localvox-light/src/main.rs), [CLI](../../../../../crates/localvox-light-core/src/cli.rs), [desktop как справка](../../../../../src-tauri/src/lib.rs). [Проверки](../../evidence/coverage.md).

#### Scenario: Запущенный демон

- **WHEN** TUI открывается при доступном API LocalVox
- **THEN** клиент подключается к нему без нового capture-engine и без второго координатора.

#### Scenario: Демон не стартовал

- **WHEN** локальная попытка запуска не дала готовый API за ограниченное время
- **THEN** показывается причина и действие повтора; ожидание не бесконечно и терминал можно штатно закрыть.

#### Scenario: Посторонний порт

- **WHEN** адрес отвечает, но не является совместимым API LocalVox
- **THEN** клиент не считает TCP-доступность готовностью и не отправляет пользовательский материал постороннему сервису.
