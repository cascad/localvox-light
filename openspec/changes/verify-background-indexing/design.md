# Design

## Context

См. [proposal](proposal.md). Проверяем принятые PIPE-013, SEARCH-001/002/003:
общий coordinator запускает `localvox-process --worker-index` после опустошения
очереди, process supervisor ограничивает время и отменяет индексатор при работе.
Worker строит Tantivy и semantic; HTTP API может дополнительно обновить индекс
при запросе, поэтому одного успешного поиска недостаточно для доказательства
фонового построения. Это межпроцессный стенд с управляемыми отказами; design
фиксирует границы, чтобы не подменить этот контур модульной заглушкой.

## Goals / Non-Goals

Проверить запуск только в простое, отмену/возобновление, timeout, недоступность
embedding endpoint и дальнейший поиск. Готовность/байты исходных артефактов и
состояние завершённой обработки не должны меняться от ошибки индексации.
Не менять политику индексации, модели, пользовательский архив, работающий демон
или аппаратные статусы. Качество embedding-модели и полнота retrieval реальной
речи не доказываются синтетическими векторами.

## Decisions

- Native integration tests находятся рядом с autocook, используют тот же private
  coordinator/warm_indexes и настоящий sibling worker. Отдельный subprocess
  тестового binary изолирует process-global env API от остальных Rust-тестов.
  Mock supervisor/копия алгоритма не заменяют этот прогон.
- Временный архив на тестовом TEMP содержит синтетические meta/версии/receipts и
  текст сводки. HTTP `/api/embed` на loopback возвращает фиксированные векторы,
  умеет удерживать запрос, отдавать 503; отдельный случай использует закрытый порт.
  Настоящие Ollama/ASR/NER/звуковые устройства не запускаются.
- Фактические индекс-файлы проверяются до вызова search API: запрос API не должен
  незаметно построить то, что приписали background worker. Затем проверяются
  lexical/semantic/hybrid, session/kind/timecode и изменение best-версии.
- Pending-задание под execution lock доказывает отсутствие старта при занятой
  очереди; HTTP gate доказывает, что индексатор действительно исполнялся при
  отмене/timeout. Проверяется конечное время supervisor, затем возобновление.
- Сравниваются байты исходных файлов, processing::inspect и очередь до/после
  отказов. Повторный idle не должен создавать горячий цикл запуска worker.

## Risks / Trade-offs

- Случайное использование реальных endpoint/данных → cwd/env дочерних процессов
  заданы явно; TEMP архив, loopback, тестовые имена, отсутствие пользовательского .env.
- Зависание теста на удержанном HTTP → finite deadlines, stop guards, supervisor
  timeout, bounded subprocess. Утечки потомков покрываются настоящим process owner.
- Нестабильные проверки по sleep → ожидание входа HTTP и файлов по deadline;
  короткое окно без запроса используется только для отрицательной проверки.
- Native worker не собран → явная ошибка с командой сборки, native tests помечены
  ignored по умолчанию и запускаются отдельно. Обычный unit pass не считается BL-005.
- Найденное расхождение → отдельный воспроизводимый gap/change; skip_specs этого
  стенда не разрешает менять производственное поведение без соответствующей работы.
