# Результат sparse-эксперимента — 2026-11-02

**Решение: не переключать продукт на новый протокол.** Инженерный инструмент
реализован; узкий кандидат сохраняет проверяемое содержимое в corpus, но не даёт
достаточной полезности/ускорения для замены обычного cleanup. Контракт смысловой
сохранности не ослаблен ради скорости. [Реализация и короткие тесты](implementation.md),
[pilot data](pilot-results.json), [длинные результаты](long-results.json).

## Короткий набор

15 native профилей: обычный формат, anchors, lines и повторы. 24 собственных
synthetic фразы, temperature 0.2, только установленный локальный Ollama. Все worker
завершились и receipts проверены; quality gate отдельно провален там, где модель
не делала полезных правок или меняла защищённое содержимое. У обычного guard
воспроизведён **RV-018**, он не считается исправленным экспериментом.

Anchors оказался сложен моделям: 9B/4B/3B исправили 1/0/1 из 8 пауз. У Gemma
первый проход дал 8/8, повтор — 0/8 с добавлением точек. Эти отрицательные результаты
сохранены. Упрощённый ответ line/text дал 8/8 у 9B, 4B и Gemma, 6/8 у 3B;
повторы 4B/Gemma — по 8/8. Защищённое содержимое после guards сохранилось.

Такая проверка охватывает corpus, parser и rollout gate. Она не доказывает, что
модель сама не предлагала плохих поправок: часть предложений отклонялась кодом.
Она также не доказывает, что модель вернёт только изменённые строки в длинной речи.

## Полная публичная запись

Тот же исходный JSONL Podlodka #109, что в предыдущем [профиле](../../profile-text-postprocessing-cost/evidence/native-reference.md):
704 строки, 7146.527375 s, SHA-256
`09014305b713638301d3cd4693d03e1f7f2920e75bdfc749c7164d0e10034ae8`.
Для каждого случая новая копия source; STT не выполнялся. Worker fingerprint
совпадает во всех случаях; исходные байты и receipts сохранены.
Windows/RTX 5080, локальный Ollama 0.40.13, context 4096 во всех 179 запросах каждого
прогона. Никакие модели принудительно не выгружались; фоновые процессы/внешний
Ollama не находятся в исключительном владении profiler. Все native случаи успешны,
timeout 900 s не достигнут.

| Модель / протокол | Wall, s | Generation, s | Выходных токенов | Итоговых edits |
|---|---:|---:|---:|---:|
| qwen3.5:4b · обычный | 331.481 | 151.592 | 30866 | 509 |
| qwen3.5:4b · guarded lines | 191.495 | 136.070 | 27681 | 11 |
| gemma4:e4b · обычный | 98.243 | 78.748 | 29707 | 559 |
| gemma4:e4b · guarded lines | 125.924 | 96.049 | 35820 | 26 |

**Edits не измеряют качество и эти возможности не эквивалентны.** Кандидат намеренно
не исправляет содержательные слова/ASR-ошибки по догадке. Из 704 исходных строк
лишь 126 допускают автоматическую правку по его строгим ограничениям; остальные
защищены целиком из-за отрицания/модальности/вопроса/цитаты/цифр/операторов.
Итоговая доля применённых правок слишком мала для заявления полного паритета.

Gemma в lines-режиме предложила 702 строки, из них 610 восстановлены guards,
66 были no-op, приняты 26. Модель фактически повторила почти весь текст в JSON:
выходных токенов стало **на 20.6% больше**, wall — на 28.2% больше.
Qwen 4B предложила 543 строки, 488 восстановлены, 44 no-op, приняты 11;
выходных токенов стало меньше только на **10.3%**, generation — на 10.2%.
Ни короткий corpus, ни JSON schema не обеспечили нужную разреженность ответа.

Для обоих candidate outputs независимо проверены версия-источник, границы edits
и сохранение последовательности содержательных токенов каждого изменённого ряда.
Сверка с аудио и приёмка смысла владельцем **not-run**. Первичная версия не менялась.

## Граница выводов о скорости

В обычном Qwen 4B 158.357 s wall лежат вне измеренных proxy HTTP вызовов, CPU самого
worker — 0.328 s. По сопоставлению событий около 38.9 s приходится между началом
операции и приёмом запроса proxy, 93.7 s — между окончанием upstream и концом операции.
Причина ожиданий/внешней нагрузки не локализована; это нельзя назвать ценой CPU guards.
В его candidate остаток вне HTTP 33.525 s. Поэтому разницу wall 331→191 s нельзя
целиком засчитать новому протоколу. Более прямые counters generation/tokens дают
лишь ~10% уменьшения. Отсутствующие native load counters оставлены null, не нулём.

У Gemma обычный/candidate остаток вне HTTP 5.548/9.053 s; рост generation и tokens
согласуется с замедлением JSON-варианта. В этом reference Gemma декодировала обычный
cleanup быстрее 4B, но качество обычного формата ещё требует защиты RV-018.
Сравнения не задают SLA и не являются общим рейтингом моделей.

## Следующая работа

1. Исправить RV-018 обычного retention guard с регрессиями на отрицание, «пока»,
   «почти», ограничения и буквальные цитаты; не объявлять старый guard достаточным.
2. Разделить детерминированное оформление и произвольную смысловую правку. Если
   продолжать sparse направление, отбирать нуждающиеся строки кодом до LLM и
   измерять реальные native calls; одной смены формата ответа недостаточно.
3. Принятие нового пользовательского режима требует delta, сохранения существующих
   действий и просмотра примеров. Обычный STT + optional summary остаётся прежним.

Исходный часовой инцидент владельца этими публичными прогонами не воспроизведён.
Само качество summary с Gemma не тестировалось, её глобальная модель не менялась.
