# Design

## Context

См. proposal и native-reference предыдущего профиля. Обычный worker уже сохраняет
строки и проверяет поправки; benchmark proxy умеет численный native trace.
Для эксперимента используется отдельный opt-in adapter в proxy: production binary
остаётся неизменным, исходные строки восстанавливаются локально из точечных edits.

## Goals / Non-Goals

Проверить скорость и полезность консервативного cleanup на 9B и маленьких моделях.
Кандидат не выполняет произвольную лексическую правку ASR: такие предложения
отвергаются, а не применяются под видом безопасного исправления. Refine/summary и
обычный API proxy не переключаются на другой протокол.

## Decisions

- `--experimental-sparse-edits` допустим только с text-only cleanup. Adapter явно
  переписывает только экспериментальные prompts/response; `Trace::start` сохраняет
  exact forwarding. Упрощённый запуск через отдельный флаг исключает скрытый default.
- `--experimental-sparse-lines` — второй взаимоисключающий вариант: changes из
  line/text; before берётся из точной исходной строки кодом. Это упрощает модельную
  задачу после неустойчивого anchors pilot (Gemma noise 8/8 → 0/8). Действуют те же
  ограничения, дополнительно lines с цифрами/операторами сохраняются целиком.
  Пропуски/невалидные ответы продолжают возвращать исходник, guards не ослабляются.
- Источник в запросе — JSON data с исходными line IDs. Ответ по JSON schema:
  `edits: [{line, before, after}]`, max 32 небольших replacements; отсутствие edits
  допустимо только как валидный JSON. Schema обеспечивает форму, не смысл.
- Before должен встречаться ровно один раз в указанной исходной строке. Известные
  IDs, deny unknown fields, границы/количество, отсутствие overlap и дубликатов
  проверяются кодом. Строка с некорректной поправкой восстанавливается целиком.
- После применения сравнивается последовательность содержательных слов без учёта
  регистра; разрешён узкий список вокальных пауз. Произвольные вставки/удаления слов
  отклоняются. Digits и соседние разделители не редактируются. Строки с отрицанием,
  модальностью, вопросом или цитатой сохраняются целиком: слишком дорогое по риску
  место для автоматического изменения пунктуации. Это консервативная граница,
  а не доказательство сохранения всего смысла в остальных строках.
- Adapter отдаёт worker полный исходный набор номеров с принятыми поправками,
  поэтому действующие grounding/retention guards выполняются дополнительно.
  Native token/timing counters относятся к короткому JSON, не к локально развёрнутому
  ответу. Отдельные counters фиксируют malformed/rejected/accepted, чтобы пустой
  ответ не выглядел качественной быстрой обработкой.
- Synthetic corpus содержит clean/noise, числа/имена/отрицания/вопросы/инъекции.
  Gate: нет нарушений защищённого содержимого и полезные ожидаемые исправления
  хотя бы 75% однозначных noise cases. Это проверка набора, не общая оценка качества.
  Сравнить 9B, установленную 4B и 3B stress model; дополнительная Gemma включается,
  если пользователь установит её. Без скачивания моделей агентом.
- Длинный публичный cleanup сравнивается только после коротких guards/usefulness;
  при неуспехе сохранить отрицательный результат, не менять продукт ради победы.

## Risks / Trade-offs

- Слабая модель выдаёт бессмыслицу → exact anchors, strict parser, rollback строки,
  safe content constraints и неизменённые downstream guards; неизвестность остаётся
  неизвестностью, не математической гарантией.
- Кандидат стал быстрее за счёт отказа от ASR word correction → прямо сравнить
  capability/edits, не выдавать за полный паритет; основной prompt не заменять.
- Сравнение подсчёта omitted → sparse omission означает «без предложений», поэтому
  использовать отдельные protocol counters, не объявлять нулевой worker omitted
  доказательством ответа модели для каждой строки.
- Переполнение/повтор IDs/ambiguous before → reject с численным reason code без
  source text в отчёте. Обычные записи/архив/настройки владельца не читаются.

## Migration Plan

Engineering prototype, без rollout/default migration. Сохранить воспроизводимые
команды, тесты, модель/digest, результаты и границы; итоговое решение по production
не принимать только на основе JSON validity и wall.
