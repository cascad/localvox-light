# Проект решения

## Context

Сейчас API ensure_recookable требует аудио при любом scope, тогда как CLI --post-only может работать по тексту.

## Goals / Non-Goals

Цель: повторять текст и сводку после retention. Не включать глобальную перестройку хранилища и бессрочное
расширение гарантий на все процессы приложения.

## Decisions

Разделить preconditions по scope: All требует аудио; Text/Summary требуют валидного source transcript. Проверка владения и постановка до инвалидирования сохраняются. Не восстанавливать утраченный звук и не выдавать missing text за пустую речь.

Реализация 2026-09-27: проверять источник под execution lock; scoped-задание
начинать с Text/Summary вместо Prepare, в том числе для прежнего JobKind::Ingest.
Общий `artifacts::source_transcript` строго читает выбранную версию и проверяет
доступные receipts. Для старых непустых версий без receipts допускается структурная
проверка без утверждения исторической целостности. Приёмка фазы и ручной post-only
используют тот же путь. Проверка — в [журнале сверки](../../evidence/implementation-review-2026-09-27.md).

## Risks / Trade-offs

Не принимать описание механизма за доказательство crash-safety. Работа затрагивает
повтор/отказ и должна иметь проверку на временном архиве; нужен ревью выбранного поведения.

## Verification

Проверить Text/Summary без аудио, отказ All, отсутствие/повреждение транскрипта, сохранение версии и конфликт lock.
