# Повторять текст и сводку после retention

Статус: **implemented / tested in source tree**; установленный release не обновлён.
Результаты: [evidence](../../evidence/implementation-review-2026-09-27.md).
Основание: [BL-007](../../backlog.md#bl-007). Это отдельное предложение, baseline пока описывает код.

Связанные принятые решения от 2026-09-27: [DEC-001](../review-code-inventory/proposal.md#dec-001)
о хранении исходников и [DEC-003](../review-code-inventory/proposal.md#dec-003)
о сохранении годных артефактов при восстановлении. Этот change остаётся нужен для
старых архивов, ручного удаления аудио и явно включённой очистки. Он не включает
автоматическую очистку и не меняет её настройки. Принятие направления не закрывает задачи.

## Why

На момент обнаружения API ensure_recookable требовал аудио при любом scope, тогда как CLI --post-only мог работать по тексту.

## What Changes

Повторять текст и сводку после retention. Поведение при отказе и повторе описано в delta spec.

## Capabilities

### New Capabilities

Нет новых возможностей продукта.

### Modified Capabilities

- `transcript-versions`: уточнение поведения для описанных сценариев.

## Impact

Core/API и связанные сценарии; исходное аудио не мигрируется. Работа с установленной
сборкой и архивом пользователя этим документом не выполняется.

## Исходные сведения BL-007

**Повтор текста/сводки после удаления аудио по retention.**
Тип: улучшение поведения; состояние: `proposed`; функции: F1/F8/F10.
Основание: производным нужен сохранённый транскрипт, но `Archive::ensure_recookable`
сейчас требует аудио для любого scope. Готово, когда текст/сводка повторяются по
валидному транскрипту без аудио, полный STT при этом объяснимо отказывает, исходный
текст сохраняется. Сначала зафиксировать это изменение PIPE-012.
