# Отзывчивая остановка

## Context

См. [proposal](proposal.md), BL-018/RV-014. Найдены две конкретные блокирующие
зависимости: `asr_worker_pool` делает безусловный recv результата Vosk, а команды
ChunkLane опрашиваются только из feed PCM. Исторический 10-секундный отказ пока
не привязан к одной из них: одинаковый лог печатался для autocook и engine.

## Goals / Non-Goals

Устранить найденные ожидания управляющего сигнала и сделать оставшиеся ожидания
различимыми. Проверить искусственно удерживаемый канал и отсутствие PCM.
Не увеличивать общий timeout, не считать unit-тест воспроизведением всех нативных
зависаний CPAL/Vosk и не останавливать активную пользовательскую запись ради эксперимента.

## Decisions

- Ожидать загрузку Vosk с recv_timeout и проверкой running, а не бесконечным recv.
  Сам нативный вызов загрузки не поддерживает принудительную отмену в потоке;
  coordinator прекращает ждать его, поток не удерживает завершение процесса.
- Опрос команд выполняется из служебного цикла независимо от PCM; существующий
  frame poll сохраняет совместимость прямых тестов ChunkLane. Команды логируются
  при получении; стоп закрывает текущие чанки прежним путём.
- `Daemon::shutdown` сам снимает running, вызывает именованный bounded join всех
  важных компонентов и возвращает ошибку таймаута/panic после попыток завершения.
  Внутри engine ожидания потоков имеют имена и heartbeat после сигнала остановки.
- Существующий phase-supervisor уже умеет cancel/process tree; проверить его
  интеграционные тесты и восстановление очереди. Архитектуру отдельных процессов
  для нативного capture выбирать только при доказанном оставшемся зависании.

## Risks / Trade-offs

- Native loading/capture может зависнуть внутри чужого кода → не обещать его
  прерывание этим изменением; определить конкретный компонент по новой диагностике.
- Таймаут coordinator при остановке → не пропускать финализацию записи engine;
  итоговый выход ошибочный, а незавершённая работа восстанавливается отдельно.

## Verification

Контролируемый незавершающийся model sender, команды без PCM, named join timeout/panic,
существующие process-tree cancellation и recovery. Исходный release-инцидент и
аппаратная остановка остаются отдельным обязательным пунктом evidence до воспроизведения.
