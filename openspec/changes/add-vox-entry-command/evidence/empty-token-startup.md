# Пустой токен при запуске vox — 2026-11-21

RUN-005 (delta), RUN-004 (delta), API-001, SETUP-007 (delta).

## Причина и исправление

После установки v0.2.5 владелец запустил vox: TUI показал timeout готовности API
за 15 с и не получил список/управление записями. Read-only проверка подтвердила:
соседний демон действительно работал и слушал 127.0.0.1:3017, health возвращал 401,
непустого пользовательского токена не было. vox читает `.env.defaults` через
dotenvy, в окружение попадает `LOCALVOX_API_TOKEN=`. Демон унаследовал пустую строку,
создал `Some("")`, а HTTP трактовал это как настроенный Bearer. Клиент с пустым
токеном заголовок не отправляет. Launcher проглатывал этот 401 до общего timeout.

HttpConfig.access_token теперь единообразно считает пустое значение отсутствующим.
Общий validate_bind применяется daemon/standalone/serving: без непустого токена
разрешён loopback, внешний bind отклоняется. Нормальная авторизация и Host/Origin
проверки сохраняются; непустые секреты не обрезаются и не меняются. Launcher после
однократного spawn сохраняет конкретный HTTP/compatibility отказ; сетевое ожидание
остаётся ограниченным и не создаёт второго демона. Контракт не переписан под дефект.

## Выполнено

- Новый настоящий HTTP тест на старом коде — FAILED с HTTP 401 при Some("").
  После исправления — PASS: health/sessions без Bearer, None/пустое значение,
  чужие Host/Origin 403, нелокальный запрос 401, непустой токен по-прежнему нужен.
- Внешние bind с None/пустым токеном отклоняются, включая похожие на localhost
  домены; IPv4/IPv6 loopback разрешены. Непустой токен допускает внешний bind.
- HTTP suite: 43 passed / 6 явных media/shared-client helper scenarios ignored.
  Launcher: 6 passed / 1 subprocess helper ignored, включая конкретный 401 после
  spawn, единственный запуск, существующий/посторонний/неавторизованный API,
  отказ/таймаут, сохранение жизни демона после закрытия клиента.
- Настоящий ConPTY `vox_uses_portable_settings_from_another_directory_and_reuses_the_running_api`
  passed: portable defaults/.env, чтение записи, клавиатура и команды клиента.
- Оптимизированные daemon/vox/TUI/standalone API собраны локально. Для daemon
  явно сохранён localvox-light-core/onnx, как в полном release-комплекте.
- Настоящий оптимизированный standalone API в частной папке на D: с унаследованным
  пустым токеном: health/sessions 200, чужие Host/Origin 403, внешний bind отвергнут
  до обслуживания. У первого acceptance helper не был задан DLL search path;
  readiness истёк, helper остановил только свой дочерний процесс. Повтор с DLL из
  установленного комплекта и отключёнными native error dialogs прошёл.

## Применение и границы

По прямому поручению владельца обновлена существующая установка F:\lv.
Владелец завершил демон через трей; перед заменой проверено отсутствие его процесса.
Заменены localvox-light.exe, vox.exe и localvox-tui.exe; оригиналы/manifest сохранены
в игнорируемом target/review/vox-empty-token-2026-11-21/original на D:.
Активный .env проверен SHA до/после; модели и архив не изменялись. Manifest содержит
новые hashes/размеры и release_tag=null: это локальный исправленный комплект,
а не опубликованный GitHub v0.2.5. Установленный --bundle-check прошёл.

Авторизация проверена без микрофона/capture. Пользовательский демон агент повторно
не запускал; следующая ручная проверка владельца остаётся отдельным результатом.
Новый release/push/native Mac/Linux запуск этого исправления не выполнены.
Полная установка и doctor прежнего этапа проверяли доставку/наличие компонентов,
но не подтверждали успешный запуск vox с унаследованными пустыми presets.
