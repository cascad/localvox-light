# Proposal

## Why

RV-021: при повторном STT готового YouTube-аудио UI/TUI ошибочно показывают
download/extract среди будущих шагов. Глобальный force сбрасывает доказанную
подготовку, а список next не ограничен оставшимися фазами текущего задания.

## What Changes

- Сохранять проверенное аудио как результат подготовки при forced STT.
- Формировать next только из запрошенных незавершённых текущих/будущих фаз.
- Не объявлять прошлые этапы успешными только из-за перехода очереди.
- Проверить повтор с готовым/повреждённым аудио, фазовые переходы и реальный HTTP;
  обновить evidence RV-021 и короткое описание хода обработки.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `processing-pipeline`: сценарии PIPE-011 для достоверного плана повторного запуска.

## Impact

Read-only workflow projection и тесты. Worker, очередь, модели, личный архив,
формат HTTP и зависимости не меняются. Обе клиентские схемы используют этот план.
