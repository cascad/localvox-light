# RV-021: план повторного запуска · 2026-11-11

## Воспроизведение

Unit fixture с настоящим WAV, сохранённой старой STT и forced recook до исправления
упал: для Prepare/Download получен Queued вместо Done. Причина — live+force
сбрасывал также подготовку, хотя worker переиспользует проверенный вход. Next
собирал незавершённые строки даже из прошлых фаз. Личный архив не использовался.

## Исправление

Force относится к transcript/производным артефактам. Аудио по-прежнему требует
audio_overview; факт запуска Transcribe не является proof. Next ограничен текущей
и будущими фазами и фильтрами requested/готовности. Старые проблемы остаются в
stages. Полнота результатов проверяется отдельно от next: завершённая очередь с
утраченным прошлым результатом показывает attention, а не успех.

## test-run

`cargo test --locked -p localvox-light-core -p localvox-light-api --jobs 2 -- --test-threads=2`:

- Core: 422 passed / 7 ignored. Готовое/повреждённое/удалённое аудио, force не
  принимает старую STT, все фазы next, неизвестные часы и отсутствие прошлого
  результата после Done проверены unit-тестами.
- API: 81 passed / 8 ignored; 3 integration passed. Настоящий HTTP с частным WAV
  и очередью Prepare → Transcribe: download/extract Done, next только summary;
  порча WAV снимает готовность, но не планирует прошлую подготовку как будущую.
  GET не изменяет файлы очереди/аудио.
- Первый общий прогон: 80 passed / 1 failed в settings fixture. Readiness-файл
  наблюдался между create и write, адрес был пустым. Producer теперь публикует
  readiness/result через существующий atomic_write вместо задержек/повторов
  проверки URL. Повторный полный прогон выше прошёл; настройки продукта не менялись.
- Main specs strict: 15 passed / 0 failed. Change strict и check-openspec прошли.
- Release daemon/worker/TUI собраны одной командой в обычный target/release
  (4m 01s); CLI `--help` daemon/worker и `--version` TUI проходят. Содержимое
  `/assets/index-KyvBl_Os.js` из ui/dist побайтно найдено внутри нового daemon:
  вчерашний фикс длительностей UI теперь установлен в обычный бинарник.
  Работающих LocalVox-процессов перед сборкой не было; для проверки демон не
  запускался и запись/очередь владельца не обрабатывались.

## Граница

Модели/устройства и реальная запись владельца не запускались. Контракт формата
HTTP, порядок исполнения, сохранённые данные и настройки не менялись. Вчерашнее
runtime-свидетельство остаётся историей дефекта; ручной recook нового бинарника
владельцем — not-run. PIPE-011 delta не синхронизирована и change не архивирован.
