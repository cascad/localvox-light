# Design

## Context

См. proposal.md. Worker Prepare проверяет artifacts::audio и переиспользует готовый
звук независимо от force. Однако workflow::view сбрасывает все этапы при live+force,
включая Download/Extract, а execution.next собирает любую незавершённую строку.

## Goals / Non-Goals

**Goals:** исправить RV-021 одним серверным планом для UI/TUI, сохраняя доказательства
готовности и ошибки прошлых этапов.

**Non-Goals:** изменения исполнения, восстановления, расписания, artifact validation,
повторный прогон моделей или пользовательской записи.

## Decisions

- Force инвалидирует результаты STT/производных в представлении, а не сохранённое
  аудио. Подготовка по-прежнему требует audio_overview; отсутствие звука не становится
  успехом по факту перехода очереди.
- execution.next ограничивается текущей/будущими фазами задания, после фильтра
  запросов/готовности; активная операция по-прежнему исключается отдельно.
- Прошлые неподтверждённые/невалидные строки остаются видны как проблемы в stages,
  не превращаются в будущие действия. Phase order задаётся явным exhaustiveness match
  по enum, без сравнения имён/числовых значений.

## Risks / Trade-offs

- Принять фазу за proof → отдельные тесты отсутствующего/повреждённого аудио и
  неизменности stage states; read-only HTTP fixture проверяет сериализованный plan.
- Новая фаза очереди → exhaustive enum match потребует осмысленно обновить план.

## Migration Plan

Нет формата/миграции данных. Собрать daemon и worker вместе после тестов, сохранив
пользовательский архив. Проверка реальной записи владельцем остаётся not-run.
