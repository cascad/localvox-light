# Design

## Context

Сейчас реальный renderer знает размеры body, а scroll helpers используют более
высокий viewport. Список хранит selection, но его offset каждый раз считается от 0.

## Goals / Non-Goals

**Goals:** одна геометрия для рендера/измерений, размер страницы по content area,
устойчивое окно списка при перелистывании. **Non-Goals:** новые режимы, scheduler,
изменение аудио или общий рефакторинг TUI.

## Decisions

- Повторно использовать небольшие layout helpers для внешних рядов/колонок,
  document body и list block. Простая замена 10 другой константой не учитывает resize.
- Добавить requested list offset в App; renderer и навигация используют один clamp
  с учётом selection и количества видимых строк. Page перемещает и offset, и selection;
  стрелки сохраняют viewport, фильтр сбрасывает offset, обновление сохраняет ID выбора.
- Документ листается в wrapped terminal rows, отключает follow_selection/journal.follow;
  End возвращает хвост. В формах сохраняется обработчик редактора, в других панелях
  page keys не меняют документ.

## Risks / Trade-offs

- Заголовки и двухстрочные элементы → размеры из тех же Rect/Block, тесты разных
  размеров/фильтра и реального экрана; маленькая область имеет минимальный шаг 1.
- Обновления/границы → clamp по содержимому, пустые списки безопасны; paging не
  вызывает HTTP/плеер и не выбирает новую сессию автоматически.
