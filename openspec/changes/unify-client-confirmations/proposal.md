# Proposal

## Why

В TUI сохранение настроек всё ещё требует печатать ДА; владелец ранее запретил
это и теперь явно распространил правило на все подтверждения. Выбран простой s.

## What Changes

- Все TUI подтверждения без текстовых полей: компактный диалог, действие/цель,
  s подтвердить, Ctrl+S/Ctrl+Enter также работают, Esc отменить.
- Plain s действует только в таком диалоге; ввод и остальная навигация сохраняются.
- Верхний S, открывающий сохранение, не подтверждает его повтором. Paste/repeat/
  обычный Enter не отправляют действие; pending не дублируется.
- Сохраняются привязка к исходной цели, серверная авторизация и API confirmation
  payload. UI уже подтверждает кнопками без печати слов; это остаётся допустимым.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `runtime-settings`: RUN-006, клавиша s для полного завершения; RUN-007, единые
  подтверждения всех действий.

## Impact

Общий TUI form handler/renderer, сценарии settings/delete/recook/cancel/shutdown,
unit/render/ConPTY, краткий справочник и локальный TUI. Серверные проверки не ослабляются.
