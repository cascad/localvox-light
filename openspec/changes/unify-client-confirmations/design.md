# Design

## Context

Shutdown уже имеет пустую form и компактный renderer. Общий Confirm(Task) и
DiscardSettings сохранили поле ДА. UI подтверждает кнопками, API требует явный
payload подтверждения, а не физически напечатанное слово.

## Goals / Non-Goals

**Goals:** единый компактный TUI confirm без пароля, s/Ctrl+S/Ctrl+Enter и Esc,
ясная цель, отсутствие повторной отправки и внезапного подтверждения.

**Non-Goals:** снимать API auth/ownership/confirmation проверки, автоподтверждать
действия, менять клавиши обычных текстовых форм или поведение кнопок UI.

## Decisions

1. Form::is_confirmation объединяет Shutdown/Confirm/DiscardSettings. Fields пусты;
   renderer использует общий компактный путь, сохраняя специальное предупреждение shutdown.
2. Plain s (и его нормализованная раскладка) принимается только без модификаторов,
   только в confirmation и только Press. s в настройках открывает диалог и возвращается без отправки;
   отдельный s подтверждает. Совместимый Shift+S не подтверждает диалог. Paste, Release, Repeat и Enter инертны.
   Ctrl+S/Ctrl+Enter остаются совместимыми путями отправки.
3. Task/target фиксируются при открытии. Pending action блокирует повтор; ошибка
   сохраняет диалог и исходную цель для явного retry. Discard остаётся локальным действием.

## Risks / Trade-offs

Терминалы без key-release/repeat протокола не позволяют физически распознать
удержание клавиши; поэтому проверяется один обработанный input event,
отмеченный Repeat отбрасывается. В legacy VT физическое удержание без признака
Repeat неотличимо от отдельных нажатий; временных эвристик не добавляется.
Обычный Enter из палитры ничего не подтверждает. Таймеров/эвристик не добавляется.
