# Design

## Context

См. proposal.md. PS подавляет дорогой штатный Write-Progress, а native мастер
получает только строки; curl CR-meter также не является протоколом прогресса.

## Goals / Non-Goals

Общий транспорт и renderer для штатного мастера на трёх ОС. Без новых Python/Node
зависимостей пользователя, без замены модели и без параллельной загрузки в продукте.
Численное время зависит от сети; измеряется полный настоящий transfer.

## Decisions

- Скрытый режим bundled localvox-install выполняет HTTP через имеющийся ureq,
  потоково считает SHA-256 и публикует только проверенный временный файл. Скрипты
  вызывают его через явный путь, fallback curl/IWR остаётся для standalone исходников.
- Типизированные ограниченные progress frames передаются только новому родительскому
  renderer; native helper самостоятельно рисует тот же Activity при обычном запуске.
  stdout/stderr имеют отдельные буферы фрагментов, один Activity владеет терминалом.
- Manifest задаёт immutable primary, резервные URL, точный размер и SHA-256 Vosk;
  digest сверяется с полным официальным архивом до изменения URL. Резерв не может
  ослабить проверку или поменять веса.
- ZIP staging — sibling выбранного каталога модели, чтобы не удалять собственный
  staging при замене модели и не копировать большой распакованный каталог через C:.
- Ollama byte events используют тот же renderer; проверка success и наличия tag
  после pull сохраняется.

## Risks / Trade-offs

- Старые helpers → capability handshake и сохранённый standalone fallback.
- Нет Content-Length → spinner/байты/скорость, без ложного ETA.
- Сбой/неверный SHA/короткий ответ → удаляется только наш .part, конфиг не публикуется.
- Тестовый полный официальный reference может скачиваться диапазонами для сравнения;
  это отдельное измерение и не реализация транспорта продукта.
