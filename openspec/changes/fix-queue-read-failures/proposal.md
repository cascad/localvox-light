# Proposal

## Why

PIPE-002/011 запрещают скрывать нечитаемый jobs.json пустой очередью. Сейчас core блокирует мутации и progress сообщает ошибку, но queue/jobs API игнорируют load_error и отвечают успешным пустым списком/нулями. Это даёт ложное «всё обработано» и скрывает причину остановки.

## What Changes

- Передавать отказ чтения queue/jobs как HTTP 503, сохраняя успешный формат и корректную пустую очередь при отсутствии файла.
- Сохранять последние успешные данные с явной отметкой ошибки в UI/TUI; отличать начальную недоступность от подтверждённого отсутствия задач, восстанавливаться после исправления хранилища.
- Зафиксировать воспроизведение, real HTTP и клиентские проверки без изменения очереди пользователя.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `processing-pipeline`: уточнить сценарии PIPE-011 для нечитаемой очереди, начального сбоя и восстановления; существующий запрет ложного успеха сохраняется.

## Impact

Archive/HTTP, верхняя строка UI/TUI и browser/native tests. Формат jobs.json, планировщик, retry-политика, успешные payload и действия над заданиями не меняются. Известные BL-002/004 и аппаратная приёмка остаются открытыми.
