# Proposal

Статус: реализовано и проверено 2026-11-09; [результаты](evidence/results.md).
Два full/relevant сравнения source NER дали 22–24% уменьшения времени с exact
Entity parity; два обычных grounding profile подтвердили прежние verdict/cache.
Рабочая установка не обновлялась, общая точность summary/Mac не приняты.

## Why

Продолжение BL-003: [NER components](../profile-ner-inference-cost/evidence/results.md)
показали по 221 name/role окну, около 25 s на каждый проход. Роли нужны только
для сравнения с найденными именами; окно вне всех name spans не может повлиять
на результат. Такой пропуск можно обосновать геометрией spans без эвристик модели.

## What Changes

- Сохранить полный name pass. В role pass выполнять только прежние полные окна,
  которые пересекают хотя бы один name span; размеры, overlap и контекст не менять.
- Использовать общий план окон и индекс объединённых byte intervals: не добавлять
  списки слов, пороги релевантности, догадки по содержанию или новые зависимости.
- Оставить полный проход инженерным эталоном на той же реализации. Проверить
  точное совпадение entities/score/spans на границах/Unicode/перекрытиях и длинной
  сохранённой публичной STT, измерить оба порядка запуска в fresh release процессах.
- Показывать skipped windows в численном инженерном профиле; обычный API не
  включает clocks/новые логи. Сохранить ошибки необходимых вычислений без fallback.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Это внутренняя оптимизация существующих LLM-004/PIPE-007 с сохранением
результата проверки; `skip_specs: true`. Нового пользовательского выбора нет.

## Impact

Core NER/его профиль, model-free и explicit native tests, CI/engineering docs,
coverage/evidence. Модели, настройки, thresholds и состав pipeline не меняются.
Рабочий daemon/worker и архив владельца не заменять. Если для выигрыша потребуются
хрупкие допущения или ослабление проверки, остановить внедрение и обсудить.
