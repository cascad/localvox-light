# Recording Specification

## Purpose

F3/F9. Захват, команда записи, pre-roll, пауза и диагностика устройств.

Статус контракта: **accepted**, 2026-09-27. Это обязательное поведение,
а не заявление о безошибочности текущей сборки.
[Основание принятия и границы](../../baseline.md) ·
[Сверка каждого требования](../../evidence/coverage.md#recording).

## Состояния из реализации

| Состояние | Событие | Действие |
|---|---|---|
| armed=false | start | armed=true; попытка создать meta/сессию, seed pre-roll |
| armed=true | start | игнорирование в движке |
| armed=true | stop / автостоп | закрытие хвостов, причина, снятие маркера |
| любое | пауза record_pcm | discard fast; finalize archive chunk; armed отдельно |
| armed=false | CallStarted | игнорирование |

## Requirements

### Requirement: REC-001 Явное начало архивной записи

В обычном режиме ChunkLane SHALL начинать невооружённым: PCM наполняет кольца в RAM, архивные чанки появляются после команды start. Повторный start в движке игнорируется; API при видимом маркере уже идущей записи возвращает ошибку. Это правило об архивном аудио, а не обещание отсутствия любых записей на диск: live-текст, заметки и legacy-сегменты имеют другие пути.

Код: [ChunkLane::new/start/feed](../../../crates/localvox-light-core/src/pipeline.rs), [Archive](../../../crates/localvox-light-api/src/archive.rs).

#### Scenario: До кнопки

- **WHEN** запущен движок без команды start
- **THEN** новая архивная сессия не открывается.

#### Scenario: Повтор старта

- **WHEN** start приходит в уже armed ChunkLane
- **THEN** разговор не разделяется на вторую сессию.

#### Scenario: Команда принята, аудио ещё не началось

- **WHEN** API сохранил start, но движок ещё не создал сессию либо получил отказ диска
- **THEN** принятый запрос не выдаётся за подтверждённую запись; состояние записи и ошибка отражают фактическое создание/сохранение аудио.

### Requirement: REC-002 Pre-roll и время начала

При создании сессии система SHALL записывать накопленные кольца обоих источников и сдвигать started_at назад на длину более длинного кольца. Размер берётся из preroll_sec (обычно 300 с), сразу после запуска история может быть короче. При ошибке создания каталога следующие кадры повторяют попытку; временный orphan-буфер ограничен max(pre-roll, 60 с) на источник.

Код: [ensure_current, seed_preroll, preroll_len_sec](../../../crates/localvox-light-core/src/pipeline.rs).

#### Scenario: Неполное кольцо

- **WHEN** запись начата вскоре после запуска
- **THEN** сохраняется фактически накопленная история, не выдуманные пять минут.

#### Scenario: Каталог недоступен

- **WHEN** armed=true, но сессию создать не удалось
- **THEN** попытки повторяются, старый избыток ограниченного буфера может теряться.

### Requirement: REC-003 Stop и метки звонка

Stop SHALL сохранять stopped_at/reason, закрывать текущие чанки и лишь затем убирать маркер записи. Детектор CallStarted/CallEnded меняет метки meetings только у armed-сессии, не начинает запись сам. Автостоп использует отсутствие уровня выше 0.003 на обеих дорожках и настраиваемый интервал; значение <=0 отключает его.

Код: [stop, on_signal, maybe_autostop](../../../crates/localvox-light-core/src/pipeline.rs).

#### Scenario: Звонок без записи

- **WHEN** детектор сообщает о звонке при armed=false
- **THEN** архивная запись не начинается.

#### Scenario: Тихий старт

- **WHEN** запись началась в тишине
- **THEN** таймер автостопа отсчитывается от старта, а не от старой активности.

#### Scenario: Звучит только loopback

- **WHEN** на системной дорожке есть достаточный уровень
- **THEN** этот звук обновляет время активности.

### Requirement: INV-REC-001 Разные границы паузы

При переходе record_pcm в false конвейер SHALL отбрасывать незаконченный fast-сегмент, закрывать с сохранением архивный чанк и останавливать часы integrity watchdog. Пауза захвата и завершение архивной сессии — разные события. Пока record_pcm=false, PCM не передаётся в ChunkLane и pre-roll не пополняется.

Код: [sync_pause_discard, run](../../../crates/localvox-light-core/src/pipeline.rs), [ChunkRecorder::finalize_current](../../../crates/localvox-light-core/src/chunks.rs).
Существующая проверка: `recorder_pause_closes_and_resumes_new_chunk` в chunks.rs.

#### Scenario: Пауза внутри фразы

- **WHEN** есть открытый fast-сегмент и архивный чанк
- **THEN** первый отбрасывается, второй закрывается с сохранением аудио.

### Requirement: REC-004 Потеря устройства и отставание

Движок SHALL отличать отставание очереди от недопоступившего звука и выдавать предупреждения watchdog. В коде есть переподключение/выбор fallback микрофона; тишина loopback оценивается во время помеченного звонка. Это диагностика и попытки восстановления, не доказательство отсутствия потерь при любом отказе.

Код: [run_engine](../../../crates/localvox-light-core/src/engine.rs), [MicHealth, LoopbackHealth, Integrity, Backlog](../../../crates/localvox-light-core/src/pipeline.rs).
Существующая проверка: `a_backlog_in_our_own_queue_is_not_a_loss`, `a_pause_is_not_a_loss` в pipeline.rs.

#### Scenario: Очередь растёт

- **WHEN** обработчик не успевает за захватом
- **THEN** память может расти и выдаётся предупреждение об отставании.

#### Scenario: Пауза

- **WHEN** пользователь приостановил захват
- **THEN** пауза не учитывается как утрата аудио в integrity watchdog.

### Requirement: REC-005 Завершение движка

При штатной остановке pipeline SHALL вычитать уже доступные PCM через try_recv, закрыть архивные чанки и финализировать fast-хвосты; движок ждёт поток pipeline раньше потоков захвата. Новая тяжёлая live-ASR после running=false не начинается: дисковые сегменты доступны восстановлению, RAM-черновики теряются.

Код: [run](../../../crates/localvox-light-core/src/pipeline.rs), [run_engine, asr_thread_loop](../../../crates/localvox-light-core/src/engine.rs).

#### Scenario: Shutdown с накопленным звуком

- **WHEN** остановка начата при непустой PCM-очереди
- **THEN** доступные кадры дренируются, архивные хвосты закрываются без ожидания бесконечного disconnect.

### Requirement: INV-REC-002 Controls independent of PCM

Цикл записи SHALL проверять команды start/stop и сигнал остановки независимо
от появления новых PCM-кадров, в том числе при паузе или пропавшем устройстве.
Остановка записи SHALL финализировать имеющееся аудио до снятия признака активной записи.

#### Scenario: Stop with no new PCM

- **WHEN** команда stop поступила, но новых аудиокадров нет
- **THEN** цикл обрабатывает её на своём служебном опросе, сохраняет имеющийся чанк и закрывает запись.

#### Scenario: Shutdown while waiting for model

- **WHEN** получен сигнал завершения, а live ASR ещё ждёт модель
- **THEN** ожидание результата загрузки перестаёт удерживать завершение движка;
  сохранённое архивное аудио остаётся для последующей обработки.

Код: [engine](../../../crates/localvox-light-core/src/engine.rs), [pipeline](../../../crates/localvox-light-core/src/pipeline.rs), [named join](../../../crates/localvox-light-core/src/cli.rs), [daemon](../../../crates/localvox-light/src/main.rs).

## Observed limitations

Реальное извлечение устройств и длительная нагрузка не прогонялись. AEC, глобальный hotkey и автоматическое начало звонка из старого реестра не подтверждены этой реализацией. Запрос API start сохраняет командный файл, а не подтверждает уже созданный аудиоартефакт. В текущем проходе BL-018 исправлен и проверен опрос команд без PCM; полноценная приёмка остановки открыта. См. RV-006 и [evidence](../../evidence/implementation-review-2026-09-27.md).
