# Проверка миграции в OpenSpec

Дата: 2026-09-27. Ветка: `new_course`, рабочее дерево с незакоммиченными изменениями.
Статус всех capability: **draft / awaiting-review**. Это первичная инвентаризация
основных путей кода, не независимая полная приёмка всех функций.

## Что создано

15 capability specs, 82 Requirement-ID, 133 WHEN/THEN сценария в baseline.
Три proposed change с delta/design/tasks; все задачи реализации открыты.
13 наблюдений для последующей сверки в [review](../review.md).
Старые PIPE/SC/BL/F-ID сохранены. Прежние docs/specs стали указателями;
установка и команды сборки остались в README, исторические планы сохранены.

## Проверки

- OpenSpec CLI 1.13.2: `validate --all --strict --no-interactive` — 18/18 прошли,
  ошибок/предупреждений нет; есть INFO о длинных требованиях (>500 символов).
  Длина оставлена для деталей и угловых случаев; INFO не проверяет истинность текста.
- `list --specs` различает 15 описаний; `list` показывает 3 изменения с 0/4 задач.
- Проверены локальные пути/якоря, уникальность Requirement-ID и существование
  многословных ссылок на тесты/символы. Это структурная проверка, не запуск тестов.
- `git -c core.safecrlf=false diff --check` — без ошибок.

[Снимок 59 связанных исходных файлов](code-snapshot.json) содержит HEAD, пометку dirty
и SHA-256 фактических файлов. Он позволяет отличить последующие изменения кода от
прочитанной версии; не доказывает, что изучены все ветви каждого файла.

## Что не проверялось

Код приложения этой миграцией не менялся. Сборки, Rust/runtime-тесты, реальные модели,
микрофон, сторонние MCP, облачные вызовы и пакет из пяти видео не запускались.
[Ранее выполненные проверки PIPE](pipeline.md) — отдельное историческое свидетельство.
Ни одна capability не переведена в accepted. Перед этим нужны повторная сверка,
существенные воспроизведения и согласование намеренного поведения с владельцем.
