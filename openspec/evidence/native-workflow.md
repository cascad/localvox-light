# Переход на официальные skills и change workflow

Дата: 2026-09-27. Ветка `new_course`, рабочее дерево с незакоммиченными изменениями.
Основание: прямое поручение владельца подключить официальные skills и привести
текущее ведение документов к штатному OpenSpec. [ADR-0003](../../docs/adr/0003-official-openspec-workflow.md).

## Установка

- `npm install --global @fission-ai/openspec@1.13.2`; CLI сообщает `1.13.2`.
- Выбран custom-набор workflow: explore, new, continue, propose, apply, update,
  verify, sync, archive. Это настройка OpenSpec пользователя на этой машине.
- `openspec init --tools codex --profile custom --no-animation` создал девять
  официальных skills в [.agents/skills](../../.agents/skills), с `author: openspec`
  и `generatedBy: 1.13.2`. Содержимое SKILL.md не редактировалось.
- Первоначальный init с `--language Russian` отказал, потому что config уже
  существовал. Повтор без этого флага успешен; язык уже задан в проектном context.
- Чтобы skills обнаруживались и в задаче с cwd вне репозитория, созданы пользовательские
  Windows junction-ссылки `~/.agents/skills/openspec-*` на те же проектные каталоги.
  SHA-256 SKILL.md через ссылку и исходный путь совпадает. При переносе репозитория
  ссылки потребуют обновления. Это проверка установки файлов, не доказательство
  отображения каждого skill в UI уже открытой задачи.

## Перенос документов

[Карта BL-ID → change](native-workflow-mapping.json) сохраняет идентификаторы и hash
исходного текста бэклога (UTF-8 с LF). Все 12 конкретных BL-записей перенесены в
proposal соответствующих changes с сохранением исходных сведений, примеров, границ
проверки и критериев; относительные ссылки пересчитаны. Реализационные checkboxes
не дублируются в inbox; прежние пункты исследования в proposal сохранены как текст.

- Три существовавших change сохранили свои delta/design/tasks, по 0/4 выполненных задач.
- Девять новых change созданы через `openspec new change`; перед записью proposal
  прочитаны `status` и `instructions proposal`. У них нет выдуманных design/tasks.
- Четыре из новых меняют поведение: восстановление артефактов, объединение импорта,
  остановка, узнавание говорящих. Их delta ещё не подготовлены.
- Пять новых ограничены измерениями, исследованием, приёмкой, документацией или CI.
  Для них используется штатный `skip_specs: true`; это не отметка о выполнении.
- BL-011–017 остаются сырыми группами идей в inbox. Их декомпозиция не была поручением
  на реализацию и не заменена фиктивными готовыми change-планами.
- `backlog.md` теперь только inbox и индекс; catalog/review/evidence — вспомогательные
  навигация и свидетельства. Работы и их готовность читаются штатным CLI.

## Проверка

- `openspec list` обнаруживает 12 changes; `list --specs` — 15 capability.
- Проверены статусы и apply-инструкции всех changes: у девяти новых
  `isPlanningComplete=false`, apply заблокирован отсутствующими артефактами.
  Ноль задач при отсутствии tasks.md не трактуется как выполненная работа.
- `openspec validate --all --strict --no-interactive --json` завершился с кодом 1:
  **23/27 прошли; четыре незаконченных поведенческих proposal не имеют delta**.
  Все 15 baseline specs, три прежних change и пять работ с skip_specs прошли формат.
  [Полный результат](native-workflow-validation.json) сохраняет ошибки и INFO,
  не превращая неполную общую проверку в зелёную.
- Дополнительно проверены локальные ссылки/якоря и `git diff --check`; результаты
  и состояние документов сохранены в [структурной проверке](native-workflow-structure.json).

## Ограничения

Это установка workflow и перенос состояния документов. Приложение, архив пользователя,
модели и очередь видео не изменялись и не запускались. Причины зависания и конкретной
ошибочной подписи не установлены этим переносом. Ни одна capability не принята,
дельты не синхронизированы, незавершённые changes не архивированы.
Исторические [результаты первой миграции](migration.md) сохранены без переписывания.
