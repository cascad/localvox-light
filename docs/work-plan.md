## Stage 0 — Замеры и подготовка (перед кодом фазы A)

**WP-0.1. LLM-бенч на UAT-эталоне (M).**
Прогнать `transcript_uat.txt` через 3–4 модели (Qwen3-30B-A3B и/или gpt-oss-20b,
Qwen3-8B, T-pro 2.0 — что влезает в железо; через Ollama) на трёх задачах:
cleanup, summary, глоссарий-промпт. Сравнить с ручными эталонами
(`transcript_uat_processed.md`, `transcript_uat_summary.md`).
- Метрики: термо-точность (доля правильно нормализованных терминов из таблицы UAT),
  субъективная оценка summary, скорость/RAM.
- Выход: выбранная дефолтная локальная модель + числа в `local-models.md`.

**WP-0.2. Замер RTF GigaAM v3 int8 (S).**
На целевом железе: RTF одного потока + масштабирование по воркерам (тест на
youtube-аудио через `localvox-asr`). Проверка бюджета «час ≤ 5 мин».
- Если бюджет не бьётся на CPU — решаем: меньше воркеров других задач/ночной
  режим/GPU; облачный ASR не рассматриваем (P8).

**WP-0.3. Глоссарий-seed (S).** ✅ конвертирован из UAT-таблицы —
`assets/glossary/it-ru-base.toml`. Дополнять по ходу.

**Примечание:** аудио UAT-встречи не сохранилось (старый код удалял WAV) — ASR-бенчи
делаем на новых записях/youtube; текстовые эталоны UAT работают для LLM-бенча.

## Фаза A — Фундамент качества

Порядок: WP-A1 → WP-A2 → WP-A3 → WP-A5; WP-A4 (LLM) — параллельно с A1–A3
(зависит только от текста, не от формата записи).

**WP-A1. Формат записи: чанки (L).** `core::chunks` (новый модуль).
- [ ] Потоковый writer: PCM → WAV-файл, flush 1–5 с, периодический fsync.
- [ ] Ротация по VAD-тишине: цель 5–10 мин (конфиг), разрез на ближайшей паузе;
      аварийный фолбэк — жёсткий разрез с нахлёстом 15–30 с при 15 мин без тишины.
- [ ] Закрытие чанка → фоновая конвертация WAV → FLAC (ffmpeg или flac-crate).
- [ ] Layout сессии: `sessions/<дата_имя>/audio/chunk_NNN.flac` + `meta.json`
      (см. `architecture-target.md`).
- [ ] Recovery: на старте — недописанный WAV-чанк финализируется и остаётся.
- [ ] Retention: минимум — **выключить удаление после ASR** (engine.rs), sweeper
      «старше N дней» (конфиг `[retention]`).
- Приёмка: kill -9 в середине записи → потеряно ≤5 с; чанки играются; границы
  чанков — в тишине (ручная проверка на живой записи).

**WP-A2. Версии и манифест (M).** `core::versions`.
- [ ] `transcripts/vNNN-<метка>.jsonl` + `versions.json` (модель, параметры, дата,
      метка, родители, best).
- [ ] API модуля: создать версию, перечислить, назначить best; производные
      (processed/summary) помнят версию-родителя.
- [ ] CLI: `localvox versions <сессия>`, `localvox versions set-best …`.
- Приёмка: два прогона разными моделями → две версии, переключение best, экспорт
  берёт best.

**WP-A3. Slow-lane: очередь джобов + ASR-варка (L).** `core::jobs`.
- [ ] Durable-очередь джобов (переиспользовать имеющуюся механику сегментной
      очереди: файл-маркеры + переочередь на старте).
- [ ] Джоб `asr`: чанки сессии → GigaAM v3 int8 параллельно по пулу → версия
      транскрипта с пословными таймкодами (из CTC).
- [ ] Планировщик: сразу после закрытия чанка / по завершении сессии / вручную;
      idle-режим и «ночная варка» — конфиг.
- [ ] `localvox process <сессия>` — прогнать/доварить.
- Приёмка: час аудио → транскрипт ≤ 5 мин (WP-0.2 железо); рестарт посреди варки →
  доваривается без дублей.

**WP-A4. LLM-крейт (L).** `localvox-light-llm` (новый крейт).
- [ ] Trait `LlmProvider` + OpenAI-compatible клиент (reqwest, стриминг);
      профили в конфиге (`[llm.profiles.*]`: ollama/openai/openrouter).
- [ ] Шаблоны-файлы `templates/*.md` (стартовый набор из F1) + схема протокола.
- [ ] Глоссарий: загрузка `glossary/*.toml`, дет. проход (aho-corasick +
      ambiguity guard) + подмешивание в промпт; лог замен.
- [ ] Chunking/map-reduce для длинных транскриптов.
- [ ] Валидация summary против транскрипта (второй проход).
- [ ] Джобы `cleanup`, `summary` в slow-lane; выход — `processed.md`, `summary.md`
      (версии-производные).
- Приёмка: на UAT-тексте — не хуже ручного эталона (оценка + термо-метрика WP-0.1).

**WP-A5. Единый вывод + экспорт + meta.sqlite (M).**
- [ ] youtube/asr-пути пишут сессионный layout (chunks + transcripts/), `.txt` —
      конвертер.
- [ ] Экспорт: md (Obsidian-совместимый), SRT/VTT (таймкоды есть), txt.
- [ ] `meta.sqlite`: сессии, версии, метки, теги (P9: только мета/индексы,
      пересоздаваемо из файлов; rusqlite).
- Приёмка: `localvox-asr <youtube-url> --template конспект` → сессия + конспект;
  `localvox export <сессия> --srt`.

**Выход фазы A:** сценарии S1/S4/S9 работают полностью — «после каждой встречи
готовый протокол», «конспект видео одной командой».

## Фаза B — Интерактив

- **WP-B1. Fast lane в RAM + live-индикация (M):** сегментная очередь → RAM;
  подача черновика «как думание LLM» в TUI; дисковый режим — legacy-флаг.
- **WP-B2. Голосовой модуль (L):** `localvox-light-voice` — wake-word в партиалах
  Vosk (только mic), грамматика «запиши [в слот] …», стоп-слово/пауза,
  ретро-режим из ring buffer (мини-буфер до F3), Piper TTS через ort + анти-эхо
  гейт, полная конфигурируемость и отключаемость (реестр F2).
- **WP-B3. Слоты (M):** `localvox-light-slots` — trait SlotSink/SlotSource,
  markdown-адаптер (append/по-шаблону), реестр из `[slots.*]`, per-slot
  LLM-обработка. Ярус 0 мобильного закрыт автоматически.
- **WP-B4. Поиск, этап 1 (M):** spike tantivy vs sqlite FTS5 (ru-стемминг!) →
  индексатор всех артефактов → `localvox search` + TUI-панель.
- **WP-B5. Надёжность захвата, часть 1 (M):** приоритетный список микрофонов +
  автофоллбек; watchdog тишины; sanity-check устройств.
- **Бенч-гейт:** прогнать «тщательный» режим (second opinion) на живых встречах —
  решить, включать ли в C.

**Выход фазы B:** S2/S3/S5/S7-я0 — «ассистент, с которым разговариваешь».

## Фаза C — Ambient (контурно)

Демон + трей (сначала Windows, затем mac/linux) · автодетект по WASAPI-сессиям +
pre-roll ring buffer + сессионизация · AEC (webrtc-audio-processing/speexdsp) ·
API-крейт (HTTP+WS, токен) + MCP-сервер архива · PWA (поиск/чтение/чат/управление) ·
re-ASR + refined-версии · embeddings (bge-m3 через fastembed) · роутинг F5 ·
плеер в TUI (чанк+offset). Детализация — в конце фазы B.

**Выход:** S6/S7-я1/S8 — «секретарь на автопилоте».

## Фаза D — Паритет и рост (контурно)

Диаризация (опц. модуль, sherpa-onnx, персистентные профили) · RAG-чат ·
календарь · мобильный ярус 2 · отбор из идей-пула (talk-time, дайджест, People,
маскирование…) · полный retention-тюнинг.

## Сквозное

- **Каждый WP**: тесты на новую логику; `verify` перед мержем; журнал решений
  бэклога при отклонениях от плана.
- **Бенчи как ворота**: merge-режимы, embeddings-модель, VAD-замена (Silero вместо
  webrtc — можно взять в любой момент как S-задачу, выигрыш большой) — включаются
  только по замерам.
- **Конфиг**: новые секции — сразу в `light.toml`-эскиз (`architecture-target.md`)
  и `.env.example`-миграцию обсуждаем в WP-A1.
