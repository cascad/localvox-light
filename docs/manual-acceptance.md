# Ручная приёмка UI и TUI

Проверяем текущую сборку на Windows: настоящий микрофон, системный звук, слышимость
плеера и работу двух клиентов с одним демоном. Сначала короткий прогон, затем
длинная запись. **Пока все пункты ниже — `not-run`: документ подготовлен, приёмка не выполнена.**

Все доступные действия описаны в [справочнике пользователя](user-guide.md).
Этот чек-лист закрывает оставшуюся [задачу 10.2](../openspec/changes/add-technical-journal-workspace/tasks.md),
а также проверяет отмену из [BL-002](../openspec/changes/archive/2026-11-01-serialize-session-mutations/evidence/implementation.md).

## 1. Подготовить сборку и тестовый архив

1. Завершить текущую запись и выйти из прежнего демона через меню трея «Выход».
2. Запомнить исходные настройки summary и устройств: после проверки вернуть их.
3. В PowerShell из корня проекта собрать интерфейс, демон, worker и TUI вместе:

```powershell
Set-Location D:\rust_repo\localvox-light
$env:TEMP = "$PWD\target\test-temp"
$env:TMP = $env:TEMP
$env:CARGO_BUILD_JOBS = '2'
New-Item -ItemType Directory -Force -Path $env:TEMP | Out-Null
npm.cmd --prefix ui run build
if ($LASTEXITCODE -ne 0) { throw 'UI build failed' }
.\scripts\run.ps1 -Tui -BuildOnly
```

Если mpv ещё не установлен: `npm.cmd --prefix ui run setup:mpv`.
Модели и локальный провайдер summary должны быть настроены по [README](../README.md#как-запустить).

Запустить демон с отдельным архивом на D: и оставить его работающим:

```powershell
.\target\release\localvox-light.exe --daemon --audio-dir "$PWD\target\uat-manual"
```

Открыть UI: **http://127.0.0.1:3017/**. Во втором PowerShell:

```powershell
Set-Location D:\rust_repo\localvox-light
.\target\release\localvox-tui.exe --address http://127.0.0.1:3017
```

Если настроен другой адрес или API-токен, использовать те же параметры подключения
в обоих клиентах; TUI получает токен через `LOCALVOX_API_TOKEN` или форму подключения.
Проверить в настройках микрофон и устройство системного звука. Для перезапуска
демона повторять команду с **тем же `--audio-dir`**. Все новые записи назвать `UAT …`;
удаление проверять только на них. Настройки приложения остаются общими с обычным запуском.

## 2. Короткий сквозной прогон

В TUI: `:` — действия, `Tab` — панель, `↑/↓` — выбор, `Enter` — открыть;
`1–5` — вкладки. В форме `Ctrl+Enter` отправляет, `Ctrl+S` — запасной вариант,
`Esc` отменяет. Буквенные хоткеи ниже действуют вне формы, в английской раскладке.

| ID | Что сделать | Что должно произойти | Результат |
|---|---|---|---|
| M01 · Запись двух источников | Выключить summary и сохранить. В TUI нажать `F9`, назвать запись `UAT звук`, отправить форму. На 30–60 секунд включить речь через выбранный выход и самому произнести несколько отличимых фраз. Остановить кнопкой «Остановить» в UI. | Оба клиента показывают подтверждённую запись и растущее время. После stop она заканчивается в обоих клиентах, появляется обработка. При прослушивании слышны и микрофон, и системный звук. | not-run |
| M02 · Обязательная STT, без очистителей | Дождаться распознавания `UAT звук`, открыть «Ход», затем «Текст» в обоих клиентах. | Распознавание выполнено; refine/cleanup не запускают LLM автоматически, summary отмечена как отключённая. Текст доступен без ожидания сводки. В UI `Ctrl+Shift+C`, в TUI `y` копируют весь текст без таймкодов и имён; вставить в редактор и проверить начало и конец. | not-run |
| M03 · Живой журнал | Включить summary, записать ещё одну встречу `UAT журнал` на несколько минут. Во время обработки смотреть «Ход» в UI и TUI (`5`), раскрыть `+ N lines` / операцию через `Enter`. | Видны предыдущие этапы, текущая операция и следующие шаги. У текущего этапа идёт время, завершённое время замирает. Неизвестное время явно подписано. Команды и аргументы различимы, подробности приглушены; завершение команды само по себе не означает готовый результат. | not-run |
| M04 · Звук и перемотка | Открыть готовую запись. В UI проверить play/pause, перемотку и ▶ у реплики. Затем в TUI: `Space`, `g` → время, `Alt+←/→` ±15 с; `F6` → `←/→` ±5 с; во вкладке «Реплики» выбрать строку и нажать `p` дважды. | В каждом клиенте слышен нужный звук, позиция меняется; фрагмент заканчивается у конца реплики, повторный выбор запускает его снова. Переключение записи не оставляет старый звук. Клиенты слушать по очереди. | not-run |
| M05 · Выход TUI при записи | Начать `UAT выход`, говорить; закрыть форму, нажать `q` в TUI. Продолжить говорить ещё 10–15 секунд. Снова открыть TUI, затем остановить запись через `F8`. Повторить короткую проверку выхода в терминале VS Code. | TUI закрывается и возвращает нормальный ввод. UI всё время показывает продолжающуюся запись, после повторного подключения её видит TUI. В итоговом аудио есть звук после закрытия клиента. `F10` — дополнительный способ выхода; Ctrl+Q может перехватывать терминал. | not-run |
| M06 · Два клиента и размеры | Пока идёт обработка, переключать документы и очередь в обоих клиентах. В UI сузить окно примерно до 480 px, сменить тему; TUI уменьшить до 80×24, затем расширить, проверить ASCII через палитру. | Доступны stop записи, навигация и документы; текст и кнопки не выходят за экран. В обоих клиентах одна серверная очередь; обновления не выдают старый результат за новый и не сбрасывают ввод в форме. | not-run |

## 3. Отмена, продолжение и длинная запись

Для M07 нужна тестовая встреча, у которой summary ещё выполняется. Если этап
успел закончиться, повторить на более длинной **тестовой** записи.

| ID | Что сделать | Что должно произойти | Результат |
|---|---|---|---|
| M07 · Отмена | После готовой STT, во время summary, нажать «Отменить обработку» в UI. На другой тестовой записи сделать то же через `X` в очереди TUI. | Сначала остановка, затем отмена после освобождения worker. Готовый текст остаётся читаемым и копируется, незавершённая summary не становится готовой. Ошибка или неподтверждённая остановка не изображаются успехом. | not-run |
| M08 · Продолжение после перезапуска | Оставить одну запись отменённой, штатно перезапустить демон с тем же тестовым архивом и подключить клиенты. Затем UI: «Продолжить обработку»; TUI на другой отменённой записи: `R`. | После перезапуска работа сама не возобновляется. Явное продолжение запускает сохранённую фазу; готовая STT сохраняется. Двойное нажатие не создаёт два задания. | not-run |
| M09 · Удаление во время обработки | На отдельной `UAT …` запустить summary, затем удалить запись: корзина и подтверждение в UI; на другой записи — «Удалить запись» и `ДА` в TUI. | Сначала останавливается обработчик, потом запись исчезает из архива и очереди. При отказе остановки файлы остаются и видна причина; позднее завершение worker не запускает отложенное удаление. | not-run |
| M10 · Выключение summary на ходу | Запустить ещё одну тестовую запись. В одном случае выключить summary до её старта, в другом — после начала; сохранить настройку. | Ещё не начатая summary пропускается. Уже работающая summary заканчивается; переключатель не обрывает текущий этап. Очередь и «Ход» объясняют оба исхода. | not-run |
| M11 · Запись на 1–2 часа | Добавить тестовый длинный материал. Сначала обработать без summary, затем проверить отдельно со summary на свежей тестовой записи. Сохранить длительности этапов и общее время. | Нет молчаливого зависания: видны работа, ожидание или причина остановки, прошлые длительности и дальнейшие шаги. Текст можно читать до готовности summary. Время материала отличается от времени обработки; универсального лимита «за N минут» нет. | not-run |

Если нужно проверить конфликт со сторонним CLI или отказ диска, использовать
отдельный технический стенд: [выполненные проверки BL-002](../openspec/changes/archive/2026-11-01-serialize-session-mutations/evidence/implementation.md).
Для обычной приёмки не требуется принудительно убивать процессы или блокировать диск.

## 4. Что записать по результатам

Для каждого M-ID заменить `not-run` на `pass` или `fail`; если пункт пропущен,
оставить `not-run` и указать причину. Приложить:

- Сборку: `git rev-parse --short HEAD`, профиль `release`; дату прогона.
- Windows/терминал, микрофон и устройство вывода, модели ASR/summary.
- M-ID, имя тестовой записи, действия, ожидаемый и фактический результат.
- Для ошибки — время, снимок UI/TUI и соответствующий участок «Ход»/лога демона;
  для медленного этапа — его длительность и последнюю операцию.

После проверки закончить тестовую запись, вернуть исходные настройки и штатно
закрыть тестовый демон. Обычный архив запускать прежней командой.

Отдельно остаются воспроизведение исходного зависания shutdown и проверка конкретной
старой подписи участника в пользовательском архиве. Этот прогон их не закрывает.
Автотесты и замеры уже описаны в evidence; ручные `pass` по ним не проставляются.
