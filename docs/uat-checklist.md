# UAT-чеклист — ручная приёмка пачкой

> Копится по мере разработки; после прогона помечай ✅/❌ и комментарий — по ❌
> заводятся фиксы. Все сценарии — на свежем `cargo build --release`.

## Подготовка
- [ ] `slots.toml` в корне (пути на свой vault), активаторы «запиши», «запомни», «отметь мысль» включены.
- [ ] Запуск `.\target\release\localvox-light.exe`; в Debug-панели строка `voice: активаторы […] · слоты: … · TTS sapi`.

## Загрузка и очередь (WP-B1 + полоска)
- [ ] При старте статус: `Загрузка модели Vosk [██████░░░…] N с из ~M с` (первый раз — «первый запуск», второй — с оценкой времени).
- [ ] После загрузки — «Запись — модель загружена за N с».
- [ ] Очередь WAV в статусе — 0 или около (старые файлы доварились один раз); в корне `localvox-audio/` НЕ появляются новые `src0_*.wav`.
- [ ] Чанки пишутся: `localvox-audio/sessions/<новая>/audio/src0_chunk0001.wav` растёт.

## Голос: базовые команды (WP-B2)
- [ ] «запиши в идеи попробовать новую схему» → статус `● заметка [идеи] …` → пауза 4 с → `✓ записано…` + голос «Готово, записал…» → строка в файле слота.
- [ ] Многосегментная: «запиши в идеи первая часть» → пауза 1–2 с → «и вторая часть» → «всё» → В ФАЙЛЕ ОДНА заметка «первая часть и вторая часть».
- [ ] Стоп-слово не попадает в текст заметки.
- [ ] «запиши» (без текста) → голос «Слушаю…» → фраза → «всё» → записано; если молчать 20 с — статус «заметка отменена: тишина», записи нет.
- [ ] «запомни поменять кран» → пауза → заметка в «идеи» (жёсткий слот; «в идеи» говорить не надо).
- [ ] «отметь мысль про воду» → отдельный md-файл в папке «входящие».
- [ ] Падежи: «запиши в идею тест-падежа» → слот «идеи» (не default).
- [ ] «запиши в слот покупки хлеб» → голос «Не знаю слот покупки», записи нет.
- [ ] Новая команда посреди диктовки закрывает предыдущую заметку (обе записаны раздельно).
- [ ] Эхо: подтверждение «Готово…» из колонок НЕ порождает новую заметку/команду.
- [ ] Индикация: счётчик фраз в статусе растёт по мере диктовки.

## Ретро-режим (WP-B2, «запиши это»)
- [ ] Включи любой ролик в колонки на ~15 с → скажи «запиши это» → в default-слоте текст сказанного из ролика (+ твои реплики, если были).
- [ ] «запиши это в идеи» → то же, но в слот «идеи».
- [ ] «запомни это» → последние 30 с в слот «идеи» (жёсткий слот команды).
- [ ] Сразу после запуска в тишине «запиши это» → голос «Нечего записывать…», записи нет.
- [ ] «запиши это надо сделать» → обычная заметка «это надо сделать» (не ретро).
- [ ] Подтверждения ассистента («Готово…») в ретро-захват не попадают.

## Надёжность захвата (WP-B5)
- [ ] Замьютить микрофон физически/в ОС на ~20 с при записи → статус-предупреждение «микрофон молчит…»; после размьюта — «микрофон снова слышен».
- [ ] (Если есть второй микрофон) выдернуть основной: захват переключается на fallback из `LOCALVOX_LIGHT_MIC_FALLBACKS`, предупреждение в статусе; воткнуть обратно — работает дальше (вернуть основной можно через F2).
- [ ] Спровоцировать совпадение: выбрать в качестве микрофона устройство вывода → предупреждение «микрофон совпадает с устройством вывода».

## MCP-сервер архива (F6)
- [ ] Подключить к Claude Code: `claude mcp add localvox -- D:/rust_repo/localvox-light/target/release/localvox-mcp.exe --work-dir D:/rust_repo/localvox-light/localvox-audio`
- [ ] В Claude спросить: «найди в моих записях localvox всё про <тема недавней сессии>» → агент вызывает search_transcripts и цитирует с именем сессии/таймкодом.
- [ ] «покажи протокол последней сессии» → list_sessions + get_summary.
- [ ] «запиши в мои идеи: <текст>» → append_note → строка в vault-файле.

## HTTP API (F6)
- [ ] `localvox-api.exe` → `curl http://127.0.0.1:3017/api/sessions` — список сессий JSON.
- [ ] `curl "http://127.0.0.1:3017/api/search?q=<слово>"` — результаты с сессией/таймкодом.
- [ ] `curl -X POST http://127.0.0.1:3017/api/notes -d "{\"text\":\"из http\"}"` — заметка в default-слоте.
- [ ] `localvox-api --bind 0.0.0.0:3017` без токена → отказывается стартовать.

## Refined-версия и CLI версий (WP-C9)
- [ ] `localvox-process <сессия> --refine` (Ollama поднят) → появляется `vNNN-refined.jsonl`, в `--list-versions` она помечена `*best`, parents=[001].
- [ ] Число реплик в refined == сырой версии; таймкоды совпадают (плеер/поиск не разъезжаются).
- [ ] Поиск и экспорт после refine отдают причёсанный текст (best переключился автоматически).
- [ ] `--set-best 1` возвращает сырой как рабочий; `--set-best 2` — снова причёсанный.
- [ ] Повторный `--refine` на уже причёсанном best → «best уже причёсан» (идемпотентно), `--force` — переделать.

## Семантический поиск (WP-C11)
- [ ] `localvox-search --semantic "запрос по смыслу"` (Ollama поднят) → находит фрагменты БЕЗ дословного совпадения слов; первый прогон строит индекс.
- [ ] Веб-архив: селектор «по смыслу» рядом с поиском → результаты осмысленные; «гибрид» мешает точные и смысловые.
- [ ] Перевари/refine сессию → семантический индекс сам переиндексирует её при следующем поиске (лог «semantic: сессия … проиндексирована»).
- [ ] Останови Ollama → «точный» режим работает как раньше; «по смыслу» даёт понятную ошибку, не вешает страницу.

## F5-роутинг «куда занести» (WP-C10)
- [ ] Веб-архив, вкладка «Заметка»: напиши текст → кнопка 🧭 → появляются чипы подходящих слотов; клик по чипу заполняет поле «Слот».
- [ ] Предлагаются только реальные слоты из slots.toml (не выдуманные).
- [ ] `curl -X POST /api/route -d '{"text":"..."}'` (через UTF-8 файл) возвращает `suggestions` с именами слотов.
- [ ] Добавь `description` слоту в slots.toml → подсказки станут точнее.
- [ ] Ollama выключен → 🧭 показывает ошибку (таймаут), API остальными эндпоинтами продолжает отвечать (не завис).

## Плеер (WP-C8)
- [ ] Открой сессию в веб-архиве → вкладка «Транскрипт»: на каждой строке кнопка ▶; нажми → слышен именно тот фрагмент (с таймкода строки).
- [ ] Клип через границу чанков (строка около 5-минутной отметки при chunk_sec=300) звучит без щелчка/обрыва.
- [ ] Сессия, у которой аудио удалено по retention → ▶ даёт «нет аудио», не крешит.

## Хвосты (WP-C13)
- [ ] Убей демон во время записи (taskkill /f) → при следующем старте восстановленный чанк ВИДЕН плееру (▶ на строке транскрипта этого куска играет).
- [ ] В веб-архиве найди что-то → ▶ прямо на карточке результата играет фрагмент (без захода в сессию).
- [ ] Строка статуса в вебе показывает «⚙ варится …» пока автоварка работает; `curl /api/jobs` отдаёт состояние очереди.
- [ ] Открой веб с телефона → браузер предлагает «Установить приложение» (PWA-манифест).
- [ ] Поиск «по смыслу» находит абзацы из summary.md, не только реплики транскрипта.
- [ ] `LOCALVOX_LIGHT_AUTOCOOK_REFINE=1` + выключенная Ollama → сессия всё равно сварена (транскрипт есть), в логе «варка ок, пост-обработка не удалась».

## Автопилот целиком (WP-C12)
- [ ] `LOCALVOX_LIGHT_CHUNK_FLAC=1`: запиши сессию → чанки в .flac → автоварка её варит (транскрипт появляется), плеер играет.
- [ ] `LOCALVOX_LIGHT_AUTOCOOK_REFINE=1` (+Ollama): после автоварки у сессии появляется v002-refined как best — без ручного запуска.
- [ ] После автоварки поиск (точный и «по смыслу») сразу находит новую сессию без паузы на индексацию (индексы прогреты фоном).
- [ ] Запусти и сразу заверши демон без звука → мусорного пустого каталога сессии не остаётся.

## Автоварка (WP-C7)
- [ ] Запусти демон `--daemon`, запиши сессию, подожди >quiescent (60с) + интервал → в `sessions/<...>/transcripts/` появляется версия БЕЗ ручного `localvox-process`.
- [ ] Появляется `<work_dir>/jobs.json` с джобом сессии в состоянии `Done`.
- [ ] Убей демон во время варки → при перезапуске джоб снова берётся (`Running`→`Pending`), сессия доваривается.
- [ ] `LOCALVOX_LIGHT_AUTOCOOK_SUMMARY=1` → у сваренной сессии появляется и `summary.md`.
- [ ] `LOCALVOX_LIGHT_AUTOCOOK=off` → автоварки нет, только ручная.
- [ ] Во время активной записи автоварка НЕ трогает текущую сессию (пишущуюся); файл `<work_dir>/.recording_session` содержит её имя.
- [ ] Одновременный ручной `localvox-process <та же сессия>` при работающей автоварке не плодит дубль-версий (сериализуется `.cook.lock`).

## Ambient-сессионизация (WP-C6)
- [ ] Начни звонок → в `sessions/` появляется отдельный каталог `<время>_call-<окно>`, а не пометка в текущей сессии.
- [ ] В meta.json сессии звонка — блок `meetings`; первый чанк длиннее живого звука на ~pre-roll (начало «до» детекта на месте).
- [ ] Заверши звонок → создаётся новая ambient-сессия, у встречи проставлен `ended_at`.
- [ ] `LOCALVOX_LIGHT_SESSION_GAP_SEC=60`, помолчи >60 с → следующая речь пишется в новую ambient-сессию.
- [ ] Обычный короткий прогон без звонков — по-прежнему одна сессия.

- [ ] Во время звонка нажми паузу и возобнови — встреча не закрывается преждевременно, её `ended_at` ставится по реальному концу звонка.
- [ ] Заверши звонок и помолчи — пустой ambient-каталог НЕ появляется; `localvox-process` не падает на пустых сессиях («пустая сессия — пропуск»).

## Детект звонков (WP-C4)
- [ ] Во время записи начни звонок в любом мессенджере (или включи запись голосового в браузере) → статус `☎ звонок: <app.exe> — <заголовок окна>`.
- [ ] Заверши звонок → через ~5 с статус `☎ звонок завершён (~N мин)`.
- [ ] В `meta.json` сессии — блок `meetings` с приложением, заголовком окна и временами.
- [ ] Свой localvox микрофоном звонок не триггерит (сам себя не детектит).

## Веб-архив и автостарт (WP-C5)
- [ ] Запусти `--daemon` → в трее «Открыть веб-архив» → браузер открывает страницу localvox: список сессий реального архива.
- [ ] Поиск на странице находит то же, что `localvox-search` в консоли; клик по результату открывает сессию, вкладки Транскрипт/Протокол/Причёсанный работают.
- [ ] Вкладка «Заметка» → текст + слот «идеи» → появляется в твоём vault (тот же путь, что и голосовые заметки).
- [ ] С телефона (тот же Wi-Fi): `LOCALVOX_API_BIND=0.0.0.0:3017` + `LOCALVOX_API_TOKEN=...`, открой `http://<ip>:3017/` → без токена данные не грузятся, после ввода токена (🔑) — всё работает.
- [ ] Трей: «Автозапуск при входе» → галка появляется; перелогинься/перезагрузись → localvox сам поднялся в трее; выключи — галка исчезает, после перезагрузки не стартует.

## Ревью-фиксы фазы C
- [ ] Открой в браузере любой внешний сайт, из его консоли: `fetch('http://127.0.0.1:3017/api/notes',{method:'POST',body:'{\"text\":\"csrf\"}'})` — должен вернуть 403, заметка НЕ появляется (защита от CSRF на дефолте без токена).
- [ ] `curl -H "Host: evil.com" http://127.0.0.1:3017/api/sessions` → 403 (защита от DNS-rebinding).
- [ ] Запусти второй экземпляр с тем же рабочим каталогом — отказ «каталог уже занят», первый продолжает писать.
- [ ] Трей: «Пауза» → пункт меняется на «Продолжить запись», тултип — «localvox — ПАУЗА»; повтор — обратно.
- [ ] Займи порт 3017 и запусти --daemon — в консоли явное «HTTP API не запущен», запись работает дальше.

### Фоновый режим headless на mac/linux (WP-C90)

- [ ] `./localvox-light --daemon` без трея → в логе `daemon — interface at http://127.0.0.1:3017/` и `archive at …`.
- [ ] Открывается `http://127.0.0.1:3017/` в браузере — список сессий реального архива.
- [ ] Запиши сессию, подожди quiescent+интервал → версия транскрипта появляется БЕЗ ручного `localvox-process` (nice(5): варка уступает записи по CPU).
- [ ] `./localvox-light --doctor` → 8/8 зелёных, код 0; на сломанной установке — «НЕТ»/«ЖДЁТ» и код 2.
- [ ] Останов по Ctrl+C и по SIGTERM (`kill`) → процесс выходит, недописанный кусок закрыт, повар не осиротел.
- [ ] `curl "http://127.0.0.1:3017/api/health?token=..."` с чужого адреса — 401 (токен в query больше не принимается, только заголовок Bearer).
- [ ] Store-приложение (например Teams из Microsoft Store) в звонке — детект тоже срабатывает.

## Качество варки и диагностика (WP-C14/C15)
- [ ] `meta.json` свежей сессии: у каждого чанка есть `rms` и `voice_ratio`.
      Норма: тихая речь RMS ≈ 200–400, обычная ≈ 1000–3000, тишина ≈ 0;
      разговор с паузами voice_ratio ≈ 0.1–0.3, лекция ≈ 0.5+.
- [ ] Наговори минуту в микрофон с паузами → после варки транскрипт **читаемый**
      (а не «овори г минукауроверяето»). Если каша — сверься с RMS в мете.
- [ ] Сессия, сваренная старой сборкой: запусти демон → в логе «переварка …:
      версия v001 сварена другим рецептом» → появляется новая версия, `best`
      переезжает на неё, поиск отдаёт новый текст. Повторный цикл — тишина
      (переварка ровно один раз).
- [ ] `localvox-process <сессия>` дважды подряд → второй раз «уже есть vNNN»
      (идемпотентность не сломана рецептом).
- [ ] Бенчмарк: `localvox-bench fetch --dataset golos-crowd` →
      `localvox-bench wer bench/golos-crowd/manifest.jsonl` → WER ≈ 7–8 %
      (сильно выше — регрессия движка или окон).
- [ ] `localvox-bench sweep bench/lf-sparse/longform.jsonl --windows 30:15,180:150`
      → на 180/150 WER катастрофический (≈ 90 %), на 30/15 — единицы процентов.

## Честность LLM (WP-C16) — самый опасный класс дефектов
- [ ] Запиши сессию, где ты просто напеваешь / молчишь → варка проходит,
      **summary.md не появляется**, в логе `llm: пропущено — речи слишком мало`.
      Протокол, выдуманный из тишины, — блокер релиза.
- [ ] Реальный разговор (≥ минуты связной речи) → протокол появляется, и в нём
      **нет ни одного имени/срока/числа, которых не звучало**.
- [ ] Открой протокол в вебе → кнопка «Копировать» кладёт текст в буфер.
- [ ] Открой «Читаемый текст» у сессии без него → внятная подсказка с командой
      `--cleanup` (а не `--summary`, который его не создаёт).
- [ ] Живая сессия в списке архива помечена «● идёт запись», а не «не сварено».
- [ ] `localvox-bench llm --models qwen3.5:4b --sessions <реальная>` → на ловушке
      «не выдумала», на реальной «разобрала», выдуманных чисел 0.
