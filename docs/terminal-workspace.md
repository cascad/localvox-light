# Терминальное рабочее пространство

После установки команда **`vox`** открывает TUI и запускает демон, только если
локальное API не работает. Уже работающий демон используется повторно. Перезапусти
терминал после регистрации PATH; portable запуск — `.\vox.exe` / `./vox` из папки
установки. Настройки берутся из этой папки. Обычный выход закрывает клиент.
Чтобы завершить и демон: F2 → «Завершить LocalVox», проверить адрес, ввести `ДА`
и нажать Ctrl+S / Ctrl+Enter. Запись закроется; очередь продолжится при следующем
запуске. Клиент ждёт результат. Ошибка или потеря ответа остаётся в консоли ошибок,
клиент не закрывается автоматически; Esc в подтверждении отменяет полный выход.
`vox --check-command` проверяет доступность команды без изменений.

Новый клиент разрабатывается в `localvox-light-terminal`, HTTP-граница — в
`localvox-light-client`. Старый engine-связанный TUI удалён. План и матрица действий:
[change](../openspec/changes/add-technical-journal-workspace/proposal.md).

Сборка отдельно от capture/ASR:

```powershell
cargo check -p localvox-light-client -p localvox-light-terminal
cargo tree -p localvox-light-terminal
cargo run -p localvox-light-terminal --bin localvox-tui -- --address http://127.0.0.1:3017
```

API-токен передаётся через `LOCALVOX_API_TOKEN`, адрес — `--address` либо
`LOCALVOX_TUI_URL`. В argv токен не передаётся. Клиент не открывает архив напрямую
и не загружает модели. `localvox-light --tui` и интерактивный запуск делегируют
соседнему `localvox-tui` до проверки моделей и создания engine. `--daemon` и
`--no-tui` сохраняют серверный режим; capture-параметры относятся к запуску сервера.
Запуск рабочего демона не нужен для unit-тестов.

Диспетчер клиента находится в `src/app/commands.rs`: Action задаёт смысл действия,
COMMANDS — статический порядок и подписи палитры. Хоткеи и F8/F9 передают Action,
а индекс используется только для курсора меню. При добавлении пункта обновляйте
каталог и обработчик; перестановка строк не должна менять привязки клавиш.

Комплект из исходников собирается и запускается так:

```powershell
./scripts/run.ps1 -Tui
./scripts/run.ps1 -Tui -Profile dev -BuildOnly
```

`-Desktop` и `-Tui` несовместимы. `BuildOnly` собирает демон, worker и клиент,
но ничего не запускает. Пути берутся из сообщений Cargo, включая custom target-dir;
при ошибке сборки или неполном комплекте старые бинарники не запускаются.
В release новый клиент — `localvox-tui[.exe]`; руководство и installer mpv включаются
в архив. Без mpv остаются доступны документы и остальные действия.

Перед первым чтением архива клиент проверяет авторизованный `/api/health`:
`service=localvox-light`, `api_protocol=1`, capabilities `technical-journal-v1`
и `terminal-workspace-v1`. Сторонний/старый API и 401/403 показывают ошибку;
до успешной проверки пользовательский материал не отправляется.
Если локальный HTTP адрес отказал в соединении, клиент один раз запускает соседний
`localvox-light --daemon` без видимого окна на Windows и ждёт API не дольше 15 секунд.
Timeout, чужой ответ, удалённый адрес и HTTPS не запускают локальный демон.
Проверка выполняется в фоне, терминал можно закрыть. Повторное подключение через
палитру только проверяет адрес/токен и не повторяет запуск либо прежние POST/DELETE.
Запущенный демон живёт после закрытия TUI.

Обновляется весь комплект. Если старый демон уже работает, новый клиент сообщит
о несовместимом API: штатно перезапустите демон после обновления. Restart клиента
его не заменяет. Откат — целый предыдущий release в отдельной папке; смешивать старый
демон и новый клиент не нужно. В этом изменении пользовательский архив и установленный
демон не переносились и не перезапускались. Старый TUI доступен для справки в истории Git.

Рабочие разделы: архив, заметки, очередь, «Спросить», настройки, поиск и чат.
На широком терминале видны список, документ и контекст; на 80×24 клавиша Tab
переключает активную панель. Версии/best, исходный STT, служебные сведения и
ошибки доступны отдельно от чистого текста копирования.

Очередь сохраняет порядок сервера, включая несколько активных линий и причину
failed/stuck. Enter открывает «Ход» выбранной задачи. Повторы «сводка», «текст» и
«всё» — разные действия палитры с явным подтверждением. Text/Summary используют
сохранённую расшифровку и не требуют оставшегося аудио; полный повтор требует его.
API отказывает изменениям, если сессию держит worker, до инвалидирования результатов.

`R` (Shift+r) вне форм и пункт палитры «Повторить или продолжить этап» возобновляют
Failed или Cancelled с сохранённой фазы. В очереди используется выбранная строка, в архиве —
открытая запись. Эта команда сохраняет готовые файлы/квитанции и не требует аудио
для повторения summary или ещё не скачанного ingest. До ответа повторное нажатие
заблокировано. Готовый текст остаётся видимым, поздние ответы предыдущей попытки
не меняют новый прогресс. Для полной переработки остаётся отдельное «Повторить всё».
[Проверки](../openspec/changes/resume-failed-processing/evidence/implementation.md).

В документе выбранной задачи очереди указаны фаза, число попыток, причина и
«Повтор не раньше». `~ повтор` в списке — ожидание автоматического повтора,
`? повтор` — координатор не подтверждает возможность запуска. При старом API
неизвестные фаза/срок отмечены словами. У исчерпанного бюджета остаётся ручной
повтор; новая дата не выдумывается. [Проверки](../openspec/changes/explain-automatic-retry-state/evidence/implementation.md).

Версии и best видны в сведениях документа. «Выбрать версию» принимает её ID и сам
не запускает LLM. Переименование участника относится только к текущей записи,
охватывает все его голоса и источники и сохраняет речь/таймкоды. Имя источника
можно сбросить пустым полем. Изменение языка требует полной переработки; сервер
проверяет доступность исходного аудио/модели перед инвалидированием.

`X` (Shift+x) вне форм отменяет обработку выбранного задания очереди или открытой
записи архива; то же действие — «Отменить обработку» в палитре. Пока обработчик
останавливается, видна остановка, затем отмена; готовые результаты остаются доступны.
Отмена не останавливает запись аудио и не возобновляется автоматически после перезапуска.
Сторонний CLI без управления нужно остановить отдельно.

### Своя раскладка команд

Без настройки работают штатные RU/EN сочетания. Для другой раскладки скопируй
[пример](examples/tui-keymap.json) и укажи соответствия: слева символ, который
приходит из терминала, справа — штатная командная клавиша (`y`, `j`, `/` и т. п.).

```powershell
.\target\release\localvox-tui.exe --keymap D:\my-config\localvox-keys.json
```

Для постоянного выбора файла можно задать `LOCALVOX_TUI_KEYMAP`. Прописная буква
наследует Shift-вариант команды; явное соответствие для неё имеет приоритет.
Переназначение действует также с Ctrl и в `qq`; формы, поиск и обычная вставка
сохраняют исходный текст. Ошибочный файл отклоняется до запуска клиента.
Терминал должен доставить нажатие: поглощённую оболочкой клавишу конфиг не восстановит.
Это настройка символов, а не определение физической клавиши во всех терминалах.

Клавиши:

- В списке архива нажми `/`, затем печатай имя: фильтр применяется сразу без учёта регистра.
  Вне ввода j/k (о/л в RU) и ↑/↓ выбирают, Enter открывает. `/` (точка в RU) включает поиск; второй `/`, j/k и другие буквы вводятся буквально. Backspace удаляет символ, Ctrl+U очищает запрос, Esc очищает и выходит из поиска.
  Ввод не переключает открытый документ и звук. После Enter/Tab ввод завершается, запрос остаётся; новый `/` продолжает его. Esc вне ввода возвращает в меню, сохраняя запрос; `/` → Esc очищает его. F2 открывает действия, F10/Ctrl+Q закрывают клиент. Командные клавиши работают в RU/EN: `g`/`п`,
  `/`/точка на русской клавише Slash; текст в фильтре и формах не преобразуется.
- Page Up/Down перелистывают сфокусированный список или документ на одну видимую
  страницу, включая переносы строк и изменение размера окна. Список не открывает
  запись сам. В журнале это ручное чтение; End возвращает следование хвосту.
- Значок у записи: змейка — обработка, `◷` — очередь, `◦` — ждём кусок,
  `✓` — готово, `!` — ошибка, `■` — отменено. При одновременной записи видна
  подпись «запись». Фаза/позиция очереди указаны, когда известны. Цвет не обязателен:
  ASCII/no-color сохраняют подписи; ошибка обновления даёт неподвижный `?`.

- Tab / Shift+Tab — фокус, стрелки / j k — выбор, Enter — открыть.
- Esc закрывает верхнюю форму/консоль/справку, затем возвращает из деталей в список,
  из списка — в меню. Из плеера — к деталям. Из записи, открытой поиском/очередью,
  возврат ведёт к тому же результату/заданию; звук продолжается. В заметках Enter
  переводит из списка слотов в детали.
- 1–5 — вкладки документа, `:` — палитра всех действий, `?` — справка.
- F8 — stop записи, F9 — форма начала.
- `qq` / `йй` за полсекунды вне ввода, F10 из любого экрана или Ctrl+Q — закрыть
  только клиент; демон и запись продолжают работать. Другая клавиша/вставка
  отменяет первое q. В форме и фильтре q остаётся текстом.
- `y` / `н` в «Репликах» копирует только текст выбранной строки без имени и времени;
  в «Сводке» — текст выбранного блока; в «Тексте» — весь текст, включая часть вне экрана.
  Ctrl+Y / «Копировать документ»
  копирует весь текущий документ. В форме эти буквы остаются текстом.
  В графическом UI для вкладки «Текст» — Ctrl+Shift+C.
- `i` — импорт: вставить ссылку YouTube / HTTP(S), нажать Enter. Ctrl+Enter тоже
  работает; одна вставка ничего не отправляет.
- В текстовой форме Tab меняет поле, Enter вставляет строку, Ctrl+Enter / Ctrl+S
  отправляет, Esc отменяет. В импорте, настройке и переходе ко времени Enter
  подтверждает. Многострочная вставка не запускает буквенные команды.
- В заметке Ctrl+R предлагает слот; выбор назначения и отправка остаются явными.
- В журнале Enter / стрелки раскрывают блок, `/` фильтрует, PgUp/Home останавливают
  слежение, End возвращает хвост, `o` загружает предыдущие события.
- В начале «Ход» сведения о записи свёрнуты. `I` или «Сведения о записи» раскрывают
  ID, источник, версию, модель и источники звука. В копируемых документах их нет.
- Space — play/pause, `p` — выбранный фрагмент, `g`/`п` — переход по времени
  через три поля часов/минут/секунд; Tab меняет поле, ↑/↓ меняют число,
  Enter подтверждает. Минуты/секунды 0–59, итог не больше длительности записи.
  Alt+←/→ перемещает на 15 секунд.
- F6 передаёт стрелки постоянной полосе аудио: ←/→ перемещают на 5 секунд, Home/End —
  к границам. Перемотка снимает границу фрагмента и сохраняет паузу без нового load.
  F6 или Tab возвращают управление документу. `▶` / `‖` обозначают воспроизведение/паузу
  (`>` / `=` в ASCII); их ширина одинакова. В формах буквы и пробел остаются текстом.
- В настройках сначала видны основные параметры, `A` показывает все; `/` ищет
  по всему каталогу. Enter открывает редактирование. Для переключателей, устройств
  и провайдеров ↑/↓ выбирают вариант, Enter подтверждает, «По умолчанию» сбрасывает
  явное значение. `S` сохраняет. Палитра позволяет отменить несохранённые правки.
- В ответе «Спросить» Enter раскрывает исходный материал. Сбой отмечен отдельно
  от ответа; его причина доступна в консоли, даже при пустом answer.

Настройки разделяют «значение / применение / пояснение» короткими внутренними
засечками. Значения берутся из `.env.defaults`; рядом виден источник предустановки
или своего значения из `.env`. Подсказка не становится значением.
Изменения сначала попадают в локальный черновик, отмеченный `*`. `S` или действие
палитры сохраняет только изменённые ключи; ошибка сохраняет правки. `need_restart`
показывается явно. Snapshot-настройки, включая модель/провайдер/инструменты и
основной autocook, требуют перезапуска демона. Исключение — существующий переключатель
summary в группе «После распознавания». Транскрибация обязательна, затем опциональная
сводка; автоматических refine/cleanup больше нет, старые env-флаги их не включают.
Ручные очистка/повторы сохраняются. Если processed.json отсутствует, «Текст» показывает
ту же исходную расшифровку единым текстом с переносами по ширине, без заголовков
реплик, имён, таймкодов и добавленных диалоговых тире. Имена и таймкоды остаются
во вкладке «Реплики». Подпись источника не попадает в копию; модель не вызывается,
файл очистки не создаётся. Существующая ручная очистка сохраняет своё оформление.
Переключатель сводки применяется к следующим автоматическим этапам; текущий LLM-этап
сохраняет результат. Старые jobs без follow_settings и ручные запросы сохраняют флаги.
В схеме видны текущая фаза/этап с таймером, следующие шаги, длительности завершённых
этапов, ожидание worker/повтора и состояние координатора. Неизвестное время обозначено
явно. Старое Running без актуального задания не изображает живой процесс.
Сервер отдаёт неизвестные settings.extra только как key/set; клиент также отбрасывает
extra.value старого сервера (RV-010).

Если сводки нет, оба клиента показывают «Сводка ещё не создана», а готовый «Текст»
остаётся доступен. Это не ошибка обновления данных и не предложение запускать CLI.

### Локальная Ollama

В основных настройках выбрать провайдер сводки `Ollama`, адрес
`http://localhost:11434/v1` и имя уже установленной модели, затем сохранить и
штатно перезапустить демон. Перезапуск одного TUI эти параметры не применяет.
Для текущей установки проверена модель `qwen3.5:9b`; ключ локальной Ollama не нужен.
Адрес выбирается из сохранённого списка. `N` в настройках или «Добавить LLM-сервер»
в палитре открывает добавление HTTP(S) URL; Enter помещает адрес и выбор в черновик,
`S` сохраняет. Список хранится в `LOCALVOX_LLM_SERVER_URLS`, активный адрес — отдельно
в `LOCALVOX_LLM_BASE_URL`. До сохранения запрос модели не отправляется. URL не должен
содержать логин/токен; модель и авторизация остаются отдельными параметрами.
Список установленных моделей можно посмотреть через `ollama list`.
Адрес использует [OpenAI-совместимый API Ollama](https://docs.ollama.com/api/openai-compatibility).

### Предустановки настроек

Предустановки каталога находятся в [.env.defaults](../.env.defaults). Файл читается
рядом с пользовательским `.env`, затем из cwd; если обоих нет — берётся та же копия
из комплекта. Пустые машинные пути/устройства означают явный режим автоматического
выбора; это сохраняет прежний выбор устройства. Пользовательские значения и CLI
сильнее предустановок. Изменение самого файла предустановок требует перезапуска;
сброс через UI/TUI применяется по сроку конкретного параметра. Секреты задаются в `.env`.

### Консоль ошибок

`~` / `ё` вне формы или `F12` в любом экране открывают нижнюю консоль. Снаружи
виден только индикатор непрочитанных ошибок и состояние недоступного результата.
Открытие гасит индикатор, история остаётся. Запись содержит время (UTC, `Z`),
источник, операцию, сессию и известный этап; неизвестный этап так и подписан.
Одинаковые отказы одного этапа свёрнуты в `+ N повторов` со временем последнего.
`Tab` / `Shift+Tab` выбирают событие, Enter раскрывает повторы, ↑/↓ и PgUp/PgDn
прокручивают, `y` копирует историю, Esc закрывает. F8 продолжает останавливать запись.

Продолжающийся опрос с тем же отказом не зажигает индикатор снова. Новый сбой после
восстановления или новая явная неудачная команда дают новое уведомление. История
живёт до закрытия TUI: до 128 эпизодов, до 32 времён повторов на эпизод.
Ошибки заполнения формы остаются рядом с полем.

Палитра позволяет сменить адрес/токен. Токен скрыт в редакторе; пустой ввод сохраняет
прежний, отдельное поле очищает его. Переподключение не повторяет POST/DELETE.
При ошибке действия его форма восстанавливается; если уже открыта другая, исходный
черновик доступен через «Восстановить черновик после ошибки» (до восьми последних).
Это также действует при заполнении очереди запросов. Последние запросы поиска и чата
можно открыть для правки; они не переотправляются сами.

В поиске доступны lexical, semantic и hybrid. Ответ показывает исходный запрос,
причину совпадения и доступный score; ожидание, пустой результат и ошибка различаются.
Enter на найденной реплике или источнике чата открывает её сессию и выделяет строку
по timecode. Прослушивание запускается отдельным действием «Слушать фрагмент».
Чат показывает проверенность ответа и источники; ошибка поиска не означает «не найдено».

Новая заметка использует явно введённый слот либо серверный слот по умолчанию.
«Предложить слот» показывает причину и допустимое назначение, но ничего не записывает:
назначение выбирается в форме заметки. Изменение текста убирает устаревшую подсказку.
Ошибка доставки сохраняет текст и слот. Нечитаемое назначение отличается от пустого.
Удаление передаёт исходные raw/source и выбранный слот. Серверный local-first/outbox
остаётся отдельным незавершённым обязательством NOTE-004/RV-007.

I/O ограничен пятью потоками: один для start/stop/состояния записи, один для документов,
один для действий и два для модельных запросов/peaks. Долгая модель не занимает очередь
документов или stop. Ответы покинутого контекста отбрасываются, его ещё не начатые
задания чтения не выполняются. Неудачный peaks повторяется с задержкой 30 секунд.
Пустой ранний ответ до появления аудио повторяется через 5 секунд; новая длительность
записи снимает это ожидание. Пока peaks нет, остаётся шкала позиции. Ошибка загрузки
волны отправляется в консоль и не блокирует звук или чтение текста.
JSON-запросы нового клиента используют `Connection: close`: дешёвый stop не зависит
от свободного keep-alive parser-потока при одновременных долгих ответах tiny-http.

«Спросить» принимает UTF-8 текстовый файл до 1 MiB и 400000 символов, снимает BOM,
сохраняет имя файла и выбранного provider. Ошибка чтения/размера происходит до POST.
Возврат в раздел читает тот же сохранённый запрос. Pending/running/done/failed,
ответ и ошибка доступны раздельно; Enter в документе раскрывает исходный материал.

Копирование использует системный clipboard. Сохранение создаёт новый UTF-8 файл
по указанному пути и отказывается перезаписывать существующий. Provenance,
сомнения, исходные исправленные строки и служебные подписи в копию не входят.
Подтверждение относится к открытому документу. Оно снимает сомнение в содержании
после проверки целостности и успешного сохранения отметки; checksum/I/O-ошибка
или занятый worker показываются как отказ. Повреждённый результат не становится ready
от одного пользовательского подтверждения.

## Плеер

Нужен mpv ≥0.38 с JSON IPC. Исполняемый файл ищется через `LOCALVOX_MPV`, рядом
с `localvox-tui`, в dev-каталоге `target/tools/mpv`, затем PATH. Установка для
Windows x64: `npm --prefix ui run setup:mpv`. Скрипт скачивает first-party build,
сверяет SHA-256 из GitHub release API и сохраняет provenance в target; пользовательский
PATH и системная установка не меняются. Остальные ОС используют свой пакет mpv.

Плеер принадлежит клиенту, закрывается с ним и не управляет демоном. Конфигурация,
скрипты и терминальные shortcuts mpv отключены; API-токен не передаётся в argv,
query или унаследованном LOCALVOX_API_TOKEN. Заголовок задаётся через частный IPC.
На Windows до передачи заголовка проверяются PID сервера и DACL pipe; на Unix
socket расположен в каталоге 0700. При отсутствии backend документы остаются доступны.
Отсутствие исполняемого файла, неподдержанная версия, сбой запуска/IPC и ошибка
аудио различаются в консоли. Общая надпись «нужен mpv» больше не заменяет любую причину.
Волна получается через API независимо от mpv; постоянный pre-roll из шапки убран.

Синтетическая media-проверка без звукового вывода:

```powershell
cargo test -p localvox-light-terminal --test media_playback -- --ignored --nocapture
```

Это проверка настоящих mpv/HTTP/Range/seek/fragment; она не подтверждает слышимость
на физическом устройстве. Общие проверки клиента: `cargo test -p localvox-light-client
-p localvox-light-terminal`; ConPTY проверяет настоящий binary, Unicode-вставку,
resize, открытие журнала, stop внутри редактора и выход без остановки новой записи
на синтетическом HTTP-сервере. Отдельная ConPTY-проверка восстанавливает raw mode,
bracketed paste и alternate screen после ошибки отрисовки.

Проверка настоящего API → mpv на временном часовом WAV:

```powershell
cargo test -p localvox-light-api media_http_range_plays --lib -- --ignored --nocapture
cargo test -p localvox-light-api flac_range_is_sample_accurate --lib -- --ignored --nocapture
```

Вторая команда требует ffmpeg. HTTP читает PCM окнами до 1 MiB вместо сборки всего
остатка WAV перед отправкой; FLAC декодируется для запрошенного интервала под надзором
process supervisor с timeout 30 секунд. Окно — предел буфера PCM, не измерение всего RSS.
Физические устройства этими проверками не используются.

Совместный сценарий browser + actual TUI на одном настоящем временном API:

```powershell
npm --prefix ui run build
cargo build -p localvox-light-terminal --bin localvox-tui
npm --prefix ui run test:integration
```

Требуется установленный Playwright Chromium. Обработка в этом сценарии заменена
явным synthetic producer артефактов/receipts; speech/LLM не запускаются. Сам HTTP,
архив, журнал, browser media decoder, notes/settings/asks, авторизация и ConPTY настоящие.
Проверены отказ записи PATH, 401/повторная авторизация, TUI reconnect/resize и quit
при продолжающем работать private API. Артефакты: `ui/test-results/cross-real-api/`
(`browser.png`, trace.zip, terminal.txt, terminal-notes.txt и ANSI capture).

Для Windows x64 release-комплект содержит `scripts/setup-mpv.mjs`:
`node scripts/setup-mpv.mjs` устанавливает проверенный SHA-256 официальный build
в `tools/mpv` рядом с клиентом (в исходниках — `target/tools/mpv`). Требуется Node.
На других платформах установите mpv ≥ 0.38 по инструкции
[проекта mpv](https://mpv.io/installation/) и задайте `LOCALVOX_MPV` либо PATH.
