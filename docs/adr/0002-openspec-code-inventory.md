# ADR-0002: OpenSpec сначала как описание фактического кода

Дата: 2026-09-27. Решение об организации: принято по указанию владельца.
Статус при исходном решении: **черновики**. Переход завершён 2026-09-27:
[принятый baseline](../../openspec/baseline.md) теперь определяет требуемое поведение.
Далее сохранена история исходного решения; она не отменяет новый статус.
Дополняет и заменяет организационную часть [ADR-0001](../specs/decisions/0001-specifications-in-git.md).

Владелец выбрал OpenSpec и уточнил: README и другие документы сейчас производные
от кода. Переносим не обязательства из README, а извлекаем действительную логику
из реализации, включая отказы, инварианты и угловые случаи.

`openspec/specs` содержит инвентаризацию по возможностям; `openspec/changes` —
предложения; `review.md` — вопросы сверки; `evidence` — ссылки и фактические результаты.
Дублирующие контракты в `docs/specs` заменяются навигационными указателями. Исторические
продуктовые планы остаются историей; руководства установки остаются в README.

Штатный синтаксис OpenSpec используется без собственного DSL. На стадии инвентаризации
нормативные слова в нём не означают согласия сохранить обнаруженный баг. Статусы
приёмки явные. После проверки и согласования OpenSpec станет источником правды;
принимать его автоматически в ходе миграции нельзя.

Цена: необходимо поддерживать ссылки на код/проверки и отдельно проверять семантику.
Плюс: стандартный формат, проверяемые сценарии, отдельные дельты предложений,
без внедрения ещё одного runtime-сервиса или тестового фреймворка.
