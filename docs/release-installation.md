# Установка полного комплекта

Пакет содержит демон со встроенным браузерным UI, `localvox-process`, `localvox-tui`,
`vox`, мастер `localvox-install`,
нативные библиотеки, `.env.defaults`, скрипты моделей и лицензии. На Windows/macOS
также собирается окно `localvox-desktop`. Рабочая `.env` при обновлении сохраняется.
Модели и дополнительные программы мастер готовит по выбранным возможностям.

Linux-комплекты рассчитаны на Ubuntu 24.04 или совместимую систему с её glibc.
Intel Mac требует macOS 13.3 или новее: ONNX Runtime той же версии собирается в CI
из закреплённых официальных исходников и включается в комплект. Пользователю
не нужно устанавливать SDK или Python для распознавания.

## Из Release

Команды предназначены для нового полного release. Пока он не опубликован,
использовать [архив Actions](#свежая-сборка-из-actions); старый v0.1.5 не подходит.

Windows PowerShell:

```powershell
irm https://github.com/cascad/localvox-light/releases/latest/download/install.ps1 | iex
```

macOS (Apple Silicon / Intel), Linux (x64 / ARM64):

```bash
curl -fsSL https://github.com/cascad/localvox-light/releases/latest/download/install.sh | bash
```

Мастер сначала скачает проверенный комплект во временную папку, затем покажет
рекомендуемый набор или галочки компонентов. `↑/↓` — фокус, Пробел — галочка,
Enter — дальше; Esc — назад/продолжить шаг/отменить. Перед установкой появится план.
Без подтверждения целевая папка, настройки и PATH не меняются.

Рекомендуемый набор включает обязательное распознавание, голоса участников,
сводки с Ollama, ссылки YouTube и плеер. Недостающие программы устанавливаются
автоматически через менеджер ОС; возможен запрос системного пароля. На Mac при
необходимости устанавливается Homebrew. Rust, Node, Python и заранее установленный
`jq` пользователю не нужны. Для TUI требуется mpv ≥ 0.38; на Windows он уже в комплекте.

Папка программы: Windows — `%LOCALAPPDATA%\Programs\LocalVox`, macOS —
`~/Applications/LocalVox`, Linux — `~/.local/share/localvox`. В выборочной установке
можно изменить её и папку весов. Выбранное место запоминается для следующего запуска.

После установки перезапустить терминал и ввести `vox`. Откроется TUI и при
необходимости запустится демон. Браузерный UI: http://127.0.0.1:3017/.

## Свежая сборка из Actions

Пока новый полный релиз не опубликован, скачать артефакт нужной платформы из
[Build binaries](https://github.com/cascad/localvox-light/actions/workflows/build-binaries.yml).
Распаковать внешнюю ZIP-обёртку GitHub: внутри будет `localvox-<target>.zip` для
Windows либо `.tar.gz` для Mac. Передать именно внутренний архив установщику:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-release.ps1 -Archive 'D:\Downloads\localvox-x86_64-pc-windows-msvc.zip' -InstallDir 'D:\LocalVox' -Wizard
```

```bash
bash scripts/install-release.sh --archive="$HOME/Downloads/localvox-aarch64-apple-darwin.tar.gz" --install-dir="$HOME/LocalVox" --wizard
```

Для Intel Mac имя содержит `x86_64-apple-darwin`. Установщик взять из клона или
из этой же ветки: [Windows](../scripts/install-release.ps1) / [Mac](../scripts/install-release.sh).
После публикации он также доступен командой выше. Helper scripts и manifest моделей берутся из самого
пакета, той же версии. `-SkipModels` / `--skip-models` устанавливает только бинарники
и явно сообщает, что перед записью ещё нужны модели. Старые релизы с одним EXE
полным комплектом не считаются. Установка новой версии требует закрыть старые
клиенты и демон после завершения записи.

Если внутренний архив уже распакован в окончательную папку, можно использовать
скрипт прямо из неё: `-InstallDir . -Reconcile` (Windows) или
`--install-dir="$PWD" --reconcile` (Mac). Он проверит комплект и откроет мастер,
сохранив готовые файлы.

CI проверяет целостность архива, doctor и отсутствие изменений у read-only команд.
Клавиши реального мастера проверяются через PTY/ConPTY с маленькими фиктивными
моделями. [Локальный стенд для трёх ОС](installer-testing.md) не устанавливает настоящие зависимости.

## Проверить или настроить повторно

После установки полностью перезапустить терминал и ввести `vox`: откроется TUI,
демон при необходимости запустится сам. Чужая команда `vox` не заменяется: при
конфликте установщик покажет её путь, LocalVox доступен как `.\vox.exe` / `./vox`
из установленной папки. Обычный выход из TUI оставляет демон работать.

Установщик по умолчанию добавляет каталог в пользовательский PATH. Для portable
режима передать `-NoPathUpdate` (Windows) / `--no-path-update` (Mac/Linux).
Проверка команды без записи — `vox --check-command`; повторная регистрация —
`vox --install-command` (до регистрации использовать путь из папки установки).
На Windows это user PATH без admin; Bash/Zsh/Fish используют startup config.
Пользовательские alias/functions оболочки сохраняют собственный приоритет.

Из папки установки:

```powershell
.\localvox-light.exe --setup-check
.\localvox-light.exe --setup
```

На Mac те же флаги у `./localvox-light`. `--setup-check` ничего не устанавливает,
не запускает серверы и не пишет файлы. `--doctor --doctor-json` выдаёт JSON schema 1
со стабильными ID компонентов; коды 0/1/2 означают готово/предупреждения/не хватает
обязательного. Проверка файлов не заменяет пробную запись и проверку качества модели.

В установленной папке можно также запустить `localvox-install` (`.exe` на Windows,
`./localvox-install` на Mac/Linux). «Сохранить текущий набор» проверяет готовность
выбранного ранее; «Выбрать компоненты» позволяет изменить галочки. В выборе папок
пункт «Указать готовые папки моделей» принимает отдельные Vosk/GigaAM и дополнительные
модели из разных мест. Они используются без копирования. Пустое поле — автоматический выбор.

`localvox-light --setup` настраивает текущую программу и её активную `.env`;
для переноса программы в другую папку использовать `localvox-install`.

Для сводки выбрать Ollama: мастер прочитает список установленных моделей без их
запуска. В источнике сводки доступны Ollama по имени модели, свой сервер и готовый
GGUF с новым именем. GGUF должен поддерживаться Ollama; импорт занимает место
в её хранилище дополнительно к исходному файлу. Существующее имя не заменяется.
Иной OpenAI-совместимый сервер задаётся адресом и именем модели; его API/авторизация
настраиваются отдельно. Снятая галочка сводки сохраняет транскрибацию.

Если локальной Ollama нет, мастер запустит официальный установщик, дождётся API
и скачает выбранную модель. Уже работающий сервер используется повторно;
место хранения его моделей сохраняется. При ошибке подробности запуска —
в `cache/ollama-start.log` рядом с программой.

Перед действиями будет план и пункт «Продолжить». Для изменений остановить демон:
мастер не меняет используемые им модели и настройки. Отмена ничего не меняет.
После сбоя повторить команду установки: сохранённый выбор появится для проверки,
готовые файлы и модели будут использованы повторно. Настройки применяются после
успешной подготовки компонентов; незавершённый план не становится рабочим конфигом.
Обычный повтор без нового выбора не скачивает модели и не переписывает `.env`.

Проверка через установщик (работает даже до первой установки):

```powershell
.\scripts\install.ps1 -Check
.\scripts\install.ps1
.\scripts\install.ps1 -Update
```

```bash
bash scripts/install.sh --check
bash scripts/install.sh
bash scripts/install.sh --update
```

Обычный повтор bootstrap сверяет manifest и SHA-256 установленного комплекта,
пропускает загрузку исправной версии, затем открывает мастер. `-Update` / `--update`
получает последний релиз; `-Tag v…` / `--tag v…` выбирает конкретную версию.
`-InstallDir` / `--install-dir` задаёт папку явно. Команды выше — из клона;
скачанный release bootstrap принимает те же параметры.

Совместимость старого `install-release` сохранена: `-Reconcile -SkipModels` /
`--reconcile --skip-models` проверяет только комплект; `-RequiredOnly` /
`--required-only` скачивает обязательные модели, `-SkipModels` / `--skip-models` —
только программу. По умолчанию модели скачиваются в `~/.localvox/models`
(Windows: `%USERPROFILE%\.localvox\models`). Новая стандартная папка на Windows
получает атрибут Hidden. Существующие папки и их атрибуты не меняются.

Явные пути моделей в `.env`/CLI имеют приоритет, затем используются существующие
`models` рядом с программой или в рабочей папке, затем пользовательская папка.
Уже готовые модели не переносятся и не скачиваются повторно. Если настроенный путь
неисправен, doctor покажет именно его; в мастере можно выбрать готовую папку или
загрузку. Хранилище Ollama не меняется.

`localvox-light --model-paths-json` показывает выбранные пути и их источники без
загрузки моделей и сетевых запросов. `fetch-models.ps1 -Check` /
`fetch-models.sh --check` проверяет наличие файлов без записи. Явный `-Root` /
`--root` по-прежнему задаёт `<root>/models`. Скрипт вне готового комплекта при
наличии `.env` требует явный root: конфигурацию безопасно читает бинарник LocalVox.

## Проверка Mac владельцем

До фактического прогона все пункты **not-run**. CI-сборка не заменяет эту проверку.

- Пройти мастер с уже установленной Ollama и повторить его: без повторного скачивания.
- На чистой установке проверить официальный установщик Ollama, pull модели и импорт GGUF; отменить план до действий.
- Установить подходящий архив в папку с пробелом в имени; выполнить `./localvox-light --doctor`.
- Запустить `./localvox-light --daemon`, открыть UI и TUI, проверить доступ к одному архиву.
- Разрешить микрофон и нужные системные разрешения; проверить доступность loopback и выбранного выхода.
- Записать речь и системный звук, дождаться первой готовой части, проверить стыки и прослушивание.
- Stop: дождаться полного текста; закрыть UI/TUI и убедиться, что демон остаётся доступен.
- В терминале демона нажать `Ctrl+C`, снова запустить его: завершённая запись доступна, лишняя обработка не начинается.

Автозапуск после входа в систему и аппаратный capture на Mac отдельно не объявлены
проверенными. Для бага указать архитектуру Mac, версию ОС, действие и этап из журнала.
