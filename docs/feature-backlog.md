# Бэклог фич localvox-light

> Статус: черновик для обсуждения, собираем фичи. Обновлён 2026-07-10.
> Контекст: анализ конкурента в `docs/competitors/summit-ai-notes.md`,
> карта локальных моделей под задачи — в `docs/local-models.md`.

## Видение

Локальный приватный **голосовой секретарь**: постоянно рядом, слушает (пока явно не
выключили), сам понимает, когда началась встреча, превращает речь в структурированные
заметки/задачи/конспекты, принимает голосовые команды и отвечает голосом. Всё офлайн
или через модульные LLM-провайдеры по выбору пользователя. Windows-first, CLI/TUI,
русский язык — first-class.

Отличие от Summit: они — пассивный рекордер со сводками для macOS; мы — интерактивный
ассистент (голосовые команды + TTS-ответ), кроссплатформенный ingestion (микрофон,
системный звук, YouTube, файлы), скриптуемый.

## Принципы данных

1. **Durability — фундамент, не регрессировать:** WAL/append-only транскрипт,
   at-least-once, crash recovery. Данные должны сохраняться надёжно.
2. **Первичные данные неприкосновенны.** Любая обработка (LLM-cleanup, суммаризация,
   роутинг) создаёт новые артефакты **рядом** и никогда не перезаписывает более сырые:
   аудио → `transcript.jsonl` → `processed.md` → `summary.md` — цепочка только
   дополняется.
3. **Аудио храним по retention-политике (N дней), а не удаляем после транскрипции.**
   Это сырьё для повторных прогонов: другие ASR-модели, диаризация, будущие фичи.
   Сейчас код удаляет WAV сразу после успешного append в транскрипт
   (`engine.rs`) — заменить на политику. Опция для экономии диска: после
   транскрипции пережимать WAV → FLAC (lossless, ~вдвое меньше, пригоден для
   повторного ASR) и хранить уже его. Порядок цифр: 16 kHz mono ≈ 115 МБ/час WAV,
   ~7 дней активной речи по 8 ч ≈ 6–7 ГБ (FLAC ~3 ГБ).
4. **Удаление — только по retention-политике или явной команде пользователя.**

## 1. Ядро (заявлено владельцем продукта)

### F1. LLM-обработка транскриптов — must have

**Что:** два вида обработки поверх сырого транскрипта:
1. *Обработка текста* — пунктуация/капитализация (критично для Vosk-пути), удаление
   слов-паразитов и фальстартов, нормализация терминов, разметка ролей говорящих —
   то, что сейчас делается вручную внешним LLM (`transcript_uat_processed.md`).
2. *Суммаризация* — протокол встречи: ключевые пункты, решения, action items,
   открытые вопросы (`transcript_uat_summary.md` как референс выхода).

**Провайдеры — модульно:** локально и через облако.

Эскиз архитектуры:
- Один trait `LlmProvider` (chat-completion: messages in → text/stream out).
- **Ключевое упрощение: OpenAI-compatible HTTP API как универсальный протокол.**
  Его поддерживают Ollama, LM Studio, vLLM, llama.cpp-server, OpenRouter, сам OpenAI,
  а также GigaChat/YandexGPT через прокси. Один reqwest-клиент с настраиваемым
  `base_url`/`api_key`/`model` закрывает почти всё. Отдельные реализации трейта — только
  если понадобится нативный протокол (например, Ollama `/api/chat` ради keep_alive).
- Конфиг — именованные профили провайдеров (`llm.toml` / секция light_config):
  `[llm.profiles.local]` → Ollama qwen3, `[llm.profiles.cloud]` → OpenAI gpt-5-mini;
  выбор профиля per-задача (cleanup дёшево локально, summary — куда скажут).
- **Шаблоны промптов — файлы** (`templates/*.md` с плейсхолдерами), пользователь
  добавляет свои (аналог Attention Templates у Summit, но открытые файлы, а не UI).
  Стартовый набор (из разбора Summit): stand-up («сделано/планы/блокеры»), 1-on-1,
  собеседование («опыт/сильные стороны/риски/оценка»), техобсуждение, интервью с
  клиентом, discovery call, лекция, ретроспектива, подкаст, конспект видео.
  Назначение шаблона — на запись или на слот/папку целиком.
- **Дефолтная схема полного протокола** (что извлекаем): основные темы, ключевые
  выводы, решения, спорные вопросы, риски, числовые данные, следующие шаги,
  поручения, ответственные, сроки. Конспект — обычный md-файл, редактирование
  перед отправкой у нас нативное (это файл).
- Длинные встречи: chunking по границам сегментов + map-reduce (промежуточные выжимки →
  финальная сводка). Контекстное окно профиля — в конфиге.
- Запуск: (а) on-demand CLI `localvox process <transcript.jsonl> --template summary`,
  (б) автоматически по завершении сессии, (в) later — rolling summary в realtime.
- Выход — рядом с исходником: `transcript.processed.md`, `summary.md`.

**Глоссарий терминов (добавлено 2026-07-11).** ASR фонетически коверкает IT-термины,
часто в несколько слов: реальные примеры из нашего UAT — «капаштет/как посетит» →
capacity, «дракон троп» → drag-and-drop, «сторик понты» → story points, «кант» →
Гант, «йота» → UAT (готовая таблица — `transcript_uat_processed.md`, §1 — это seed
первого глоссария). Схема из трёх слоёв:

1. *Детерминированный проход* (без LLM, офлайн, дёшево): `glossary.toml` —
   канонический термин + известные варианты написания; матчинг однозначных
   вариантов (aho-corasick по нормализованному тексту) + фонетический fuzzy.
   **Ambiguity guard:** варианты, совпадающие с нормальной русской речью
   («жира», «кант», «как посетит»), автозаменой не трогаем — только помечаем.
2. *Глоссарий в промпт LLM-cleanup*: список канонических терминов подмешивается в
   промпт («если фрагмент фонетически похож на термин — используй каноническое
   написание») — LLM снимает неоднозначность по контексту. Основной слой качества.
3. *ASR-уровень (later, research)*: hotword-biasing — sherpa-onnx умеет для
   transducer-моделей; GigaAM RNNT + shallow fusion. Не для старта.

Откуда брать словарь:
- **Свои транскрипты** — лучший источник: таблица из UAT как seed + майнинг
  подозрительных n-грамм из архива с LLM-предложением канона (полуавтоматическое
  пополнение).
- **Автогенерация вариантов**: по списку английских терминов генерировать ожидаемые
  кириллические фонетические написания правилами транслитерации (Jira → джира/жира,
  pipeline → пайплайн) — тысячи вариантов бесплатно.
- **Готовые базы**: Microsoft Terminology Collection (большая ru↔en база
  IT-терминологии, скачиваемая), названия инструментов из CNCF landscape /
  топ-репозиториев GitHub, community-глоссарии айти-сленга.
- **Per-slot/per-project глоссарии**: жаргон проекта, названия команд, имена людей
  (тот же механизм позже пригодится для имён спикеров).

Принципы: замены не мутируют `transcript.jsonl` — глоссарный проход пишет в
processed-слой + лог применённых замен (аудит «что заменили»); метрика качества —
доля правильно нормализованных терминов на UAT-эталоне (входит в LLM-бенч).

In-process inference (llama.cpp bindings / mistral.rs), как встроенный AI у Summit —
**не обязателен на старте**: Ollama/LM Studio дают локальность без нашей возни с
инференсом. Вернуться к этому, когда захотим «поставил exe и всё работает».

Решено (2026-07-10, дополнено 2026-07-11): стартовые провайдеры — **Ollama (локально)
+ OpenAI + OpenRouter (облако)**, все через один OpenAI-compatible клиент (OpenRouter
для нас бесплатен по коду — тот же протокол, другой base_url). GigaChat/YandexGPT —
по потребности позже.

Открытые вопросы:
- Дефолтная локальная модель для ru-суммаризации (Qwen3? Vikhr? — надо забенчить
  на наших UAT-транскриптах).
- Cleanup всего потока реалтайм-сегментами или пост-фактум целиком?

### F2. Голосовые заметки по команде («запиши…») — must have

**Что:** во время работы говорю «запиши» — опционально с указанием куда: «запиши в
идеи…» — ассистент фиксирует заметку в настраиваемый слот и **проговаривает голосом**,
что записал (подтверждение). Это наш главный дифференциатор — у Summit никакого
голосового интерактива нет.

Эскиз:
- *Детект команды:* Vosk уже отдаёт streaming partial results — матчить командное
  слово в партиалах дёшево и без новых зависимостей. Отдельная KWS-модель — потом,
  если будут ложные срабатывания.
- *Грамматика:* `запиши [в <слот>] <текст>` — текст до паузы (VAD уже есть).
- *Два режима захвата:*
  1. **проспективный** — «запиши: купить лицензию vosk» → следующая фраза = заметка;
  2. **ретроспективный** — «запиши это» → взять последние N секунд из ring-буфера
     (см. F3) и LLM-ом выжать суть. Киллер-фича: мысль уже прозвучала на встрече,
     не надо повторять.
- *Слоты — быстрые пре-конфигурации назначений, а не просто файлы.* Слот = голосовые
  алиасы («идеи», «ретро») + **адаптер-интеграция** + её настройки + **шаблон
  обработки** записи. Несколько слотов могут сидеть на одной интеграции с разной
  логикой работы: слот «идеи» — Obsidian-заметка на дальнейший груминг (LLM формирует
  заголовок + суть + теги), слот «ретро» — тот же Obsidian, но append строки в список
  любимых песен. Адаптеры — три яруса по нарастанию:
  1. **markdown-файл/папка** — zero-config; Obsidian vault = просто файлы на диске,
     так что основной кейс закрывается вообще без интеграционной машинерии;
  2. **MCP-клиент** — универсальный мост в любую интеграцию без написания каждой
     (готовые MCP-серверы: Obsidian REST, Notion, таск-трекеры…): слот указывает
     сервер + tool. Через MCP данные могут и **приходить** из слота — чтение
     контекста для F5-роутинга и RAG;
  3. нативные REST-интеграции — только если MCP где-то не хватит.
  Конфиг — секции `[slots.<имя>]` в TOML, без UI-космолёта. Дефолтный слот для
  «запиши» без адреса.
- *TTS-подтверждение:* русский TTS локально — **Silero TTS** (отличный ru, есть ONNX →
  ложится в наш ort-стек) или Piper; fallback — Windows SAPI. Playback через cpal
  (уже в зависимостях). Короткое: «Записал в идеи: …».
- *Анти-эхо:* TTS из колонок попадёт в loopback-захват → на время собственного
  воспроизведения помечать/гейтить сегменты loopback, чтобы ассистент не
  транскрибировал сам себя.
- *Модульность (решено 2026-07-10):* весь голосовой контур — **отдельный отключаемый
  модуль**: выключил — localvox остаётся чистым транскриптором, ничего из контура
  не грузится. Настраивается каждый элемент:
  - wake-word (само слово/фраза);
  - признак окончания ввода: пауза-тишина и/или стоп-слово;
  - фраза-ответ (что ассистент говорит в подтверждение);
  - проговаривать ли записанное (TTS on/off);
  - обрабатывать ли ввод LLM-ом (переформулировка по шаблону слота) или сохранять
    дословно;
  - сохранять ли сам сырой ввод (и куда).
  Дефолты глобальные + переопределения per-slot: слоту «ретро» LLM не нужен —
  дословный append, слоту «идеи» — нужен (заголовок + суть + теги).

Решено (2026-07-10): команды слушаем **только с микрофона** — это в первую очередь
личный ассистент; loopback команды не триггерит (заодно исключает срабатывание на
чужое «запиши» из звонка).

Открытые вопросы:
- Нужен ли всё же префикс-wake-word («вокс, запиши») против случайного «запиши»
  в собственной речи на встрече?
- Подтверждение до или после записи? (предлагаю: записать сразу, проговорить факт,
  голосовая команда «отмени» откатывает последнюю заметку.)
- MCP-клиент в Rust: официальный rmcp? Какие транспорты нужны первыми (stdio, HTTP)?

### F3. Always-on: постоянно висит и слушает — must have

**Что:** процесс живёт постоянно (пока явно не выключили), сам распознаёт, что
началась встреча/звонок, сам ведёт и закрывает сессии.

Эскиз:
- *Форма:* headless-демон + иконка в трее на **всех трёх ОС — Windows, macOS, Linux**
  (крейт `tray-icon` от команды Tauri покрывает все три; Linux — AppIndicator).
  TUI остаётся как «открыть консоль» для отладки. Автостарт с системой.
- *Кроссплатформенный захват системного звука:* Windows — WASAPI loopback (есть);
  macOS — ScreenCaptureKit system audio (macOS 13+) или виртуальное устройство
  (BlackHole); Linux — PipeWire/PulseAudio monitor-источники (частично уже работает
  через cpal). Детали — `docs/architecture-target.md`.
- *Автодетект встречи — сигналы (по убыванию надёжности):*
  1. **WASAPI-сессии:** на Windows видно, какие процессы держат аудио (рендер и
     захват микрофона) — zoom.exe, ms-teams.exe, discord.exe, браузер. Появилась
     активная сессия знакомого процесса → началась встреча. Конфиг-список приложений
     + игнор-лист (как у Summit).
  2. Одновременная продолжительная VAD-активность в mic + loopback.
  3. Later: календарь.
- *Pre-roll ring buffer:* постоянно держать последние N минут PCM в кольцевом буфере;
  при детекте встречи сессия начинается «в прошлое» — начало не теряется. Тот же
  буфер обслуживает ретроспективное «запиши это» (F2).
- *Сессионизация:* авто-разрез на сессии по тишине > X минут / исчезновению
  аудио-сессии; LLM-заголовок сессии (F1).
- *Privacy-контролы:* глобальный hotkey пауза/возобновление, явный индикатор записи
  в трее, retention-политика на аудио (см. «Принципы данных»: N дней, не мгновенное
  удаление; транскрипт остаётся навсегда).
- *Ресурсы:* в тишине — только VAD (дёшево); ASR-пул просыпается по активности.

Решено (2026-07-10): слушает **постоянно по умолчанию**, пока явно не выключили.
Автодетект размечает встречи как сессии поверх непрерывного потока; вручную можно
выключить/заглушить **каждый источник отдельно** (mic / loopback) плюс общая пауза
hotkey'ем.

Открытые вопросы:
- Сегменты, отброшенные noise gate / пустые: сейчас удаляются мгновенно
  (`engine.rs`). Под новую политику — хранить их те же N дней («карантин» для
  будущих, более чутких моделей) или продолжать удалять сразу?
- Трей-демон и TUI — один бинарник с флагом или два?

### F4. Поиск по всему архиву — must have

**Что:** мгновенно найти «где это обсуждали» по всем транскриптам, заметкам, сводкам.

Эскиз:
- *Этап 1 — full-text:* tantivy (Rust-нативный движок) поверх `transcript.jsonl` +
  заметок слотов + summary; CLI `localvox search "<запрос>"` с фильтрами
  (дата, источник mic/sys/youtube, сессия) и выводом с контекстом; панель в TUI.
- *Этап 2 — семантический:* локальные embeddings через ONNX (fastembed-rs,
  мультиязычные bge-m3 / multilingual-e5 — русский ок, стек ort уже наш) + лёгкое
  векторное хранилище (usearch/LanceDB/sqlite-vec). Гибридный скоринг.
- *Этап 3 — RAG-чат* по архиву («что мы решили по иксу в июне?») через F1-провайдеры.
- Индексируем **все артефакты**, не только транскрипты: summary, теги, задачи, имена
  участников, ручные заметки; фильтры (дата/источник/спикер) + «похожие документы».
- Чат со scope: одна запись / выбранные документы / весь архив; ответы потоково.
  Примеры запросов: «какие риски назвал Алексей?», «сравни решения из последних трёх
  встреч», «найди все случаи, когда обсуждали миграцию на Kafka», «составь письмо
  клиенту по итогам разговора».

### F5. LLM-роутинг: «куда это занести» — must have (после F1)

**Что:** ассистент сам предлагает перенос/занесение данных в нужные разделы/проекты:
после встречи — «нашёл 3 action items → в work.md?», «этот кусок — продолжение
обсуждения проекта икс от 3 июля, приложить туда?», автотеги, привязка к контексту.

Эскиз:
- Паттерн **suggest-then-confirm**: LLM формирует предложения со ссылками на сегменты,
  пользователь подтверждает (в TUI/CLI-ревью или голосом «да/нет» через F2-механику).
  Ничего не перемещаем молча.
- Классификация против реестра слотов/проектов (из F2-конфига) + поиск похожих прошлых
  сессий (F4-embeddings) как контекст для LLM.
- Дальняя перспектива «секретаря»: дайджест дня голосом/файлом, напоминание о
  повисших action items.

### F6. Локальный API — UI как отделяемый слой

**Что:** гарантия, что полноценный GUI можно допилить отдельным слоем, не вскрывая
бинарь. Сейчас всё скомпилировано в один процесс, но шов уже существует: ядро —
библиотека (`localvox-light-core`), TUI общается с движком через каналы событий.
Эта граница и становится API.

Эскиз:
- Отдельный крейт `localvox-light-api` (feature-флаг, по умолчанию выключен — та же
  философия, что у голосового модуля): HTTP + WebSocket/SSE на localhost.
- Поверхность API: **управление** (пауза/заглушение источников, reload устройств,
  конфиг), **поток событий** (live-транскрипт, статус очереди — ровно то, что сейчас
  ест TUI), **данные** (сессии, транскрипты, summary, поиск, запуск LLM-обработки).
- События движка — простые структуры, транскрипт уже jsonl → сериализация в WS
  почти бесплатна.
- Файлы остаются источником истины (см. «Принципы данных»); API — слой управления
  и чтения, не хранилище.
- Стыкуется с F3: трей-демон и есть процесс, который держит API; TUI со временем —
  просто ещё один клиент; GUI (Tauri/веб) подключается к тому же API без изменений
  ядра.
- **MCP-сервер поверх архива** (парный к MCP-клиенту слотов из F2): экспонировать
  `search_transcripts` / `get_transcript` / `get_summary` / `append_note` как
  MCP-инструменты — любой внешний агент (Claude, ChatGPT, свои скрипты) работает с
  базой записей. Granola продаёт это как бизнес-фичу; у нас дёшево: jsonl + tantivy.
- Синхронный стек не ломаем: tiny-http/rouille + tungstenite, либо tokio изолированно
  внутри api-крейта.

Открытые вопросы:
- Транспорт: localhost HTTP или named pipe (Windows)? (HTTP проще для будущего веб-UI.)
- Защита локального API (токен в конфиге?), чтобы посторонний софт на машине не
  читал транскрипты.

### F7. Мобильный доступ — must have (минимум: поиск по базе)

**Что:** доступ с телефона к базе записей — как минимум поиск, дальше чтение summary,
чат с базой, захват голоса на ходу. Детальный разбор — `docs/mobile-companion.md`.

Три яруса по нарастанию стоимости:
- **Ярус 0 — без кода (фаза B):** слоты-файлы кладут markdown в Obsidian vault →
  Obsidian mobile + любой синк (Syncthing/облако пользователя) дают чтение и поиск
  заметок на телефоне бесплатно.
- **Ярус 1 — PWA (фаза C):** демон (F6) отдаёт лёгкий веб-UI поверх собственного API:
  поиск по всему архиву, чтение транскриптов/summary, чат. Доступ: LAN, а вне дома —
  Tailscale/WireGuard (без нашего облака — принцип сохраняем), токен-авторизация.
  Никаких app store.
- **Ярус 2 — нативное приложение (фаза D):** Tauri 2 mobile (переиспользуем Rust):
  захват голосовых заметок/встреч на телефоне → очередь → синк на десктоп для
  ASR/LLM; уведомления (дайджест, action items).

Открытые вопросы:
- Приоритетная платформа: Android или iOS?
- Достаточно ли яруса 1 надолго, или захват на телефоне (ярус 2) важен рано?

### F8. Двухскоростной конвейер: slow lane — основной путь (решено 2026-07-11, уточнено в тот же день)

**Что:** фокус разработки — **отложенная, но качественная обработка**; мгновенная
реакция остаётся только там, где без неё нельзя. Текущая короткосегментная
реализация **остаётся в коде** (fast lane), но перестаёт быть центром продукта.

**Fast lane (минимальный, при записи).** Единственное место, где живёт Vosk — в
качественной варке он не участвует (решено 2026-07-11):
- wake-word + голосовые мемо («запиши») — обязательные потребители мгновенности;
- **live-индикация «пишем не херню»** — опциональная: партиалы/сегменты Vosk как
  эфемерный черновик на экран — подача как «думание» LLM в чатах (серый поток,
  позже заменяется чистовой версией) + уровни/VAD-статус. Отключаемо, на качество
  архива не влияет.
- Реализация — та же короткосегментная VAD-история, что сейчас, но сегменты живут
  в **RAM** (черновику надёжность не нужна — slow lane всё переварит из чанков).
  Текущий дисковый режим сегментов остаётся legacy-флагом на переходный период,
  кандидат на выпил после стабилизации чанков.

**Запись аудио — потоковая, чанки по границам тишины (уточнено 2026-07-11):**
- Пишем **потоково с частым flush**: PCM уходит на диск каждые 1–5 секунд, fsync
  периодически — при падении теряются секунды, а не куски.
- «Чанк» — это просто **ротация файла на паузе речи**: цель ~5–10 минут, режем по
  ближайшей VAD-тишине → границы не попадают на слова → **нахлёст и дедупликация
  склейки не нужны вовсе**. Аварийный фолбэк: нет тишины 15 минут подряд — жёсткий
  разрез с маленьким нахлёстом (редкость; одна склейка по пословным таймкодам).
- При закрытии чанка — фоновая конвертация WAV → FLAC (retention-решение).
- Зачем ротация, а не один файл: гранулярный retention и re-ASR + **параллельная
  варка чанков пулом воркеров** — ключ к бюджету скорости (см. ниже).
- Durability: **чанки — первичный durable-артефакт**; recovery после падения =
  доварить необработанные чанки (та же семантика, что сейчас у WAV-очереди).

**Slow lane («варка» — фоном, ночью, по запросу):** ASR точными моделями, диаризация
(опц.), глоссарий + LLM-cleanup, merge, summary, перевод, embeddings-индексация.
Через ту же durable-очередь джобов (переживают падение), поверх retention-аудио.
Планировщик: idle / расписание / питание от сети.

**Бюджет скорости (решено 2026-07-11): час сессии — ≤5 минут варки в среднем**
(ориентир Summit: ~2 мин на M1). Рекомендованная схема (Vosk не участвует):
- *Дефолт:* один проход **GigaAM v3 e2e int8, чанки параллельно** пулом воркеров —
  конформер 240M int8 на 4–8 ядрах даёт кратный запас к реальному времени;
  контрольный замер на целевом железе — в фазе A вместе с LLM-бенчем.
- *Опция «тщательно» (selective second opinion):* по CTC-конфиденсу (низкая
  уверенность/энтропия) находим сомнительные спаны и **только их** прогоняем второй
  моделью (GigaAM fp32 / Whisper turbo), LLM-арбитр с глоссарием выбирает вариант.
  ~95% аудио варится один раз — бюджет держится.
- *Полный двухмодельный мерж всего аудио* — только по явному запросу и если докажет
  преимущество на UAT-бенче.

**Версии обработок (первоклассная сущность):**
- Каждый результат обработки первичного аудио/текста — **новая версия**, исходник
  никогда не мутируется. `versions.json` — манифест: модель, параметры, дата,
  пользовательская метка, родительские версии. Перелистывание версий в TUI/PWA,
  указатель `best`/`current`, производные (summary, индекс) считаются от выбранной.
- Типовые версии: `v001-fast` (черновик Vosk — только для истории, в мерже не
  участвует) → `v002-gigaam-int8` (основной ASR) → `v003-refined` (second opinion
  по сомнительным спанам, родитель v002) → диаризация/перевод как следующие слои.
- **Мерж нескольких транскриптов в один хороший**: состоятельно — ошибки разных
  архитектур (Kaldi/Vosk vs conformer/GigaAM vs Whisper) слабо коррелированы, мерж
  чинит то, что каждая модель врёт по-своему. Порядок внедрения: (1) LLM-merge
  (два-три транскрипта + глоссарий в промпт → «собери лучший», дёшево через F1);
  (2) механическое пословное голосование (ROVER-стиль, по таймкодам) — позже.
  **Гейт:** мерж включается по умолчанию, только если бьёт single-best на
  UAT-бенче — иначе остаётся опцией для важных встреч.
- **Re-ASR по запросу**: «переварить фрагмент» / «от места до конца»:
  `localvox reasr <сессия> --from <t1> [--to <t2>] [--model …]` → новая версия.

**Отчуждаемость (принцип, 2026-07-11):** вся работа с транскриптом (поиск, чат,
обработки, версии) — независимые модули поверх **файлов сессии**, а не внутренностей
ядра. Любой модуль можно вынести в отдельный процесс/инструмент без вскрытия ядра.

### F9. Надёжность захвата (капризы аудио-железа) — must have

Из разбора Summit (2026-07-11); всё ложится на нашу архитектуру дёшево:

- **Эхо-подавление — приоритет поднят (2026-07-11):** без наушников общаемся часто,
  а при записи крупными кусками (F8) посегментный текстовый дедуп не работает.
  Основное решение — **AEC на захвате**: speexdsp/webrtc-audio-processing, loopback
  как reference-сигнал, эхо колонок вычитается из микрофонного тракта до записи.
  Вспомогательный слой — текстовое выравнивание mic/sys транскриптов по пословным
  таймкодам на этапе slow-lane merge. В наушниках эха нет — детектировать и
  не тратить ресурсы.
- **Автопереключение микрофона**: приоритетный список устройств в конфиге;
  устройство пропало → берём следующее (расширение имеющегося hot-reload по F2).
- **Watchdog «микрофон молчит»**: активная сессия + нулевой RMS/нет VAD N минут →
  предупреждение (TUI-баннер / трей / опционально голосом). Плюс sanity-check
  «выбранный микрофон совпадает с устройством вывода» (грабли из Summit 1.9.1).

### F10. Плеер: транскрипт ↔ аудио — must have (следствие retention)

**Что:** клик по реплике → проигрывание аудио с этого момента; скорость
воспроизведения; фильтр реплик по говорящему (после диаризации).

- У нас это дёшево: реплика несёт таймкод → чанк + смещение (формат записи F8),
  rodio играет с offset; скорость — ресемплинг. Непрерывное прослушивание — чанки
  подряд (зону нахлёста пропускаем по таймкодам).
- Бонус: CTC-декодер GigaAM отдаёт фреймовые таймстемпы → **пословные таймкоды
  почти даром** (переход внутрь длинного сегмента; подсветка в будущем GUI).
- Требует аудио на диске → включается retention-политикой; для «вечных» записей —
  сессия/слот с retention = forever (настраивается, как и договаривались).
- UI по нарастанию: TUI (Enter на реплике) → PWA/GUI (HTML5 audio через F6 API).

## 3. Наши уникальные направления (усиливать)

- **YouTube/файлы + F1 = конспект любого видео/подкаста одной командой:**
  `localvox-asr <url> --template конспект`. У Summit такого пути нет вообще.
- **Windows-first**: Summit mac-only, у Windows-корпоратов выбора локального
  инструмента почти нет.
- **Голосовой интерактив** (F2): единственный «двусторонний» ассистент в нише.
- **Durable-конвейер**: at-least-once, crash recovery — держать планку и рекламировать.
- **CLI-скриптуемость**: пайплайны, cron, интеграция в чужие скрипты.
- **Русский first-class офлайн**: GigaAM v3 против Whisper/Parakeet у всех
  остальных — измеримое преимущество на нашем языке.
- **Linux**: нишу «встречи локально на Linux» не закрывает никто, кроме Screenpipe.
- **MCP-сервер поверх архива** (F6): база записей как инструменты для внешних
  агентов — Granola продаёт это как бизнес-фичу, у нас дёшево.
- **Открытые форматы**: jsonl + markdown, данные greppable, нулевой lock-in —
  «архив переживёт вендора» (судьба Rewind/Limitless — в ландшафте).
- **Модульность + небольшие деньги + жизнь без облака** — позиционирование против
  подписок $9–15/мес; варианты монетизации — `docs/positioning.md`.

## 4. Идеи-пул (вторая волна, 2026-07-10 — по мотивам ландшафта конкурентов)

> Источник: `docs/competitors/landscape-2026.md`. Статус: сырьё для отбора,
> не обязательства.

**Захват:**
- **Watch-folder**: кинул аудио/видео в папку → авто-транскрипт + summary. Наш
  ingest уже умеет файлы — не хватает только вотчера каталога.
- **Контекст активного окна**: при старте сессии снять имя процесса/заголовок окна
  («zoom.exe — Weekly sync») → авто-название и метаданные встречи. Лайт-версия
  Screenpipe без OCR, почти бесплатно.
- **Голосовые закладки**: «отметь» — таймштамп-маркер в транскрипте (у Summit —
  кнопкой, у нас голосом; та же механика, что «запиши»); позже — переход к моменту
  (F10) и конвертация закладки в AI-инсайт с окружающим контекстом.
- **Слот из буфера обмена**: «запиши из буфера» — текст/ссылка из clipboard в слот.
- **Импорт диктофона телефона** (ярус 2 F7): голосовые с телефона в общий конвейер.

**Обработка:**
- **«AI-блокнот»** (паттерн Granola/Hyprnote): пишу 3 строчки тезисов во время
  встречи (панель заметок в TUI / файл рядом), LLM сшивает мои тезисы с транскриптом
  в полные заметки. Человек помечает ЧТО важно — машина дописывает ЧЕМ это было.
- **Локальный перевод минуток ru↔en** (LLM/NLLB) — шаринг англоязычным коллегам.
- **Дозревание заметок**: голосовая мемо пишется мгновенно черновиком (fast lane,
  Vosk) — TTS сразу подтверждает; затем slow lane переваривает тот же кусок аудио
  качественно и тихо обновляет заметку в слоте (с пометкой «уточнено»).
  *Решение 2026-07-11: отложено в конец очереди фич.*
- **Talk-time статистика**: кто сколько говорил (после диаризации; для ретро и 1:1).
- **Детект языка сегмента** (ru/en code-switching) → роутинг сегмента в правильную
  ASR-модель.
- **Язык/модель ASR per-запись**: ручной override для отдельной сессии (встреча на
  английском → Whisper/Parakeet вместо GigaAM).

**Знания:**
- **Дайджест дня/недели**: «что я обещал», повисшие action items — файлом, голосом
  или push (F7).
- **Saved searches** / смарт-папки поверх поиска.
- **Автосвязи сессий**: «продолжение обсуждения от 3 июля» (embeddings, F4/F5).
- **People-профили** (после диаризации): все упоминания и обещания по человеку.

**Интерактив:**
- **Голосовой диалог с базой**: «что мы решили по иксу?» → ASR → RAG (F4) →
  TTS-ответ. Логичное замыкание F2 + F4.
- Микро-грамматика управления: «отмени», «повтори», «что записал?».

**Шеринг:**
- **«Минутки одной командой»**: экспорт summary в md/pdf/email по шаблону.
- **Маскирование чувствительного**: авто-редакция имён/цифр/названий перед экспортом
  наружу — комплаенс-фича, усиливает приватный нарратив.

**Инфраструктура:**
- **Portable-режим**: запуск с флешки без установки и прав администратора
  (корпоративная реальность).
- **Шифрование архива at rest** (опция; ключ у пользователя).
- **Профили конфига**: «работа»/«дом» (разные слоты, устройства, retention).
- **`localvox doctor`**: самодиагностика окружения (модели, устройства,
  ffmpeg/yt-dlp, ollama).
