# Поведенческие проверки на своей ОС

Запускать из клона LocalVox на Windows, macOS или Linux. Модели и доступ к микрофону
не нужны; рабочий архив и демон не используются. По умолчанию сборка и тесты идут
с одним worker. При первом запуске Cargo соберёт тесты, следующие используют кеш.
По умолчанию проверяются текущие исходники и собранные из них клиенты.

Windows:

```powershell
python .\scripts\test-behavior.py
```

macOS:

```sh
python3 scripts/test-behavior.py
```

Linux:

```sh
python3 scripts/test-behavior.py
```

Чтобы проверить установленный клиент, добавить `--installed-dir` и свою папку:
например, `F:\lv` на Windows или `"$HOME/Applications/LocalVox"` на Mac.
`--installed-dir` проверяет настоящие `vox`/TUI в
терминальных сценариях: старый бинарник не заменяется незаметно свежей сборкой.
Остальные библиотечные/API/GUI проверки относятся к текущим исходникам; это
различие указано в отчёте. Без параметра PTY тоже использует собранные исходники.

Набор проверяет навигацию и формы, задержанные HTTP-ответы, удаление и последующие
опросы списка, повторное название, ранний текст, synthetic Start/Stop на двух
дорожках, хранение и очередь, API, настоящий mpv через IPC, поведение GUI в Chromium.
Тестовые WAV генерируются; mpv использует null audio и ничего не проигрывает в колонки.

Если зависимость отсутствует, группа получит **blocked**, а итог будет ненулевым.
Команды подготовки попадут в задание агенту. Для полного набора нужны:

- Rust из `rust-toolchain.toml`, Node 24 и Python 3.11+.
- Native Vosk library: `scripts/setup-vosk.ps1` на Windows или
  `bash scripts/setup-vosk.sh` на Mac/Linux. Это библиотека, голосовая модель не скачивается.
  При `--installed-dir` готовая библиотека используется из комплекта; повторная загрузка не нужна.
- GUI: в `ui` выполнить `npm ci` и `npx --no-install playwright install chromium` один раз.
- mpv ≥0.38: Windows `npm --prefix ui run setup:mpv`, Mac `brew install mpv`,
  Linux — менеджер ОС. Готовый путь можно задать через `LOCALVOX_MPV`.
- Системные зависимости сборки Linux — [development.md](development.md).

На Intel Mac runner также использует готовый ONNX Runtime из указанного комплекта.
Без него нужен SDK через `scripts/build-onnxruntime-macos.py`; отсутствие помечается blocked.

Быстрый повтор выбранных групп:

```sh
python3 scripts/test-behavior.py --group tui --group mpv --installed-dir "$HOME/Applications/LocalVox"
```

`--list` покажет команды без запуска. Можно повторять `--group` для `tui`, `recording`,
`api`, `setup`, `mpv`, `gui`; по умолчанию выбраны все. `setup` проверяет мастер,
команды установки и delivery scripts на локальных fixtures. `--jobs 2` явно разрешает два worker.

Результаты лежат в напечатанной папке `target/behavior/<дата-pid>/`:

- `report.md` — короткая таблица passed/failed/blocked/timeout/not-run.
- `report.json` — ОС, commit, наличие правок, команды, время и exit codes.
- Логи групп, browser PNG и traces — рядом.
- **`AGENT_TASK.md` — готовое задание местному агенту.** Достаточно передать:
  «Прочитай этот файл и исправь отказы по указанным сценариям». Автоматической
  отправки, публикации логов или запуска другого агента нет.

Обычный запуск выполняет все поведенческие browser assertions и сохраняет картинки,
но не сравнивает их с чужой платформой: рендеринг шрифтов отличается. Для проверки
визуальных эталонов добавить **`--visual`**; эта проверка отдельно отмечена в отчёте.
Обычный CI продолжает строго сравнивать изображения. Эталоны runner не обновляет.

Разрешения ОС, реальный микрофон/loopback, качество/скорость ASR и LLM остаются
**not-run**. Успешный автоматический прогон не выдаётся за аппаратную проверку.

Опциональный стек ASR проверяется и без весов: общий набор включает настройки
GigaAM/T-one и независимой пунктуации, мастер с галочками/готовыми папками,
повтор загрузки и raw fallback при отказе процессора. Настоящие веса проверяются
отдельно по [инструкции для разработчика](asr-model-testing.md).
