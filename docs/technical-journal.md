# Технический журнал

«Ход» сохраняет независимые статусы артефактов и добавляет историю
`run → stage → operation → log`. Завершение дочернего процесса не подтверждает
годность его результата. Heartbeat означает активность, счётчик работы от него
не увеличивается. Старые записи этапов читаются без выдуманных команд.

В UI блок раскрывается кнопкой `+ N lines`; N считает загруженные скрытые строки,
включая переводы строк внутри сообщения. Ошибки остаются видимыми. Фильтр,
раскрытие и переход к хвосту доступны с клавиатуры. При чтении выше хвоста новые
события не прокручивают экран. Загрузка предыдущей страницы сохраняет окно чтения.
При заполнении кеша историческое окно сохраняется, а переход к хвосту заново
загружает последние события. Ограничение истории показывается отдельно от сворачивания.
Смена файла истории показана отдельной подписью и заменяет оба курсора. Поздняя
страница старого файла не попадает в новую историю. В UI смена сессии отменяет её HTTP-запросы.
Экран «Ход» и очередь опрашиваются последовательно; при сетевой ошибке остаются
последние данные с отметкой устаревания. Активность в верхней строке открывает очередь,
а выбранная задача — её «Ход». Порядок задач берётся у сервера.

## Протокол и пределы

`GET /api/sessions/{name}/journal?limit=200&after={cursor}` продолжает чтение;
`before` загружает предыдущую страницу. Вместе after/before не используются.
Cursor — непрозрачная идентичность поколения и позиции; timestamp не служит ID.
Смена поколения/усечение возвращает `reset`. Неполная последняя строка ожидает
дописывания; повреждённая/слишком большая строка не останавливает продолжение.

Ответ содержит `events`, `next_cursor`, `previous_cursor`, `has_more`, `reset`,
`truncated`, `discarded`, `dropped_verbose`, `read_bytes`. Новые записи содержат
`journal: 1`, `run`, `operation`, `parent`, `stage`, `kind`, `at`, `label`,
необязательные `status`, `command`, `text`, `done`, `total`.

- Один запрос сканирует до 1 MiB основного progress-файла, дополнительно до
  32 байт для поколения, одного байта границы и до 4 KiB производной метаинформации.
- Страница содержит до 200 событий и 256 KiB сериализованного JSON.
- Display-текст ограничен 4096 символами. Значения флагов проходят allowlist;
  произвольные argv, env, пути, URL и токены не публикуются.
- Информационные подробности ограничены 8 MiB на запуск. `dropped_verbose`
  сообщает число пропущенных подробностей. Ошибки и переходы сохраняются сверх
  этого лимита. `discarded` относится к текущему чтению повреждённых фрагментов.
- Кеш каждого клиента ограничен 5000 событиями и 4 MiB сериализованного содержимого
  событий; индексы, строки рендерера и прочие расходы не входят в этот предел.

Журнал дописывается в существующий `progress.jsonl`, старый `/progress` совместим.
Производный `.journal-meta.json` хранит ID запуска и квоту подробностей; он не
содержит содержимое документов и не подтверждает артефакты. Обе формы append
используют один файловый lock с ожиданием до 20 ms. Ошибка записи диагностируется,
она не превращает неудачную обработку в успешную.

Supervisor продолжает писать stdout/stderr в свои spool-файлы. Ограниченный
наблюдатель читает их с отдельными offsets и не блокирует дочерний процесс.
В journal сейчас публикуются только имя потока и количество полученных байт:
произвольный вывод worker может содержать исходный текст и секреты.

## Проверки

`npm --prefix ui run test` и `npm --prefix ui run test:e2e` проверяют модель,
браузерный журнал, адаптивную оболочку и визуальные эталоны.
`cargo test -p localvox-light-core journal:: --lib -- --nocapture` проверяет
cursor, повреждения, квоту, конкурирующий append и большой синтетический файл.
Фактические результаты и ограничения находятся в
[evidence change](../openspec/changes/add-technical-journal-workspace/evidence/implementation.md).

Обычный запуск тестов не обновляет эталоны. Для намеренной правки UI используйте
`npm --prefix ui run test:e2e -- --update-snapshots`, просмотрите PNG и diff.
Проверки с намеренно испорченным визуалом в этом режиме пропускаются, чтобы не
перезаписать правильные эталоны. Ratatui создаёт `.snap.new`, которые принимаются
только после просмотра символов и стилей. CI сохраняет предложения/diff/trace.
# Совместимость клиентов

Авторизованный `/api/health` дополнительно возвращает `service: "localvox-light"`,
`api_protocol: 1` и `capabilities: ["technical-journal-v1", "terminal-workspace-v1"]`.
Старые `ok`/`version` сохранены. Новый TUI проверяет эти поля до запросов рабочего
пространства; auth/Host/Origin остаются прежними. Это проверка wire-совместимости,
не аппаратной готовности capture или установленных speech-моделей.

В графическом UI язык записи выбирается на вкладке «Реплики» с подтверждением полной
переработки. В «Тексте» исходные исправленные реплики раскрываются отдельно и не
попадают в копию. «Настройки → Подключение этого браузера» позволяет задать/очистить
локальный токен даже после 401; это не изменение токена демона. Snapshot-настройки
помечены «после перезапуска», неизвестные значения .env скрыты.

Stop доступен и пока начало записи ещё не подтверждено. Позднее подтверждение прежней
команды не заменяет более новую команду stop. В заметках устаревшие route-подсказки
отбрасываются, результат записи не стирает следующий введённый черновик.

В «Настройки → После распознавания» находится существующая опциональная summary.
Транскрибация обязательна; автоматические refine/cleanup исключены. Ручные операции
очистки сохранены. «Текст» без processed.json показывает ту же исходную расшифровку
с подписью источника, без нового прохода модели и фиктивной отметки cleanup=done.
Текущий LLM-этап сохраняет результат, настройка summary действует перед следующим этапом.
Старые jobs без follow_settings сохраняют прежний запрос.

Схема показывает текущий этап/фазу, время с начала, следующие шаги, завершённые
длительности и последний сигнал. Пауза между worker, backoff, отключённый координатор
и недоступная очередь имеют отдельные объяснения. Событие Running без текущего задания
не доказывает выполнение. Если исторические времена отсутствуют, отображается
«длительность неизвестна». Длительность операции видна и в свёрнутом журнале.
При потере связи статус помечается неподтверждённым, таймеры последнего снимка
останавливаются; старый незакрытый блок не изображает новую попытку.
[Актуальные проверки](../openspec/changes/control-postprocessing-and-terminal-player/evidence/transcript-summary-timeline.md).

События worker и строки журнала хранятся вместе: диагностика и завершение операции
сохраняют времена этапов. Представление сбрасывается только настоящей границей
нового запуска. [Регрессия и замер стоимости опроса](../openspec/changes/control-postprocessing-and-terminal-player/evidence/mixed-history-polling.md)
проверяют перемешанные записи и чтение длинной истории.
