# Диагностика фоновой обработки

Черновое описание фактического кода полного конвейера находится в
[описании PIPE](../openspec/specs/processing-pipeline/spec.md). Его сценарии и покрытие — в
[приёмке](../openspec/evidence/pipeline.md); процессы и лимиты — в [архитектуре](architecture.md).
Эта памятка отвечает на вопрос «что произошло с конкретной записью».

## Где смотреть

| Источник | На какой вопрос отвечает |
|---|---|
| `<work_dir>/jobs.json` | Какая фаза ожидает/выполняется, какая попытка, последняя ошибка |
| `<session>/progress.jsonl` | Какие операции начинались/заканчивались, счётчики и heartbeat |
| `<session>/processing.json` | Какие результаты подтверждены, их источник и контрольные суммы |
| `<session>/prepare.json` | Подтверждена ли полная новая загрузка аудио |
| `versions.json`, `transcripts/`, `processed.json`, `summary.md` | Сама выполненная работа |
| Журнал демона | PID, фаза, попытка, время/лимит и причина остановки процесса |

Сначала проверить факт сохранения артефакта и его квитанцию; затем найти событие,
которое объясняет остановку. Успешный exit или последняя зелёная строка лога не
заменяют проверки результата. `unverified` по содержанию и `invalid` по сохранности
разбираются отдельно. Поля состояния и времени определены в PIPE-008/PIPE-011.

Диагностика без загрузки моделей и изменения архива:

```powershell
.\target\debug\localvox-process.exe .\localvox-test\sessions\20260927_110841_youtube --status
Get-Content .\localvox-test\sessions\20260927_110841_youtube\progress.jsonl -Tail 25
```

При долгой сводке смотреть конкретную операцию: загрузка NER, часть N/M, ответ LLM,
проверка, повтор, объединение, сохранение. Heartbeat подтверждает жизнь/ожидание,
а фактическое продвижение — завершённая операция или изменившийся счётчик.

Запросы Ollama пишут `load_sec`, `prompt_sec`, `generation_sec` и `output_tokens`;
см. [метрики Ollama](https://docs.ollama.com/api/chat). Это диагностический вывод
обработчика. В управляемом запуске stdout/stderr передаются в журнал после окончания
процесса; текущие события доступны через progress/API.

## Ручной повтор

Использовать сохранённый транскрипт; заменить путь на нужную сессию:

```powershell
$sessionPath = 'D:/path/to/archive/sessions/session-name'
.\target\debug\localvox-process.exe $sessionPath --post-only --cleanup --force
.\target\debug\localvox-process.exe $sessionPath --post-only --summary --force
```

Без `--force` подтверждённые результаты переиспользуются. Живой обработчик той же
сессии не допускает параллельный обычный CLI-проход. Для повседневной работы доступны
кнопки повторной обработки в приложении; ограничения — PIPE-012.
Изменение исходников не обновляет уже запущенный процесс: бинарники нужно собрать
и запускать согласованной парой. Не диагностировать старую release-сборку как новую debug.

## Проверенный случай 27 сентября 2026

Запись `20260927_110841_youtube`, «AI убил рынок IT? Как я искал работу 3 месяца,
нашёл... и уволился.», источник `WVpweU1n6h4`.
Время ниже взято из её `jobs.json`, `progress.jsonl` и `processing.json`, зона +03:00.

| Событие | Время | Интервал |
|---|---|---|
| Добавлена ссылка | 11:08:41.106 | |
| Обработчик начал запуск | 11:25:01.596 | 16 мин 20,490 с ожидания |
| Загрузка | 11:25:05.486–11:25:12.524 | 7,038 с |
| Извлечение | 11:25:12.524–11:25:14.818 | 2,293 с |
| STT, 184 строки, v001 | 11:25:15.943–11:26:08.371 | 52,428 с |
| Исправление, v002 | 11:26:08.371–11:27:44.246 | 95,875 с |
| Читаемый текст подтверждён | 11:29:21.230 | 96,984 с после исправления; отдельного события начала не было |
| Сводка | 11:29:21.230–11:33:23.478 | 242,248 с |

Итого: **24 мин 42,372 с от постановки**, из них **8 мин 21,882 с после старта**.
Неучтённые промежутки входят в общий интервал; они не приписаны произвольно этапам.
Старый журнал не позволяет честно разделить четыре минуты сводки на генерацию,
проверки и ожидание — новые операции/heartbeat дают эту детализацию для следующих запусков.

Длительность видео — 30 мин 27,834 с. Старый заголовок `11:08–11:39` прибавлял её
ко времени добавления ссылки. Теперь для импорта выводится «добавлено 11:08»;
продолжительность ролика и обработки — отдельные величины.

Проверка новой командой `--status` подтвердила существование и структуру v001,
v002, `processed.json`, `summary.md` этой записи без повторной обработки.
У сводки остаётся прежняя пометка о непроверенных числах; проверка файлов её не снимает.

## Проверка исправления

Используйте соответствующий SC-PIPE из [матрицы приёмки](../openspec/evidence/pipeline.md),
зафиксируйте сборку, команду и результат. Новый дефект оформляйте по
[шаблону](specs/templates/bug.md), не копируя приватный архив в репозиторий.
